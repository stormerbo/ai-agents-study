   原文片段：`三者里第一个最危险，因为它的表现是「程序不结束」`（02:192）、`见 :295-443 与 :21-171 为同一份 paradigms.py`。
   为什么读者会卡住：他被明确告知这是第一位风险，却拿不到一个"长什么样"的样本——从第几步开始重复、参数指纹是不是真连续两次相同、步数上限在第几步触发、成本比正常高多少，全无。第 2 节给的三点失效模式里，只有第二个（工具错误被当事实）和第 9 章实测挂钩，第三个（上下文膨胀）有第 9 章数据，**唯独第一个是空的**。同时他没法只把 ReAct 拎出来跑——代码块是 ReAct/Plan/Reflection 三合一的整份文件。
   要补成什么样（骨架）：①一条真实绕圈子轨迹：每轮 `(tool_name, sorted_args)` 指纹、重复发生在第 N/N+1 轮、重复检测在第 N+1 轮抛错、以及"不检测时撞上 10 步上限"的 token 对照；②单独一节 40 行的最小 ReAct（工具定义 + while + stop_reason 判定 + tool_result 回填 + 指纹去重），Plan/Reflection 的代码留给各自小节。

2. **03 把"执行前校验计划"立为不可省的一步，却整套缺失**
   原文片段：`第 2 步不是可选的。它既是安全边界…少了它，静态计划就只剩「多花一轮钱」这一个特征了`（03:104）。
   为什么读者会卡住：他完全认同要校验，但不知道 plan 的 schema 怎么写、`city` 的合法取值从哪来（正文只说"必须在已知城市表里"）、`tool` 名怎么和 `TOOLS` 对齐、校验失败后是丢弃还是"打回并附错误"、重出几次后放弃改用 ReAct。四个问题一个都没答，而这是他落地静态计划的唯一护栏。
   要补成什么样（骨架）：①plan 的 JSON schema：`{"tool": enum(注册的工具名), "city": enum(城市表), "day": enum([明天,后天])}`；②校验函数（逐项检查并收集错误列表）；③一次完整往返："执行前校验发现 city='北京或上海中明天最高温更高的城市' 不在枚举 → 把错误与合法取值拼回消息 → 模型重出 → 通过"，并给出这一轮多花的 token；④明确"重出 N 次仍不合法就降级 ReAct"。

## 本批次总结（≤300 字）

**最严重的 3 个"读者读到一半读不下去"的点：**
1. **多模态 01:142 与 02:115 的「完整可运行代码」只剩字面 `CODE`** —— 而这两节全篇都在要求读者"成本自己测"（01:91）、"判断写成函数"（02:96），恰是唯一没有代码可抄的两节，页面会直接显示占位符。
2. **计算机使用全章不接真实屏幕** —— `环境是本地绘制的（不依赖真实操作系统）`（02:107）使 demo 全部可复现，但真实截屏、输入注入、截图坐标→屏幕坐标（DPR/窗口偏移）三层全缺，读者无法把"平均误差 1.3–2.6 px"迁移到自己的机器。
3. **"绕圈子最危险"（范式 02:192）没有任何轨迹与实测** —— 三点失效模式里唯一没有样本的一个，也是它唯一称为"最危险"的一个。

**这批里做得最透的 2 节：**
- **多模态 03**：把"分辨率旋钮"写成可自证的决策 —— 两端边界（186/996）、线性段斜率、压缩格式、切块成本用一张表算清，并附完整脚本与实跑输出；每个结论读者都能自己重跑一遍。
- **计算机使用 04**：把"权限"从一句口号拆成四道闸门，每道给"防的是/缺了会怎样"的对照表，并落成一个可运行、可单测的 `Guard` 类 + 实跑输出，概念到代码零跳跃。
