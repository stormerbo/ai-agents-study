### 章 5 结构化输出（structured-output，4 节）

**一句话判词**：四节的骨架是清楚的（形状 → 约束 → 语义 → 重试 → 业务规则），实测也都真的在「反直觉」上做了功课；但一节正文里的实测数据在别处的引用中凭空长了出来（currency），一节给的是会让 API 报错的重试代码，标题承诺的「约束解码」没有正面讲。

**定位与目标对齐**（meta.outcomes，structured-output/meta.ts:11-15）：
1. 「能用 schema 约束让模型输出可被程序直接消费的结构」→ 基本兑现，但兑现方式与承诺相反：第 2 节实测的是 **schema 强制不了什么**（maximum/pattern/format 全不生效），正面能力（协议级保证）只在第 1 节以「强制工具调用 + 关思考」的形式给了半条。
2. 「能设计解析失败时的重试与降级策略」→ 兑现（第 3 节 3 种重试 + 3 种降级，有 6 次一组的实测），是本章最扎实的一节。
3. 「能区分格式错误和语义错误」→ 兑现（第 2 节三级分层图 + 第 4 节三条修法），这条是全章的主线，做得比 meta 承诺的还清楚。

**逐节评估**

- 01-why-not-prompt-only.mdx：把「提示式 JSON 不可靠」当传言去测，结论是未复现（30 次全对）；覆盖强；缺失子主题：无关键缺口。问题：成本表把「工单任务的 output_tokens 中位（223）」和「60 条记录任务的 output/耗时（1832 / 394ms）」并列展示，两个口径没交代清楚，读者会以为 C 方案在 60 条任务上也只要 223（01-why-not-prompt-only.mdx:62-69 vs 87-91）。这是全章写得最诚实的一节 —— 它把自己第一版「解析器只认对象」的 bug 当成案例写进去了（:48-56）。
- 02-json-schema-strict.mdx：12 个关键字 × 3 次逐个引诱模型违反，得出「结构性的遵守、校验性的不生效」（:19-34）；覆盖强；缺失子主题：**约束解码本身**（标题里那四个字只在 :43-47 占了 5 行，没有机制、没有可观察后果、没有任何厂商实现对照）。问题：「所以要把三件事分开」那张图的左侧支路语义不自洽 —— L1 判定「对象？字段名对？类型对？」后走向 A1，但 A1 的标签写的是「schema + 解析器 / 能机械保证」，而本节自己的实测说类型是端点静默转换出来的（"一百九十九元" → 199，:23），解析器并不提供这个保证（:71-73）。另：strict: true 的示意把参数写在工具对象顶层（:51-62），这与 OpenAI 的 function 对象内层写法不同；正文说它「被静默忽略」是对的（对被测端点），但没有注明这是端点行为还是通用结论，读者很可能把它当成「strict: true 没用」的普适事实。
- 03-validation-retry.mdx：三种重试策略 6 次对照，0/6 / 0/6 / 6/6，并拆出「起作用的是错在哪、不是上次输出什么」（:15-47）；覆盖强。问题（P0）：retry_with_feedback 的重试分支把 assistant 的 content（含 tool_use 块）原样塞回 messages，却**没有在紧随的 user 消息里回填 tool_result**（:152-162）—— 在 Anthropic Messages API 里 tool_use 之后必须配 tool_result，这段代码第二次请求会 400；同时 :149 的注释「assistant 的 content 原样带回（消息历史必须完整）」说的恰好是这条规则，而代码只做了一半，解释与实现冲突。

### 章 6 检索（retrieval，5 节）

**一句话判词**：方法论是这一章最强的东西（第 2 节用两套指标口径把结论反转出来，是全书级别的教学材料）；但节内数据有多处互相对不上（10 条查询 4/10、两种 15 条口径、第 5 节的 3.3 同时被当成「漏召数」和「平均命中数」），而且大量关键结论建立在只有 3 个文档的玩具语料上。

**定位与目标对齐**（retrieval/meta.ts:11-15）：
1. 「能判断一个需求该用检索、微调还是直接放 prompt」→ 兑现且超额：第 1 节的三条路对照表 + 一句话判据（知识 vs 行为），并诚实标出「检索救不了推理」。
2. 「能设计切分与召回策略，并说得出每一步取舍依据」→ 兑现（第 2 节四策略对照含纯度/覆盖，第 3 节宽召回 + 重排，第 5 节改写 vs 自主）。
3. 「能搭一套最小评测集，把检索错和模型答错分开定位」→ 兑现了一半：分开定位的方法（完美检索上界、召回分层、口径匹配）都很实，但评测集的「检索侧指标」只有 recall@k/MRR，**怎么评生成侧（答案是否有据、引用是否对）全程没有**。

**逐节评估**

- 01-why-retrieval.mdx：先量「全塞进去」的真实成本（89,136 token / 0.497 比值 / 输入差 18.6 倍），再抓出 input_tokens ≠ 总输入这个会毁掉对照实验的坑（:26-47）；覆盖强；缺失子主题：无。问题：代码里 anthropic-version / x-api-key 是 Anthropic 形态，模型名默认却写 claude-haiku-4-5 而实测是 deepseek-flash（:192），读者换端点时容易配错；「第 3 章的问题」的引流（:99）指向正确但章号硬编码（见体系性）。
- 02-chunking.mdx：全章最有价值的一节。先展示「文件级指标下三种策略几乎一样」的假结论，再下沉到章节级让结论反转（13/15 → 8/15），并补了不需要标注的边界完整率；覆盖强。问题：脚本自述文件名与正文示例命令不一致（:101 chunk.py vs :187 chunk-demo.py）。
- 03-vector-limits.mdx：10 条口语化查询全部落榜（0/10 进 top-5），据此划出词法/向量的分工线，并明确把「向量对标识符差」标成原理推断未实测（:46-49）；覆盖中偏强；缺失子主题：**没有实测向量检索**（环境无 embedding 端点），所以整章关于向量的结论都是推断 —— 这在章开头交代得够清楚（:105-109），可以接受，但第 3 节标题「向量检索的天花板」与实际内容（词法失败 + 重排）名不副实。问题：重排实测「重排后 4/10、天花板 4/10」（:61-70）与第 4、5 节引用的「10 条里有 6 条不在候选集」要读者自己做减法才对得上；同一句论断「用 top-20 候选只有 4 条正确」被重复三处（:64、:95、:246），属于用同一组 10 条小样本反复举证。
- 04-evaluating-retrieval.mdx：完美检索上界 6/6 vs top-5 的 5/6，把「这不是模型的问题」变成可执行判据；再加上 recall@k vs MRR 的实跑（recall@3=1.00 掩盖了一个第 2 名）；覆盖强。问题：评测集只有 4 条，且第 4 条的召回结果只有 1 条（:196），文章靠「这更说明 recall 麻木」把它圆过去了，但 4 条的 MRR/recall 本身不具备任何区分力，文章也没标注样本量风险。
- 05-agentic-retrieval.mdx：改写查询 0 → 6.3/10、自主多轮掉到 3.3/10 且成本 7.5 倍，并抓出失败原因「模型经常选择不查」；覆盖强；缺失子主题：没提查询改写本身会引入的错误（改写漂移）与多轮里的 query drift 检测。问题（P0 表述错误）：「10 条里有平均 3.3 条从头到尾一次检索都没发」（:43）与同表 :27 的「3/4/3」互相矛盾 —— 3.3 是**平均命中数**（3.3/10），不是「没查的条数」；Mermaid :104 又把 3.3/10 写成「一次都没查」。读者拿这一节做工程判断时会把「漏召 33%」误当成「平均只漏 0.33 条」。

### 章 7 记忆（memory，5 节）

**一句话判词**：章的主线（上下文不是记忆 → 写什么 → 何时召回 → 冲突 → 值不值）是这个批次里最连贯的，误召回静默改写那组对照也确实值得；但成本模型自相矛盾（表格列标错 + 三套「12 轮倍率」+ 漏记写入侧输出 token），而最该有实测的第 5 节恰恰一个数字都没有。

**定位与目标对齐**（memory/meta.ts:11-15）：

## 批次总结

**最严重的 3 个问题（跨章）**

1. **正文对正文的引用正在漂移，而且没有任何测试覆盖它。** memory/02:54 与 memory/meta.ts:68 指向「第 5 章的 status_source」但该字段在 structured-output/04:132；structured-output/04:52 引用的「第 2 节 currency 实测」在章 5 中不存在；retrieval/05:62 引用的「第 3 章的观察」在章 3 找不到对应内容。tests/curriculum.test.ts 的「四方一致性」校验的是正文登记，不是这些散文里的章节引用，所以它们会继续漂移。
2. **三章的数字在自相矛盾，而工程质量依赖这些数字。** memory/05:24-29 表头写「注入成本」实填合计（3.3 倍 vs 1.54 倍两种读法）；memory/01 的「12 轮 6.5 倍」有 57,822 与 63,720 两套；retrieval/05:43 把 3.3/10（平均命中数）说成「平均 3.3 条没检索」；structured-output/01 的成本表跨了两个任务口径。这些恰好都出现在「让读者据此做工程决策」的位置。
3. **三块共同的盲区**：结构化输出缺「约束解码到底怎么实现、主流厂商哪家真做了、streaming 怎么处理」；检索缺「生成侧怎么评」（节题承诺了分层定位，但只给了检索侧指标）；记忆缺「多用户/隐私边界」与「让第 5 节落地的实测」。读者学完这三章，会在这三处保留盲区。

**本批次最有价值的 2 节**

- retrieval/02-chunking.mdx —— 同一个系统、两套指标口径，把 87% 显示成 53%。它教的是评测口径，而这条方法论能直接搬到其他任何一章。
- retrieval/05-agentic-retrieval.mdx —— 抓到「模型自认为知道答案于是不查」这个失败模式，并给出四条把多轮关进笼子的工程规则。（注意：它自己的 3.3 数字表述有 P0 错误，方法论的分数与事实的扣分要分开看。）

**对「是否成体系」的总体判断**

三章作为一个整体是**部分成体系**：章间定位清楚（5 → 6 → 7 递进），章内顺序全部符合依赖顺序，这一点做得比大多数教程好。但内容存在明显的文本层次问题 —— 大量关键结论靠「引用别章的实测」，而这些引用有一批已经对不上目标；同一机制（BM25、成本模型）在章内被重复实现或重复解释。按我自己对 AI Agent 领域知识的清单，这三章在广度上覆盖得相当完整，缺的都是少数几个工程化的深水区（约束解码实现、生成侧评估、多用户与隐私边界）。另外我对本项目其他章节的实测数字没有全量核对（例如 memory/01:113 引用的「第 3 章压缩实测 2272 比 1952」我未回查），涉及跨章的引用问题我只标了能直接确认的，其余标为不确定。
