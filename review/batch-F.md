### 章 14 MCP（mcp，5 节）

**一句话判词**：事实层经得起核对（协议变更与官方 changelog 逐条对得上），但「每节一块完整可运行代码」是形式上的 —— 同一个程序被逐字节复制进全部五节，而这唯一的实现有两处与规范不符。

**定位与目标对齐**：
- 「能说清 MCP 与『自己写工具』的取舍边界，以及它不负责什么」→ 兑现。四条不负责清单（src/content/chapters/mcp/01-why-protocol.mdx:27-32）+「只有一个 host 一个 server 时协议多余」的判据（01:49）。
- 「能读懂当前规范版本的关键接口，并识别旧教程里的过时写法」→ 大体兑现。03 列的七项变更与官方 changelog 逐条一致（已核对 modelcontextprotocol.io/specification/2026-07-28/changelog）；但演示代码的 _meta 键名与 MRTR 回填不是规范里的写法（P1-2），读者照抄写不出可互通实现。
- 「能评估接入一个第三方 MCP server 的安全代价」→ 部分兑现。05 把风险拆成数据外泄/动作越界两条防线，但缺官方安全清单里的授权与传输安全议题（P1-3）。

## 批次总结

- 最严重的 3 个问题：
  1. 评估章 04 节的实测数字三处互相矛盾、随附代码跑不出给出的输出（04:40 / 160 / 175），而这是该节唯一的数据支点。
  2. 评估章节号引用系统性停留在扩章前（11 处），跨节指路全部指错，破坏章内体系。
  3. MCP 章五节共用同一份程序（01:138、02:126、03:163、04:95、05:115），「每节一块完整可运行代码」形式化；且唯一实现的 _meta 键名与 MRTR 回填与官方规范不符。
- 本批次最有价值的 2 节：
  1. evaluation/07-paired-comparison.mdx：配对消任务级噪声的机制、17% 的量化、符号检验的诚实不显著、以及「7/7 被读成 7/8」的分母复盘，是少见的「方法+数据+自我纠错」闭环；数字我独立复算全对。

- 是否成体系的总体判断：
