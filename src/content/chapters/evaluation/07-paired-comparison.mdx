配对比较是把**同一个实验单位**分别置于 A、B 条件下，再分析每对结果的差值。它能控制一部分单位间基线差异；是否降低标准误，取决于两条件结果的相关性和实验设计，并非配对就一定更灵敏。[NIST：配对观测分析](https://www.itl.nist.gov/div898/handbook/prc/section3/prc311.htm)。

**旧文中的 7 项评分器重建**：这些是正文保留的规则代码，不是可核验的原始 scorer 文件。它没有检查每行是否恰好包含 4 个字段，也没有检查优先级是否只允许 P0/P1/P2；因此 7/7 只表示通过了这 7 个程序条件，不等于完整满足提示中的输出契约：

```python
import re

def score(txt, stop_reason):
    """满分 7。返回通过条数。"""
    lines = [l.strip() for l in txt.split(chr(10)) if l.strip()]
    nums = [int(m.group(1)) for m in (re.match(r"TC-(\d+)", l) for l in lines) if m]
    p0 = sum(1 for l in lines if re.search(r"P0\s*$", l))
    p1 = sum(1 for l in lines if re.search(r"P1\s*$", l))
    checks = [
        sum(1 for l in lines if ("金额" in l or "校验" in l)) == len(lines) and len(lines) > 0,
        nums == list(range(1, len(lines) + 1)) and len(lines) == 15,
        p0 == 3,
        p1 == 5,
        all("测试" not in l for l in lines),
        not re.search(r"^\s*(用例|编号|序号)", txt, re.M),
        stop_reason == "end_turn",
    ]
    return sum(checks)
```

7 项分别是内容关键词、编号/行数、P0 数、P1 数、禁词、无表头和 `end_turn`。提示还要求每行符合固定字段格式并使用 P0/P1/P2；代码没有覆盖这些要求。旧表报告的 7 分不能据此称为完整通过，且原始输出缺失，历史 16 次分数无法复核。

### 关键纠错：分母一致不等于评分器有效

旧文曾把 7 分误读为 7/8，后来按代码数出 7 项检查。这只能说明**评分器自己的分母是 7**，不能证明评分器覆盖了任务契约。静态检查发现，它允许某些非法优先级与不完整字段行通过：例如把 7 条应为 P2 的行标成 P9，仍不会改变 P0/P1 计数，也不会触发这 7 项检查。用评分器给自己打分也不能替代独立的契约测试：应分别测试“有效输出通过”和“每类无效输出被拒绝”，再抽样人工核对语义正确性。

因此保留“旧文曾记载分母误读”作为写作过程的历史说明，但撤回“16 次都满分、从未有任何约束失败”的结论。当前也无法用原始输出判定历史答案是否真的满足完整任务。

## 二、配对何时能降低标准误

回到成本那列。两种看法：

**把两组当作独立样本比较。** A 组 8 个数的样本标准差是 321.0，B 组是 625.7。若暂按两个独立样本估计均值差的标准误：

```text
SE(独立样本) = sqrt(321.0² / 8 + 625.7² / 8) = 248.6
```

**按任务配对。** 对每个任务计算 B−A，8 个差值的样本标准差是 584.8，配对均值差的标准误为：

```text
SE(配对) = 584.8 / sqrt(8) = 206.8
```

仅就这张历史摘要表的算术而言，配对 SE 比独立样本近似值低约 17%。这不是通用的“灵敏度提升”，也不构成显著性结论。对任一实验单位，差值方差满足 `Var(B−A) = Var(B) + Var(A) − 2 Cov(A,B)`；当配对观测正相关时，协方差项会降低差值方差，相关性为零时不会带来该收益，负相关时反而可能更差。独立样本公式还假设两组样本互相独立且样本量相同；这张表只用于展示算术，不代表随机化或总体推断已经成立。[NIST：配对观测分析](https://www.itl.nist.gov/div898/handbook/prc/section3/prc311.htm)

「优惠券核销」这个任务天然输出较长，这类任务基线若在 A/B 两个条件间稳定，就可能在差值中抵消；但条件与任务的交互、调用随机性和运行环境变化仍会留下波动。配对抵消的是共同基线，不会把差值变成常数，也不会自动消除所有噪声。

## 三、配对之后还要做检验

配对只是把数据整理好，**它本身不给结论**。若问题是「B 在这 8 个任务上的 token 摘要是否更常高于 A」，还需要描述统计或检验；这仍不是账单成本或总体结论。

最省事的是**符号检验**：只看每个任务差值的方向，不看大小；零差值作为 ties 排除。零假设下，在配对单位相互独立、正负等概率的前提下，正号数服从 `Binomial(n, 0.5)`。[NIST：符号检验](https://www.itl.nist.gov/div898/software/dataplot/refman1/auxillar/signtest.htm)

```text
8 个任务里：B 比 A 高 6 次、低 2 次、平局 0 次
若事先指定单侧备择 B>A：P(X≥6) = 37/256 ≈ 0.145
双侧精确检验：2 × min(P(X≤6), P(X≥6)) = 74/256 ≈ 0.289
```

当前找不到事先登记检验方向的记录，因此不能把观察到的“B 较高”事后选作单侧方向。应报告双侧精确 p≈0.289；它不显著。该检验还依赖配对单位相互独立、零假设下正负方向等概率等条件，不能靠“8 个任务”自动满足这些前提。

本表每个任务、每个条件只有一次请求，且逐次响应和运行顺序都缺失。它无法测出同一任务内的模型随机性，也不能确认任务是独立或代表目标总体。符号检验只使用差值方向，不检验 token 差的大小。**不存在不看目标效应、差值变异、显著性水平、检验功效和实验单位定义，就能通用的 15–20 个样本建议**；样本量应按预先定义的设计计算或仿真。

## 四、什么时候该用配对

配对的前提是**每个样本能在两种条件下各测一次**，而且两次之间可比。
这个前提在很多评测场景里成立，但有几个常见的破坏它的做法：

**一、两次运行之间环境变了。** 如果 A 跑完之后你改了工具返回格式，再跑 B，
那 A 与 B 的差里就混进了环境的变化。
**配对要求两个条件在同一环境下、尽量接近的时间点完成。**

**二、任务本身有先后依赖。** 如果任务 2 依赖任务 1 的产出，
那么「先跑完所有 A 再跑所有 B」和「每个任务 A/B 挨着跑」会给出不同结果。

**三、执行顺序和时间漂移混淆条件。** 如果永远是 A 先、B 后，缓存、服务负载或时间趋势可能与条件混在一起。若目标是比较条件效果，应在每对内随机决定顺序或按预先安排的区组交错运行，并记录时间戳与缓存/服务状态；随机化是控制已知与未知混杂的设计手段，不是“能配对”的数学前提。[NIST：实验设计与随机化](https://www.itl.nist.gov/div898/handbook/pri/section3/pri3.htm)

**依赖型任务怎么切。** 上面第二条在 agent 场景里很常见（多步任务、共享状态）。正确做法不是放弃配对，而是**改配对单位**：把「一个样本」定义成**一次完整执行**，而不是拆开的单步 —— A、B 两组分别在**各自干净的环境**里各跑一次，配对的是「同一个任务在同一初始状态下的两次执行」。如果任务本身会改环境（下单、写库），每次执行前都必须重置到同一初始状态（第 5 节的环境五要素），否则你配对的是两个不同的世界。**依赖链内部不做配对，依赖链整体才是一个配对样本。**

## 五、把检验写成代码

下面这段不需要第三方库，直接能跑。它用任务 ID 对齐、拒绝 ID 集不一致，并输出双侧精确符号检验及两个标准误；这里的独立样本 SE 只作摘要表的描述性对照。

```python
import math
from statistics import mean, stdev


def exact_sign_test(diffs, alternative="two-sided"):
    """Exact sign test; zero differences are ties and are excluded."""
    nonzero = [d for d in diffs if d != 0]
    n = len(nonzero)
    if n == 0:
        return {"p": 1.0, "positive": 0, "negative": 0, "ties": len(diffs)}

    k = sum(d > 0 for d in nonzero)
    lower = sum(math.comb(n, i) for i in range(0, k + 1)) / (2**n)
    upper = sum(math.comb(n, i) for i in range(k, n + 1)) / (2**n)
    if alternative == "greater":
        p = upper
    elif alternative == "less":
        p = lower
    elif alternative == "two-sided":
        p = min(1.0, 2 * min(lower, upper))
    else:
        raise ValueError("alternative must be two-sided, greater, or less")
    return {"p": p, "positive": k, "negative": n - k, "ties": len(diffs) - n}


def index_by_id(rows):
    indexed = {}
    for task_id, value in rows:
        if task_id in indexed:
            raise ValueError("duplicate task ID: " + task_id)
        indexed[task_id] = value
    return indexed


def compare_paired(a_rows, b_rows):
    """Pair (task_id, value) records; reject duplicate, missing, or extra task IDs."""
    a_by_id = index_by_id(a_rows)
    b_by_id = index_by_id(b_rows)
    if set(a_by_id) != set(b_by_id):
        raise ValueError("A/B task ID sets differ; pairing is undefined")
    ids = sorted(a_by_id)
    if len(ids) < 2:
        raise ValueError("at least two independent paired units are needed for an SE")

    a = [a_by_id[task_id] for task_id in ids]
    b = [b_by_id[task_id] for task_id in ids]
    diffs = [b_value - a_value for a_value, b_value in zip(a, b)]
    se_paired = stdev(diffs) / math.sqrt(len(diffs))
    se_independent = math.sqrt(stdev(a) ** 2 / len(a) + stdev(b) ** 2 / len(b))
    test = exact_sign_test(diffs, alternative="two-sided")
    return {
        "mean_difference": mean(diffs),
        "paired_se": se_paired,
        "independent_se": se_independent,
        "sign_test": test,
        "differences": dict(zip(ids, diffs)),
    }


a = [
    ("refund", 2155), ("register", 1942), ("coupon", 2147), ("address", 2333),
    ("invoice", 1807), ("password", 2863), ("withdrawal", 2339), ("listing", 2392),
]
b = [
    ("refund", 2192), ("register", 1981), ("coupon", 3444), ("address", 2640),
    ("invoice", 1844), ("password", 2661), ("withdrawal", 1805), ("listing", 3229),
]
r = compare_paired(a, b)
print("mean difference %.2f" % r["mean_difference"])
print("paired SE %.1f / independent-sample SE %.1f" % (r["paired_se"], r["independent_se"]))
print("signs %d positive, %d negative, %d ties; two-sided exact p=%.3f" % (
    r["sign_test"]["positive"], r["sign_test"]["negative"],
    r["sign_test"]["ties"], r["sign_test"]["p"],
))
assert abs(r["mean_difference"] - 227.25) < 1e-9
assert abs(r["paired_se"] - 206.8) < 0.1
assert abs(r["independent_se"] - 248.6) < 0.1
assert abs(r["sign_test"]["p"] - 0.2890625) < 1e-9
```

实跑状态：Python 3.14.7，使用上方表格中的历史摘要数字离线运行；这只验证算术、ID 对齐与检验实现，不是模型实验，也不复核历史记录。代码默认双侧检验；只有在看数据前明确登记方向时，才可使用 `alternative="greater"` 或 `"less"`，不应依据观察到的方向事后改成单侧。

### 一个会静默出错的对齐问题

旧代码用 `zip(a, b)` 按位置配对。只要 B 列表被 shuffle 或缺了一项，程序仍会运行，却会把不同任务相减；`assert len(a) == len(b)` 只能发现数量不同，发现不了顺序错配。因此真实分析应传入带稳定任务 ID 的记录，先验证两条件 ID 集合完全一致，再按 ID 对齐；重复运行还要把 `run_id` 与任务 ID 分开。任何一对缺失或重复都应报错或显式进入缺失数据处理，不能悄悄截断。

## 六、配对在 agent 评测里的适用边界

**提示词、模型或版本对比。** 如果同一任务能在 A、B 条件下以可比输入、初始状态和判分规则各运行一次，通常可以把任务作为配对单位；是否提高精度仍取决于两条件结果的相关性。任务集应代表目标分布，运行顺序应随机化或交错，评分规则和版本指纹应固定并记录。对有随机性的模型，单次运行只能比较这两个具体输出；要估计每个任务上的随机波动，需要在每个条件重复运行，并把同一任务的重复视作聚类数据，不能把重复调用误当成独立任务。

**不要为了配对而硬配。** 若 A、B 面向不同总体，或没有可解释的共享实验单位，就不应按数组顺序强行配对；应采用适合目标的独立样本或分层设计，并在分析中承认样本构成可能带来的差异。比如“5 个示例”与“20 个示例”的提示设置本身不妨碍在同一批评测任务上做配对；真正的问题是两条件实际评估了不同任务或不同目标总体。

## 七、小结

- **配对的作用有条件**：稳定的共同基线可在差值中抵消；精度改善取决于配对相关性与实验设计。
- **历史表只支持算术重算**：8 对差值均值为 +227.25、配对 SE 约 206.8；没有逐次响应和 usage，不能声称质量等价或账单成本上升。
- **检验方向必须预先规定**：按这 8 对的符号，双侧精确符号检验 p≈0.289；单侧 p≈0.145 只有在方向预先指定时才适用。
- **样本量必须按目标设计**：说明目标效应、方差、独立实验单位、显著性水平和功效，不套用固定的 15–20 样本口诀。
- **验证配对键与契约**：按稳定 ID 对齐；分别覆盖有效输出与每类无效输出，评分器满分不等于任务正确。
