上一节讲评测集从哪来。这一节讲它会怎么坏掉 —— 而且**坏掉之后它仍然是绿的**。

## 一、三种不同问题，检测能力也不同

**训练数据暴露**：测试题或其近似内容出现在预训练、微调或其他训练阶段。它可能抬高基准分数，但对闭源模型通常拿不到完整训练语料与数据谱系，因而很难直接确认「见过」或「没见过」。发布日期 cutoff 只能排除晚于 cutoff 的内容，不能证明其余内容未进入训练。

**提示词 / 上下文泄漏**：评测运行时，参考答案、目标题的近重复版本或其他足以透露答案的信息，被放进 system prompt、few-shot 示例、检索结果、对话历史或工具返回。示例本来就可能提供格式或任务知识；只有当它暴露了被测题的答案或改变了被测构念，才构成需要处理的泄漏风险。

**迭代过拟合**：根据同一评测集的结果反复选 prompt、参数或模型。它不要求题目被模型记住；评测集已经给开发者提供反馈，最终分数就不能再当成完全独立的确认结果。对频繁改动的小项目来说，这条最容易触发，因为每一轮都会看到同一套题的反馈。

这三类不是唯一的标准分类，实际风险也取决于工作流。防护应组合使用：快速回归集负责拦截已知退化，滚动发现集吸收新失败，访问受控的确认集按预先约定的时点运行。**锁住文件并不等于可以无限次查看**：一旦结果用于选择下一次改动，它就给了开发过程新的反馈；普通留出集仍可能被自适应过拟合。更严格的复用需要专门的统计机制，或者刷新一份未暴露的新确认集。

## 二、比泄漏更常见的坑：用模型生成评测集

「评测集不够，让模型生成一批」是很自然的想法。我实测了一遍，看它会带来什么。

任务是让模型围绕「AI agent 的上下文工程」出 20 道单选题，要求覆盖不同知识点，
并按指定格式输出题干、四个选项、正确答案。

### 缺陷一：这批题的答案位置偏斜

历史日志里两个批次的可解析答案分布分别是：

```text
批次 A：生成 20 道，答案字段可解析 20 道
  A=2（10.0%） B=12（60.0%） C=6（30.0%） D=0（0.0%）
  Pearson χ²=16.80；在「答案位置独立且均匀随机」假设下，精确多项分布尾概率约 0.000871

批次 B：生成 20 道，答案字段可解析 19 道
  A=2（10.5%） B=14（73.7%） C=3（15.8%） D=0（0.0%）
  Pearson χ²=25.00；同一假设下精确尾概率约 0.0000207
```

**这里的统计检验只是一个有条件的参照。** 当时的提示词要求单选题格式，并没有预先要求正确答案位置均匀随机；模型输出也不是从已知的均匀随机机制抽样。因此不能把 p 值解释成「已证明模型普遍偏爱 B」，也不能用它代表所有生成题。能直接确认的是这两批题本身答案位置不均衡：在这些题上，总选 B 的策略分别能命中 60.0% 与 73.7%。如果评测者希望位置无规律，应在生成后检查并配平；同时还要人工核验答案正确、选项互斥和题目覆盖。

### 缺陷二：考点高度重复

我让模型给每道题标一个「考点」，然后按语义归并。结果：

```text
名义题数 19   →   实际覆盖概念 6 个     重复率 68%

  上下文隔离            6 道   ######
  中间遗失 / 位置偏差    5 道   #####
  工具结果压缩          4 道   ####
  前缀缓存              2 道   ##
  上下文卸载            1 道   #
  上下文注入            1 道   #
```

**这批人工归并把三个概念簇放进了 15/19 道题。**「中间遗失」「位置偏差」「位置偏见」被合并为一类，「工具结果压缩」「工具结果剪裁」「工具输出治理」也被合并。这个 6 类是对单批题的人工归并结果，没有独立标注者一致性数据，也不能推广成模型生成题的重复率常数。

它说明名义题数不等于概念覆盖：把同一概念换措辞，不会增加覆盖面。评测集扩到 200 道后仍可能覆盖狭窄；要验证覆盖，先定义概念分类，再做双人抽样复核和边界题审查。

「换皮」长什么样，看这次生成里的两道（真实生成原文，来自上面那次实测）：第 4 题问「把关键系统指令与大量检索文档拼接时怎么布局」，考点标「中间遗失」；第 5 题问「为缓解迷失中间，关键信息放哪」，考点标「位置偏差」。两道题的正确答案都是 B，问的是同一件事。**这就是为什么按名义题数报「覆盖 19 个考点」会高估——它们去重之后是 6 个。**

### 缺陷三：答案字段可解析，不等于题目合格

一份 8 题的历史日志只有 5 题解析出答案字段；另一批 20 题日志有 19 题可解析，第三批日志则是 20/20 可解析。这里的 parser 只查找 `答案：A/B/C/D`，**没有校验题干、四个选项、选项唯一性、参考答案正确性或题目歧义**，所以这些比例只能称为「答案字段解析率」，不能称为完整格式合规率或有效题率。不同批次也不是受控的重复实验，不能据此估计通用失败概率。

工程结论仍然明确：把模型输出当候选记录，解析失败要显式拒绝并留日志；解析成功后还要用 schema 检查必填字段、用独立答案键或专家审查核验正确性。重试可以修格式，不能自动证明题目有效。

## 三、这个对比没有测出泄漏

我想比较同一模型回答「模型自己生成的题」和「人工题」时是否有差异。现存日志记的是 8 道题生成，其中 5 道解析出答案，模型在这 5 道上答对 5 道；人工题 8 道答对 8 道。**这是一次小样本、未配对难度、无重复运行的历史观察**，不能据此证明或排除训练数据暴露。

它还有一个明显的捷径：生成题的答案键是 4 个 B、1 个 A；人工题答案键是 7 个 B、1 个 C。只选 B 的基线就分别能答对 4/5（80%）和 7/8（87.5%）。所以表面上的 100% 两组分数不能解释成「模型没有泄漏」，也不能解释成「模型自我出题时能力更强」。

这组数据能支持的结论很有限：**这两批简单题都没有区分出能力差异，且答案位置基线很高**。要测试泄漏，需要任务难度与内容可比、答案位置配平、参考答案独立核验、按题目做配对比较，并且使用多次运行或足够样本。即便如此，输出相同也只是针对该探针的证据，不是对未知训练语料的证明。

## 四、怎么检测

下面的离线 helper 分别做三件事：检验答案位置是否符合一个**假设的均匀随机基线**、对人工标签做字面去重、以及在你能访问的语料里标记字符 n-gram 重叠候选。它们不能确认题目正确、概念覆盖充分，也不能证明闭源模型的预训练污染。

```python
import itertools
import math
import re
from collections import Counter


def _pearson_uniform(counts):
    n = sum(counts)
    expected = n / 4
    return sum((count - expected) ** 2 / expected for count in counts)


def exact_uniform_position_p(counts):
    """Small-sample exact tail for Pearson statistic under IID uniform labels."""
    if len(counts) != 4 or any(type(value) is not int or value < 0 for value in counts):
        raise ValueError("counts must be four non-negative integers")
    n = sum(counts)
    if n <= 0 or n > 100:
        raise ValueError("require 1 <= total sample count <= 100 for this teaching enumerator")
    observed = _pearson_uniform(counts)
    probability = 0.0
    for a in range(n + 1):
        for b in range(n - a + 1):
            for c in range(n - a - b + 1):
                d = n - a - b - c
                candidate = (a, b, c, d)
                if _pearson_uniform(candidate) + 1e-12 >= observed:
                    ways = math.factorial(n) / math.prod(math.factorial(x) for x in candidate)
                    probability += ways * (0.25 ** n)
    return min(1.0, probability)


def answer_distribution(answers):
    """Counts, Pearson statistic, and exact p under the declared uniform-label null."""
    if not answers or any(not isinstance(a, str) or a not in "ABCD" for a in answers):
        raise ValueError("answers must be a non-empty sequence of A/B/C/D labels")
    counts = [answers.count(label) for label in "ABCD"]
    return dict(Counter(answers)), _pearson_uniform(counts), exact_uniform_position_p(counts)


def concept_overlap(fields):
    """Literal normalization only; semantic topic coverage needs a human rubric."""
    if not fields or any(not isinstance(field, str) or not field.strip() for field in fields):
        raise ValueError("fields must be non-empty strings")
    normalized = [re.sub(r"[\s，。、]", "", field) for field in fields]
    return len(normalized), len(set(normalized))


def ngram_leakage(eval_texts, visible_corpus, n=8, threshold=0.5):
    """Flag overlap candidates in an accessible corpus; this is not proof of model exposure."""
    if type(n) is not int or n <= 0:
        raise ValueError("n must be a positive integer")
    if not math.isfinite(threshold) or not 0 <= threshold <= 1:
        raise ValueError("threshold must be between 0 and 1")
    if any(not isinstance(text, str) for text in [*eval_texts, *visible_corpus]):
        raise TypeError("all texts must be strings")

    def grams(text):
        normalized = re.sub(r"\s+", "", text)
        return {normalized[i:i + n] for i in range(len(normalized) - n + 1)}

    corpus_grams = set().union(*(grams(text) for text in visible_corpus))
    analyzable = 0
    flagged = []
    for index, text in enumerate(eval_texts):
        sample_grams = grams(text)
        if not sample_grams:
            continue
        analyzable += 1
        overlap = len(sample_grams & corpus_grams) / len(sample_grams)
        if overlap >= threshold:
            flagged.append(index)
    return {"candidateCount": len(flagged), "analyzableCount": analyzable, "indices": flagged}


if __name__ == "__main__":
    runs = {
        "batch A": ["A"] * 2 + ["B"] * 12 + ["C"] * 6,
        "batch B": ["A"] * 2 + ["B"] * 14 + ["C"] * 3,
    }
    for name, answers in runs.items():
        counts, chi2, p_exact = answer_distribution(answers)
        print("%s: n=%d labels=%s Pearson chi2=%.2f exact-p=%.8f" % (name, len(answers), counts, chi2, p_exact))

    focus = ["工具结果压缩", "上下文隔离", "上下文隔离", "中间遗失", "位置偏差",
             "工具结果压缩", "工具结果剪裁", "上下文隔离", "上下文隔离", "工具输出治理",
             "提示缓存", "位置偏见", "位置偏差", "上下文卸载", "上下文隔离",
             "上下文隔离", "位置偏差", "上下文注入", "提示缓存"]
    nominal, literal = concept_overlap(focus)
    print("literal labels: %d -> %d (not semantic annotation)" % (nominal, literal))
    local = ngram_leakage(["检索结果压缩为相关字段"], ["检索结果压缩为相关字段"])
    print("visible-corpus overlap candidates:", local)
```

离线复算这两批历史分布及字符 n-gram 演示的输出：

```text
batch A: n=20 labels={'A': 2, 'B': 12, 'C': 6} Pearson chi2=16.80 exact-p=0.00087102
batch B: n=19 labels={'A': 2, 'B': 14, 'C': 3} Pearson chi2=25.00 exact-p=0.00002071
literal labels: 19 -> 10 (not semantic annotation)
visible-corpus overlap candidates: {'candidateCount': 1, 'analyzableCount': 1, 'indices': [0]}
```

**实跑状态**：上面的 `answer_distribution`、`concept_overlap` 与 `ngram_leakage` 示例已在本地 Python 3.14.7 运行，输出逐字与此处对照一致。答案分布是从版本化的历史汇总 fixture 复算；fixture 仅转录本地旧日志摘要，不包含原始 provider 请求或响应，不能视为历史实验重放。

批次 B 的 exact p 值是假设 4 个答案标签独立且均匀随机时，Pearson 统计量至少达到观察值的精确多项分布概率；由于这不是预先随机化的实验设计，只作探索性参照。字符 8-gram 命中只表示与**可访问语料**有词面重合；它既不能证明闭源模型训练时见过题目，也不能检测所有改写或语义重合。固定的 50% 阈值是人为筛查参数，需人工复核，不是通用判定线。

`concept_overlap` 只移除空白、中文逗号/顿号/句号，19 个标签得到 10 个字面指纹；另有人工归并把这批题分成 6 类。两者都依赖所选归一规则/人工分类，不是重复率的数学下界或上界。语义覆盖应先定义 rubric，再用独立标注者抽样评审；自动去重只负责找候选，不能代替内容审查。

## 五、提示词泄漏怎么测

第二种泄漏（提示词泄漏）不像前两种那么显眼，因为它藏在你的 few-shot 例子里。

**先把这个词解释清楚。** few-shot 指的是**在提示词里放几条「输入 → 期望输出」的示范**，让模型照着格式与风格回答。不放示范叫 zero-shot，放一条叫 one-shot，放几条叫 few-shot。示范与评测题通常保存在不同位置，但**文件分开不等于内容独立**。如果示范直接包含评测答案、近重复题或足以唯一推出答案的信息，模型在评测时就能从上下文取得本应被测的内容。示范教格式或一般任务知识可能是预期行为；要判断风险，必须核对具体题目、示范内容和评测目标。

一段真实形态的提示词（示例：构造数据，未实跑；分界处就是 few-shot 那一段）：

```text
你是客服助手。回答要给出可执行的下一步，不要编造时限。

【示范 1】
用户：我的订单显示已发货但没收到。
标准输出：先查物流单号；若超过 7 天未更新，点「申请售后」→「未收到货」，我们代为跟进。

【示范 2】
用户：我要改收货地址。
标准输出：订单未发货时在订单页点「修改地址」；已发货则联系承运方改派。

【以下才是真实请求】
用户：优惠券核销失败，提示不在有效期。
```

上面【示范 1】【示范 2】这两段就是 few-shot。**测泄漏时删的就是它们，不是任务描述、不是【以下才是真实请求】那一句。**

测法很直接：**做一次消融**。

把当前提示词跑一遍评测集，记下分数；然后把 few-shot 例子**整段删掉**再跑一遍。

- 如果分数变化很小 → 在这批样本与当前 scorer 下，没观察到明显影响；不能据此排除泄漏。
- 如果分数明显下降 → 说明系统对示范敏感；它可能教了格式、一般知识，也可能与评测题重合，单凭分数差不能区分这些机制。

反过来也要测一次：**把例子换成与评测集完全无关的另一批**。
如果分数几乎不变，只能说这次替换没有在当前样本中造成可见变化；如果分数明显下降，可能是题目相似度、难度、措辞或格式示范变了，不能直接归因为泄漏。更可信的比较要固定题目和评分器，按题配对，保持示范数量/格式/长度尽量相近，反复运行并抽查错例；若要隔离「是否能看到答案」，应构造只改变答案可得性的配对条件。即使这样，结果也只支持该探针和任务范围内的判断。

对于带选项标签的 few-shot，示范答案位置也可能给模型提供捷径，但是否影响输出要用对照验证，不能从示范分布直接推断模型行为。无论如何，候选题集应先报告「只选最常见标签」基线；配平只能减少位置捷径，不能修复错误答案或概念覆盖不足。

三种对照各改哪里，写成提示词 diff 最清楚。**保持原样**就是上面的提示词。

**删掉示范**：

```diff
  你是客服助手。回答要给出可执行的下一步，不要编造时限。
-
- 【示范 1】
- 用户：我的订单显示已发货但没收到。
- 标准输出：先查物流单号；若超过 7 天未更新，点「申请售后」→「未收到货」，我们代为跟进。
- 【示范 2】
- 用户：我要改收货地址。
- 标准输出：订单未发货时在订单页点「修改地址」；已发货则联系承运方改派。
-
  用户：优惠券核销失败，提示不在有效期。
```

**换成无关示范**（内容与评测集不重合，只保留「输入 → 标准输出」这个格式）：

```diff
  你是客服助手。回答要给出可执行的下一步，不要编造时限。
-
- 【示范 1】用户：我的订单显示已发货但没收到。 标准输出：先查物流单号……
- 【示范 2】用户：我要改收货地址。 标准输出：订单页点「修改地址」……
+ 【示范 1】用户：怎么开发票？ 标准输出：在「我的 - 发票」里选择订单开票。
+ 【示范 2】用户：能开专票吗？ 标准输出：专票需在提交时填写税号，1-3 个工作日寄出。
  用户：优惠券核销失败，提示不在有效期。
```

**掉多少才能构成证据？** 不能用固定百分点阈值。先定义评测单位、主要指标、最小关心差异和停止规则；同一批题在两个条件下配对，报告差值及不确定性，并按第 10 节的设计处理重复查看。小样本时「变化超过一个经验噪声线」不自动证明泄漏；还要查具体错题，确认信息重合路径。样本不足时应报告区间和局限，不宣布因果结论。

**怎么配平。** 如果选择题格式允许安全地重排选项，可在题目定稿后轮换正确答案位置；先验证重排没有改变题意、选项依赖关系或题目顺序，再重新计算分布。以下函数会在输入缺字段、答案位置无效或标签重复时拒绝。它不做难度分层，也不保证选项语义等价，输出仍须人工复核。

```python
def balance(cases, labels="ABCD"):
    if not cases or not isinstance(labels, str) or len(labels) < 2 or len(set(labels)) != len(labels):
        raise ValueError("cases and unique labels are required")
    out = []
    for i, case in enumerate(cases):
        if not isinstance(case, dict) or not isinstance(case.get("options"), dict):
            raise ValueError("each case needs an options mapping")
        options = dict(case["options"])
        current = case.get("answer")
        if set(options) != set(labels) or current not in options:
            raise ValueError("answer and options must use exactly the configured labels")
        wanted = labels[i % len(labels)]
        if current != wanted:
            options[current], options[wanted] = options[wanted], options[current]
        out.append({**case, "options": options, "answer": wanted})
    return out

# 在定稿、人工检查题意之后运行；输出仍需答案键与内容复核。
```

配平后再运行 `answer_distribution` 检查标签计数；若选项不能安全重排，就保留原题并使用按标签分层的评分/报告。配平无法修复错误答案、歧义题或概念覆盖不足。
## 六、降低泄漏与过拟合风险的四条做法

**一、把评测集按用途分层。** 快速回归集可以随代码持续运行；发现集用于吸收线上失败与新边界；确认集用于阶段性比较。确认集要限制访问、预先规定查看时点并记录每次使用；多次根据确认集结果调整后，它也会成为开发反馈，必要时应刷新题目或引入新的确认集。留出集有帮助，但不是对自适应过拟合的绝对免疫。

**二、模型生成的题只当候选池。** 生成结果进入评测前，逐题校验结构、答案、歧义、难度和考点；另报最常见答案位置基线与概念覆盖。配平只是减少标签捷径的一种处理，不取代人工审题。

**三、记录来源、版本与使用历史。** 每题记录来源、加入日期、修改记录、所属集合、参考答案依据与审核者。来自线上失败案例的题可能随产品变化而陈旧；提示词、模型、数据集或评分器变化时，说明哪些题被用于调优，避免把开发集成绩当独立确认。

**四、将成功率与错误结构一起监控。** 长期 100% 表示当前集对该模型/版本可能出现天花板，仍能作为回归哨兵发现退化，但难以衡量进一步提升；长期 0% 也可能是任务不匹配、评分错误或难度过高。检查分层表现、错误案例、评分器与任务覆盖，再决定加难度或替换题目。

## 七、小结

- **至少区分三种风险**：训练数据暴露、运行时上下文泄漏、开发者根据重复评测反馈形成的自适应过拟合；这是一种工作分类，不是唯一标准分类。
- **历史生成题批次有答案位置偏斜**：最常见答案 B 在两批分别占 60.0% 与 73.7%；总选 B 的基线就能取得相同比例，不能把条件性 p 值当作模型普遍偏好 B 的证明。
- **名义题数不代表覆盖**：19 道可解析题经本次人工分类为 6 个概念簇；该结果没有独立标注一致性，不能外推为通用重复率。
- **解析率不等于题目有效率**：历史批次有 5/8、19/20、20/20 答案字段可解析；解析器没有验证完整 schema、参考答案和题目质量。
- **生成题只能先作候选**：准入需要结构校验、答案与内容复核、概念覆盖审查；位置配平只是其中一项。
- **确认集也会因反复查看而适应性过拟合**；固定留出、访问控制、使用日志和周期性刷新应结合使用。

最后回到那句话：泄漏最麻烦的地方不是它让分数变高，而是**它让分数变得无法解释**。分数涨了 5 个百分点，你不知道那是系统真的变好了，还是这一轮恰好撞上了模型更熟的那几个考点。要让结果更可解释，记录评测单位、版本、评分器、数据来源与每次查看，并用独立确认材料检验关键结论。

一个可操作的自检：先报告「始终选择该批最常见答案位置」的基线，并检查按考点/难度/来源分层的表现；若有多个答案位置，再做保留题目与正确答案不变、只置换评分器标签映射的负对照，以检查评分器是否意外依赖标签。直接随机打乱题目正确答案再重跑会改变任务本身，不能作为泄漏检验。
