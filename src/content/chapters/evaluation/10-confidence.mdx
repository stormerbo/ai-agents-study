前面几节反复出现「看不出差别」。这一节先量化一个更窄的问题：**要把单个成功率估计到指定精度，需要多少独立样本。** 这不是两个版本对比的样本量；版本比较还要声明显著性水平、检验效能（power）、独立实验单位和是否配对。

这个数字会让你重新评估很多结论。先看结果：

```text
基线 90% 时，估计一个成功率且让 95% 区间的近似全宽不超过：
  全宽 1pp   →  13,830 个独立样本
  全宽 2pp   →   3,458 个独立样本
  全宽 5pp   →     554 个独立样本
  全宽 10pp  →     139 个独立样本
```

**这些数字描述估计单个成功率的精度，不表示能证实某次改动提升了 1 个百分点。**

## 一、为什么基线会改变所需样本

同一张表换个基线，数字差得很大：

```text
基线 p   全宽 5pp ->  全宽 2pp ->  全宽 1pp ->
p=0.50     1,537      9,604      38,416
p=0.80       984      6,147      24,587
p=0.90       554      3,458      13,830
p=0.95       292      1,825       7,300
p=0.99        61        381       1,522
```

从 p=0.5 到 p=0.99，把区间全宽估到 1pp 所需样本从 **38,416 降到 1,522 —— 差 25 倍**。这张表是 Wald 正态近似的演算；例如 p=.99、全宽 5pp 得到 n=61，预期失败数只有 0.61，正态近似并不可靠，不能把它当成推荐样本量。靠近边界或样本较小时，应按 Wilson/Clopper-Pearson 的目标精度逐个搜索 n。

这里的计算对象是一个二项比例的估计区间。若 `delta` 是 95% 双侧区间的目标全宽，则用 Wald 正态近似反推的规划样本量为 `n = 4 z² p(1-p) / delta²`（`z=1.96`）；它不保证最终 Wilson 区间全宽严格不超过 `delta`，小样本或边界比例应直接按目标区间方法数值搜索样本量。规划时若 `p` 未知，用 `p=0.5` 可给出这个近似公式下的保守最大方差。**这衡量估计精度，不衡量两个版本差异的检验效能。**

- p=0.5 时，p(1-p) = 0.25（最大）
- p=0.9 时，p(1-p) = 0.09
- p=0.99 时，p(1-p) = 0.0099（约 0.25 的 1/25）

方差小 25 倍，达到同一估计精度所需样本就小 25 倍。样本量公式里，那个 p(1-p) 正好在分子上：

```text
n = 4 * z^2 * p(1-p) / delta^2         （delta 是 95% 区间近似全宽，z=1.96）
```

**直觉上也能理解：** 一个成功率 99% 的系统，它「失败」这件事本身很稀有，
所以少数几次失败就能说明分布；而一个 50% 的系统，两种结果各自一半，
你需要更多样本才能确认偏离。

这条推论只适用于单比例估计精度：**基线在 50% 左右时，不要指望用少量样本把成功率估得很精确。**
若问题是比较两个版本，不能直接套这张表；应按预期差异、显著性水平、power、任务配对结构和多重比较方案重新计算。

## 二、一个边界案例：全相同样本会让普通 bootstrap 退化

历史实验记录为 **40 次运行全部通过**（8 个任务各跑 5 次）。这里展示的是把每次运行暂按独立 Bernoulli 观测处理的区间计算；由于同一任务重复运行可能相关，40 次不必然等于 40 个独立任务，不能据此直接推断任务总体成功率。对这些记录计算 95% 区间，方法不同结果完全不同：

```text
点估计            100.0%
Wilson 区间       [91.2%, 100.0%]
bootstrap 区间    [100.0%, 100.0%]      <-- 宽度为 0
```

**bootstrap 给出的区间宽度是 0** —— 它说「成功率一定是 100%，误差范围为零」。
这显然不对：40 次观测到的全是成功，不代表真实成功率就是 100%。

原因在于 bootstrap 的机制：它通过**有放回地重采样观测值**来估计波动。
当所有观测值都相同时，无论怎么重采样，抽到的都是同一个值，
于是每个重采样样本的均值都等于原样本均值 —— **区间自然退化成一点。**

Wilson 区间没有这个问题，因为它用的是**解析公式**，
其中含有一个「没见过失败」也要计入的不确定性（公式里那个 `z^2/(2n)` 项）。

结论要说窄一些：当样本全相同（例如全通过）时，普通 percentile bootstrap 会退化成零宽区间；这不等于所有 bootstrap 在比例接近边界时都无效。若目标是二项成功率区间，优先报告 Wilson，或小样本下报告 Clopper-Pearson，并说明区间假设。

**两者该选哪个。** Wilson 是反演 score 检验得到的区间；Clopper-Pearson 通过反解二项分布尾概率构造，覆盖率至少达到名义水平，但由于离散性常偏保守。两种方法的区间宽度**没有固定的大小顺序**：例如 95% 双侧区间下，0/95 的 Clopper-Pearson 上限约为 3.81%，Wilson 上限约为 3.89%，前者略窄；40/40 与 26/30 的本地演示中则是 Clopper-Pearson 更宽。选方法时应看目标覆盖性质、样本量和边界情形，不要把“精确”误解成每组数据上都更宽或更适合。下面的教学实现用二分法反解二项分布尾概率：

```python
import math


def clopper_pearson(k, n, alpha=0.05):
    """精确二项区间；教学实现，适用于小到中等 n。"""
    if type(k) is not int or type(n) is not int:
        raise TypeError("k and n must be integers")
    if n <= 0 or not 0 <= k <= n:
        raise ValueError("require n > 0 and 0 <= k <= n")
    if not 0 < alpha < 1:
        raise ValueError("alpha must be strictly between 0 and 1")

    def tail_ge(p):                      # P(X >= k)
        return sum(math.comb(n, i) * p**i * (1 - p)**(n - i) for i in range(k, n + 1))
    def tail_le(p):                      # P(X <= k)
        return sum(math.comb(n, i) * p**i * (1 - p)**(n - i) for i in range(k + 1))

    lo, hi = 0.0, 1.0
    for _ in range(60):                  # 二分 60 次，精度远超需要
        mid = (lo + hi) / 2
        if tail_ge(mid) < alpha / 2:
            lo = mid
        else:
            hi = mid
    lo_bound = lo

    lo, hi = 0.0, 1.0
    for _ in range(60):
        mid = (lo + hi) / 2
        if tail_le(mid) > alpha / 2:
            lo = mid
        else:
            hi = mid
    return lo_bound, hi
```

**本次修复中实跑（2026-10-12，实跑数据）**：40 次全通过时 Wilson 下界 91.24%、Clopper-Pearson 下界 91.19%，差别极小；但换到 26/30 这种更小的样本，Wilson 是 [70.32%, 94.69%]、Clopper-Pearson 是 [69.28%, 96.24%] —— **精确法的区间明显更宽。** 区间越宽，你越难靠它下结论，这就是「Wilson 够用」的实际含义。

## 三、40 次全通过到底能断言什么

在把 40 次运行视为 IID Bernoulli 样本的前提下，Wilson 区间为 **[91.2%, 100%]**；任务内重复导致的相关性会使这个区间不再具有声称的总体覆盖率。
你不能说「成功率 100%」，更不能说「超过 95%」。

那要断言「成功率 ≥ 95%」，需要多少次连续通过？

```text
需要 0.95^n <= 0.05  ->  n >= ln(0.05)/ln(0.95) = 58.4  ->  59 次
```

**假设每次运行是 IID Bernoulli 试验，59 次全通过时单侧 95% Clopper-Pearson 下界约为 95.05%。**

这个数字可以用来校准直觉：很多项目跑 20 次全绿就宣布「稳定了」，
而 20 次全绿对应的置信下界只有 86%（用同样公式算）。

## 四、把它变成决策规则

这些数字的意义不在于「学术上严谨」，而在于它给你一条**事先就能执行的规则**。
做法是反过来用那张表：

**第一步，先问清目标是估计一个版本的成功率，还是比较两个版本。** 本节表格只回答前者：给定基线和置信区间全宽，估算单个比例需要的独立样本量。比较版本时，先确定预期差异、显著性水平、power、配对方式和主要指标，再使用适用于该设计的计算方法。

**第二步，按区间全宽目标估算样本量，再算出测量成本。** 554 个独立样本、每次约 2000 token，
就是一百多万 token。**在动手之前就知道价钱，是这一节最实际的价值。** 若多个运行来自同一任务，它们可能相关，不能不加说明地全部当作独立样本。

**第三步，如果做不起，就换一个能看出差别的指标。** 这三条路通常有效：

- **若它符合产品目标，换成连续指标**：可以测「平均输出 token」「平均步数」「平均延迟」，但连续指标并不自动更有检验效能；仍要按目标任务、方差、配对结构和预设差异估算样本量。第 7 节的历史记录报告正确率相同、成本差 227 token，但没有原始逐次 trace 时不把它视为普遍效果。
- **若比较两个版本，考虑配对设计**：同一任务分别运行两版可消去部分任务难度差异，但应按配对结果重新估算，不沿用本节单比例表
- **单独跟踪一票否决类的硬指标**：例如是否发生重复退款调用。一次已确认的违规就足以触发调查；但「零次违规」是零事件观察，不等于风险为零。若把每次独立试验中的违规概率记为 q，连续 n 次都未观察到违规时，95% 单侧精确上界为 `1 - 0.05^(1/n)`；要把上界压到约 5% 以下仍需 59 次无违规。重复任务、同一用户或同一会话内的运行相关时，必须按独立单位重新设计分析。

**第四步，如果预先设计的版本比较需要较多样本，就接受它需要长期积累。** 把它做成持续跑的后台任务，
攒几周再下结论。**不要用「跑了 30 次，好像好一点」来代替这件事** ——
那正是本节开头说的那种没有信息量的结论。

这个「持续积累」要有可执行的停止规则，否则很快会变成「每周看一眼折线图」。若采用固定样本量方法，开始前登记样本量与分析时点，到达后再作正式判断；中途的图表只作描述性监控，不用它临时挑选显著结果。若希望多次正式查看并允许提前停止，须预先选用并验证序贯方法及其边界。简单地每次重算普通区间不会自动获得任意时点有效的覆盖率。运行日志仍应逐次保存：

```json
{"date": "2026-10-12", "n": 30, "pass": 26, "model": "deepseek-flash",
 "prompt_sha8": "a1b2c3d4", "env_sha8": "e5f6a7b8"}
```

（示例：构造数据，未实跑。）趋势的判据也是区间：**只有当累计区间全宽达到预设的精度目标时，单比例估计才足够精确** —— 版本比较需要另行设计检验。

## 五、一个不该忽略的替代方案：序贯检验

上面所有公式都假设一件事：**样本量在开始前就定好，跑完再看结果。**
这个前提很重要，因为如果你**边跑边看**，看到显著就停，普通固定样本量检验通常不再维持名义上的 5% 整体错误率。膨胀多少取决于查看时点、统计量相关性和停止规则；不能把每次查看简单当作独立机会计算。

但「一次跑完再看」在工程上又不现实 —— 你不可能为了省统计效力，
明知新版本更差还要跑满几万次。

解法叫**序贯检验**：事先定好一条随样本量变化的判定边界，
每积累一批就看一次，但只在越过边界时才停。常见的实现是
**alpha spending**（把总假阳性预算分摊到各次查看上）或 **SPRT**（序贯概率比检验）。

序贯设计在某些备择情形下可以更早停下，但平均样本量取决于效应大小、错误率预算、边界和停止规则；它也可能没有节省，不能承诺「几十次就够」。代价是分析更复杂，而且你必须**事先**确定边界，不能看到数据之后再定。

对个人项目来说，一个务实的折中是：**先把样本量算出来，
然后按事先声明的序贯边界查看并决定是否提前停止**，
并且**把每次查看记录下来**。没有预设序贯规则时，不要因反复查看后偶然显著而提前停止。

**还有一个全文没提、但迟早会踩的坑：多重比较。** 上面的 5% 假阳性率是**单个指标**的预算。在 5 个相互独立且各自零效应的检验中，每个都用 `p<0.05`，至少一个假阳性的概率是 `1 − 0.95^5 ≈ 23%`（独立情形下的演示计算）；指标相关时数值会不同。修正规则按简单到严格：

- **Bonferroni**：把阈值除以指标数（5 个指标就用 0.01）。最保守、最好记。
- **Benjamini-Hochberg（FDR）**：控制「报出来的显著项里假阳性的比例」，指标多时更实用。

落到评测上的做法是：**先声明哪个是主指标**（它单独用 0.05），其余算探索性指标，报告时明确标注「未做多重比较修正」。**不修正也可以，但必须说清楚哪个结论是事先声明的、哪个是事后从数据里挑出来的** —— 后者不能当结论用。

## 六、代码

下面这段无第三方依赖，包含 Wilson 区间、bootstrap、样本量计算三个函数。

```python
import math, random


def _count_pair(k, n):
    if type(n) is not int or type(k) is not int:
        raise TypeError("k and n must be integers")
    if n <= 0 or not 0 <= k <= n:
        raise ValueError("require n > 0 and 0 <= k <= n")


def wilson(k, n, z=1.96):
    """Two-sided Wilson score interval for an IID Bernoulli proportion."""
    _count_pair(k, n)
    if not math.isfinite(z) or z <= 0:
        raise ValueError("z must be finite and positive")
    p = k / n
    d = 1 + z * z / n
    c = p + z * z / (2 * n)
    h = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n))
    return max(0.0, (c - h) / d), min(1.0, (c + h) / d)


def bootstrap(obs, n_boot=10000, seed=1):
    """Naive percentile bootstrap; all-identical observations yield a point interval."""
    if not obs:
        raise ValueError("obs must not be empty")
    if type(n_boot) is not int or n_boot < 1:
        raise ValueError("n_boot must be a positive integer")
    rng = random.Random(seed)
    n = len(obs)
    ms = sorted(sum(rng.choice(obs) for _ in range(n)) / n for _ in range(n_boot))
    return ms[int(0.025 * (n_boot - 1))], ms[int(0.975 * (n_boot - 1))]


def samples_needed(p, delta, z=1.96):
    """Approximate IID Bernoulli n for a two-sided interval's target full width delta."""
    if not math.isfinite(p) or not 0 < p < 1:
        raise ValueError("planning p must be strictly between 0 and 1")
    if not math.isfinite(delta) or not 0 < delta < 1:
        raise ValueError("delta must be a proportion strictly between 0 and 1")
    if not math.isfinite(z) or z <= 0:
        raise ValueError("z must be finite and positive")
    return math.ceil(4 * z * z * p * (1 - p) / (delta * delta))


def runs_for_lower_bound(target, confidence=0.95):
    """All-success IID Bernoulli runs for a one-sided exact lower bound >= target."""
    if not math.isfinite(target) or not 0 < target < 1:
        raise ValueError("target must be strictly between 0 and 1")
    if not math.isfinite(confidence) or not 0 < confidence < 1:
        raise ValueError("confidence must be strictly between 0 and 1")
    return math.ceil(math.log(1 - confidence) / math.log(target))


obs = [1] * 40
print("Wilson 40/40:", wilson(40, 40))
print("bootstrap 40/40:", bootstrap(obs))
print("p=.9 sample sizes:", [samples_needed(.9, width / 100) for width in (1, 2, 5, 10)])
print("all-success runs for lower bound >= .95:", runs_for_lower_bound(.95, .95))
```

```text
  Wilson 区间     [91.2%, 100.0%]
  bootstrap 区间  [100.0%, 100.0%]
  断言 >= 95% 需连续 59 次全通过

p=0.9 时，单比例估计的 95% 区间全宽目标

```

### 一个真实的报错

我第一次算「多少次全通过才能断言 ≥95%」时写的是：

```python
import math

n = math.ceil(1 / (1 - 0.95))        # 错：算出 20
```

思路是「95% 的反面是 5%，所以 20 次里错一次」—— 这算的是**平均失败间隔**，
不是**置信下界**。两者的区别在于后者要的是「在 5% 的概率下，
真实成功率仍然低于 95%」这个条件，所以是**乘积**而不是倒数：`0.95^n <= 0.05`。

算出来是 **59 次**，不是 20 次 —— **差了三倍**。
这个错误的诱人之处在于它给出的数字「看起来合理」（20 次全绿确实是常听到的说法），
而它把置信要求放松了。判断办法很直接：**凡是「至少需要多少次」的问题，
先写出要满足的不等式，再解它**，不要凭直觉套一个除法。

## 七、小结

- **单比例估计在 p=0.9 时，95% 区间全宽约 1pp 需要 13,830 个独立样本** —— 这是精度目标，不是证明版本提升 1pp
- **区间全宽 5pp 约需 554 个样本，全宽 10pp 约需 139 个样本** —— 同样只适用于单比例估计
- **基线决定估计成本**：p=0.5 比 p=0.99 要多约 25 倍样本，因为方差是 p(1-p)
- **全体观测值都相同时，普通 percentile bootstrap 会退化成零宽区间** —— 这说明该方法在这个样本上的重采样不能反映不确定性，不代表所有 bootstrap 方法在比例边界附近都无效
- **40 次全通过只能断言 [91.2%, 100%]**；断言 ≥95% 需要连续 59 次
- **凡是「至少需要多少次」，先写不等式再解** —— 别用直觉的除法
