前面几节反复出现「看不出差别」。这一节把它量化：**要看出多大的差别，需要多少样本。**

这个数字会让你重新评估很多结论。先看结果：

```text
基线 90% 时，要分辨：
  1pp 的差距   →  每组 13,830 次
  2pp 的差距   →  每组  3,458 次
  5pp 的差距   →  每组    554 次
  10pp 的差距  →  每组    139 次
```

**「这次改动让成功率提升了 1 个百分点」—— 这句话在你没有一万四千个样本时，
基本上没有信息量。** 而 5pp 以上才是几十到几百次就能看清的量级。

## 一、为什么基线会改变所需样本

同一张表换个基线，数字差得很大：

```text
基线 p     5pp ->      2pp ->       1pp ->
p=0.50     1,537      9,604      38,416
p=0.80       984      6,147      24,587
p=0.90       554      3,458      13,830
p=0.95       292      1,825       7,300
p=0.99        61        381       1,522
```

从 p=0.5 到 p=0.99，分辨 1pp 所需的样本从 **38,416 降到 1,522 —— 差 25 倍**。

原因藏在一个很简单的东西里：**方差是 p(1-p)。**

- p=0.5 时，p(1-p) = 0.25（最大）
- p=0.9 时，p(1-p) = 0.09
- p=0.99 时，p(1-p) = 0.0099（约 0.25 的 1/25）

方差小 25 倍，所需样本就小 25 倍。而样本量的公式里，那个 p(1-p) 正好在分子上：

```text
n = 4 * z^2 * p(1-p) / delta^2         （z=1.96 对应 95% 置信）
```

**直觉上也能理解：** 一个成功率 99% 的系统，它「失败」这件事本身很稀有，
所以少数几次失败就能说明分布；而一个 50% 的系统，两种结果各自一半，
你需要更多样本才能确认偏离。

这条推论很实用：**如果你的基线是 50% 左右，不要指望靠评测看出 1~2pp 的改进。**
那种改进要靠别的证据（比如机制上说得通、或者换成配对比较），而不是靠刷样本。

## 二、一个真实的坑：bootstrap 会在极端比例上失效

我拿第 2 节的真实观测做了一个实验。那批数据是 **40 次运行全部通过**（8 个任务各跑 5 次）。
对这样的数据算 95% 区间，方法不同结果完全不同：

```text
点估计            100.0%
Wilson 区间       [91.2%, 100.0%]
bootstrap 区间    [100.0%, 100.0%]      <-- 宽度为 0
```

**bootstrap 给出的区间宽度是 0** —— 它说「成功率一定是 100%，误差范围为零」。
这显然不对：40 次观测到的全是成功，不代表真实成功率就是 100%。

原因在于 bootstrap 的机制：它通过**有放回地重采样观测值**来估计波动。
当所有观测值都相同时，无论怎么重采样，抽到的都是同一个值，
于是每个重采样样本的均值都等于原样本均值 —— **区间自然退化成一点。**

Wilson 区间没有这个问题，因为它用的是**解析公式**，
其中含有一个「没见过失败」也要计入的不确定性（公式里那个 `z^2/(2n)` 项）。

**所以：比例接近 0 或 1 时，不要用 bootstrap。** 用 Wilson 或 Clopper-Pearson。
这是本节最实用的一条。

**两者该选哪个。** Wilson 是近似（score interval），Clopper-Pearson 是精确（按二项分布反解），后者给出的区间总是不窄于前者。工程判据很直接：**做 CI 门禁、看趋势，Wilson 就够用**（解析式、一行算完）；只有对外的覆盖率数字、样本量又不大时，才换成 Clopper-Pearson。它的实现是二分反解二项分布尾概率：

```python
def clopper_pearson(k, n, alpha=0.05):
    """精确二项区间：下界 = 使 P(X>=k) <= alpha/2 的最大 p。"""
    def tail_ge(p):                      # P(X >= k)
        return sum(math.comb(n, i) * p**i * (1 - p)**(n - i) for i in range(k, n + 1))
    def tail_le(p):                      # P(X <= k)
        return sum(math.comb(n, i) * p**i * (1 - p)**(n - i) for i in range(k + 1))

    lo, hi = 0.0, 1.0
    for _ in range(60):                  # 二分 60 次，精度远超需要
        mid = (lo + hi) / 2
        if tail_ge(mid) < alpha / 2:
            lo = mid
        else:
            hi = mid
    lo_bound = lo

    lo, hi = 0.0, 1.0
    for _ in range(60):
        mid = (lo + hi) / 2
        if tail_le(mid) > alpha / 2:
            lo = mid
        else:
            hi = mid
    return lo_bound, hi
```

**本次修复中实跑（2026-10-12，实跑数据）**：40 次全通过时 Wilson 下界 91.24%、Clopper-Pearson 下界 91.19%，差别极小；但换到 26/30 这种更小的样本，Wilson 是 [70.32%, 94.69%]、Clopper-Pearson 是 [69.28%, 96.24%] —— **精确法的区间明显更宽。** 区间越宽，你越难靠它下结论，这就是「Wilson 够用」的实际含义。

## 三、40 次全通过到底能断言什么

把 Wilson 区间写清楚：**40 次全通过，只能断言成功率在 [91.2%, 100%] 这个范围里。**
你不能说「成功率 100%」，更不能说「超过 95%」。

那要断言「成功率 ≥ 95%」，需要多少次连续通过？

```text
需要 0.95^n <= 0.05  ->  n >= ln(0.05)/ln(0.95) = 58.4  ->  59 次
```

**59 次全通过**，才能说「在 95% 置信下成功率不低于 95%」。

这个数字可以用来校准直觉：很多项目跑 20 次全绿就宣布「稳定了」，
而 20 次全绿对应的置信下界只有 86%（用同样公式算）。

## 四、把它变成决策规则

这些数字的意义不在于「学术上严谨」，而在于它给你一条**事先就能执行的规则**。
做法是反过来用那张表：

**第一步，先问「我想看出多大的差别」。** 不要问「需要多少样本」，
而是问「我这次改动预期能带来多少提升」。如果你的预期是 1pp，那么答案是「这个实验做不起」，
直接换别的验证方式。

**第二步，按预期差距查样本量，算出这个实验的成本。** 554 次任务、每次约 2000 token，
就是一百多万 token。**在动手之前就知道价钱，是这一节最实际的价值。**

**第三步，如果做不起，就换一个能看出差别的指标。** 这三条路通常有效：

- **换成连续指标**：正确率分辨不了 1pp，但「平均输出 token」「平均步数」「平均延迟」
  这类连续量往往能分辨（第 7 节那个实验就是例子 —— 正确率完全一样，成本差 227 token）
- **换成配对设计**：同样的样本量下灵敏度提升（第 7 节实测约 17%）
- **换成一票否决类的硬指标**：不测「成功率提升了多少」，而是测「有没有出现某类必须为零的行为」
  （比如「有没有调用过退款接口两次」）。零容忍类指标的样本量需求低得多

**第四步，如果必须测小差距，就接受它需要长期积累。** 把它做成持续跑的后台任务，
攒几周再下结论。**不要用「跑了 30 次，好像好一点」来代替这件事** ——
那正是本节开头说的那种没有信息量的结论。

这个「持续积累」要有个可执行的形态，否则很快会变成「每周看一眼折线图」。做法是**每次评测追加一条记录，需要看结论时对汇总后的 `n` 重算区间**，而不是对每天的单点下结论：

```json
{"date": "2026-10-12", "n": 30, "pass": 26, "model": "deepseek-flash",
 "prompt_sha8": "a1b2c3d4", "env_sha8": "e5f6a7b8"}
```

（示例：构造数据，未实跑。）趋势的判据也是区间：**只有当累计区间的半宽小于你要分辨的差距时，这个实验才做得起** —— 回到本节开头 13,830 那个数字。

## 五、一个不该忽略的替代方案：序贯检验

上面所有公式都假设一件事：**样本量在开始前就定好，跑完再看结果。**
这个前提很重要，因为如果你**边跑边看**，看到显著就停，
那么真实的假阳性率会远高于 5% —— 这就是所谓「偷看（peeking）」问题。

你每多看一次，就多一次「碰巧显著」的机会。跑十次看十次，
即使真实效果为零，看到一次「p 值小于 0.05」的概率也会远超 5%。

但「一次跑完再看」在工程上又不现实 —— 你不可能为了省统计效力，
明知新版本更差还要跑满几万次。

解法叫**序贯检验**：事先定好一条随样本量变化的判定边界，
每积累一批就看一次，但只在越过边界时才停。常见的实现是
**alpha spending**（把总假阳性预算分摊到各次查看上）或 **SPRT**（序贯概率比检验）。

它的好处是**平均所需样本显著小于固定样本量设计**（尤其当效果很大时，
可能几十次就能停）。代价是分析更复杂，而且你必须**事先**确定边界，
不能看到数据之后再定。

对个人项目来说，一个务实的折中是：**先把样本量算出来，
然后每攒够 1/4 的量看一次，但只在「方向一致且差距远大于阈值」时才提前停**，
并且**把每次查看记录下来**。这样至少不会把「看了十次挑最好的一次」当成结论。

**还有一个全文没提、但迟早会踩的坑：多重比较。** 上面的 5% 假阳性率是**单个指标**的预算。如果你同时看 5 个指标、每个都用 `p<0.05` 判定，那么「至少有一个假阳性」的概率是 `1 − 0.95^5 ≈ 23%`（纯计算），不是 5%。修正规则按简单到严格：

- **Bonferroni**：把阈值除以指标数（5 个指标就用 0.01）。最保守、最好记。
- **Benjamini-Hochberg（FDR）**：控制「报出来的显著项里假阳性的比例」，指标多时更实用。

落到评测上的做法是：**先声明哪个是主指标**（它单独用 0.05），其余算探索性指标，报告时明确标注「未做多重比较修正」。**不修正也可以，但必须说清楚哪个结论是事先声明的、哪个是事后从数据里挑出来的** —— 后者不能当结论用。

## 六、代码

下面这段无第三方依赖，包含 Wilson 区间、bootstrap、样本量计算三个函数。

```python
import math, random


def wilson(k, n, z=1.96):
    """Wilson 区间 —— 比例接近 0/1 时也稳。"""
    if n == 0:
        return 0.0, 0.0
    p = k / n
    d = 1 + z * z / n
    c = p + z * z / (2 * n)
    h = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n))
    return (c - h) / d, (c + h) / d


def bootstrap(obs, n_boot=10000, seed=1):
    """观测值全相同时会退化成一个点 —— 这是它的已知弱点。"""
    rng = random.Random(seed)
    n = len(obs)
    ms = sorted(sum(rng.choice(obs) for _ in range(n)) / n for _ in range(n_boot))
    return ms[int(0.025 * n_boot)], ms[int(0.975 * n_boot)]


def samples_needed(p, delta, z=1.96):
    """要分辨 delta 的差距，每组需要多少样本。"""
    return math.ceil(4 * z * z * p * (1 - p) / (delta * delta))


def runs_for_lower_bound(target, confidence=0.95):
    """连续多少次全通过，才能断言成功率 >= target。"""
    return math.ceil(math.log(1 - confidence) / math.log(target))
```

实跑数据（2026-10-10）：

```text
观测 40 次全通过
  Wilson 区间     [91.2%, 100.0%]
  bootstrap 区间  [100.0%, 100.0%]
  断言 >= 95% 需连续 59 次全通过

p=0.9 时分辨差距所需样本
  1pp -> 13,830    2pp -> 3,458    5pp -> 554    10pp -> 139
```

### 一个真实的报错

我第一次算「多少次全通过才能断言 ≥95%」时写的是：

```python
n = math.ceil(1 / (1 - 0.95))        # 错：算出 20
```

思路是「95% 的反面是 5%，所以 20 次里错一次」—— 这算的是**平均失败间隔**，
不是**置信下界**。两者的区别在于后者要的是「在 5% 的概率下，
真实成功率仍然低于 95%」这个条件，所以是**乘积**而不是倒数：`0.95^n <= 0.05`。

算出来是 **59 次**，不是 20 次 —— **差了三倍**。
这个错误的诱人之处在于它给出的数字「看起来合理」（20 次全绿确实是常听到的说法），
而它把置信要求放松了。判断办法很直接：**凡是「至少需要多少次」的问题，
先写出要满足的不等式，再解它**，不要凭直觉套一个除法。

## 七、小结

- **1pp 的提升在 p=0.9 时需要每组 13,830 次** —— 没有一万四千样本，这个提升无法证实
- **5pp 是 554 次，10pp 是 139 次** —— 这是「几十到几百次评测」能看清的量级
- **基线决定成本**：p=0.5 比 p=0.99 要多 25 倍样本，因为方差是 p(1-p)
- **比例接近 0/1 时不要用 bootstrap** —— 全通过时它给的区间宽度是 0
- **40 次全通过只能断言 [91.2%, 100%]**；断言 ≥95% 需要连续 59 次
- **凡是「至少需要多少次」，先写不等式再解** —— 别用直觉的除法
