第 1 节说判据必须可判定。这一节回答两个接下来的问题：**题目从哪来**，以及**多少题才够**。

第二个问题有一个可以算的答案 —— 但它取决于一个容易被忽略的变量。

## 题目从哪来

评测集没有固定的「最佳来源排名」。先问它要回答什么，再组合不同来源：

- **生产反馈与失败轨迹**：用于收集真实系统已经暴露的问题。先去除或替换个人信息、凭据和不必要的业务字段；检查采集授权、保留期限、访问权限与删除流程。用户投诉和线上故障会过度代表严重或容易被发现的问题，不能直接当作生产流量的随机样本。
- **代表性生产样本**：从目标时间窗口按真实流量或预先定义的分层规则抽样，用于估计常见输入上的总体表现。若要估计总体均值，抽样比例和权重必须与目标分布相符；人为多抽的稀有难例要单独报告或按已知抽样概率加权。
- **领域专家编写的案例**：用来覆盖业务规则、边界条件、拒答、歧义、政策变化与高影响风险。它们可以有意过采样低频但重要的事件，适合验证覆盖与安全要求，不适合直接解释为线上发生率。
- **合成变体与公开基准**：合成变体适合系统地改变实体、边界值、措辞或干扰项；要抽样人工核验变体是否保留原意。公开基准可以作为某些通用能力的参考，但任务、提示和训练暴露都可能与自己的系统不同；它不能替代业务样本，也不能单独证明某个版本改动在你的系统上有效。

通常会把这些来源混合使用，而不是只收线上失败或只搬公开题。**失败案例适合阻止已知问题复发；代表性样本适合估计当前分布；专家与合成案例适合补足覆盖和风险边界**。数据来源、抽样方式和目标指标共同决定一项分数能代表什么。OpenAI 的评测指南也把生产、领域专用、合成、人工整理、购买与历史数据列为可选来源，并建议持续扩充边界和盲区案例；这只是可借鉴的收集清单，不是厂商无关的唯一标准。

**工具状态要和方法建议分开看。** 截至 2026-10-22，OpenAI 已宣布 Evals 平台进入退役流程：现有评测计划于 2026-10-31 变为只读，Dashboard 与 API 计划于 2026-11-30 关闭。上面的数据来源分类仍可作为方法参考，但不要把 Evals API 或 Dashboard 当作新项目的长期依赖；OpenAI 的[退役时间表](https://developers.openai.com/api/docs/deprecations)及[迁移指南](https://developers.openai.com/cookbook/examples/evaluation/moving-from-openai-evals-to-promptfoo)会说明当前安排和迁移路径，实施前应重新核对。

收集时为每条用例保留来源类型、采集/加入时间、适用业务版本、审核依据、抽样层、标签版本和所属集合。不要把原始客户轨迹未经审查就复制进长期回归库。评测集也要分开发集、持续回归与受控确认材料；调 prompt 的开发集不再是独立确认集，详见[数据泄漏一节](/chapters/evaluation/contamination)。

## 多小才够：先说清楚要估计什么

档案中有一项 2026-10-09 的历史摘要：20 道算术、日期抽取和数值推理题，记为答对 19 道。题目被分成 12 道较简单、8 道较难。**这只是旧记录里的 19/20 摘要，不是本轮重新调用模型得到的结果。** 逐题原始响应、模型快照和可复核判分没有归档；而当时脚本用「期望答案是输出子串」作主要判分，例如输出 `15910` 也会被 `1591` 的子串检查误判为正确。因此不能把 95% 当作已核实的模型准确率或线上成功率。数值与日期应按明确格式归一后对整个字段匹配，允许误差时要写出量纲、容差和舍入规则；自然语言质量应使用带锚点的 rubric 或人工复核，不能靠关键词子串替代。

即便把 19/20 当作暂时可信的算术输入，它也只给出这 20 个题目上的**观测比例 95%**。在假设每题是从同一个目标分布独立抽取、判分正确的前提下，Wilson 95% 区间约为 **76.4%–99.1%**；但这批题是刻意分层的简单/困难组合，且没有保存逐题结果与目标流量权重，IID 代表性假设无法确认。这个区间只能演示「小样本比例很不确定」，不能替这次旧测量背书。

还有一个容易混淆的计算：对同一组 20 个二元结果做有放回 bootstrap，得到的是「从这 20 个已观察结果再抽小集合」的经验分布。它不会模拟新模型调用，也不是模型真实波动，不能自动代表真实用户问题的抽样误差；如果原题刻意分了难度层，就必须在重采样设计中保留分层结构。历史代码输出与正文表格也不完全一致，且逐题结果没有留档，所以本节撤下旧 bootstrap 波动表，不把它解释成真实模型波动或 A/B 噪声。

先区分三个问题：**描述已有题目**（报告通过数/题数与失败案例）、**估计目标分布上的通过率**（需要定义目标人群、抽样方案和评分规则）、**比较两个版本**（还需要定义比较单位、配对方式、最小关心差异、显著性水平和检验功效）。它们需要的证据不同，「多小才够」没有不看任务就能回答的固定题数。

## 估计精度与版本比较不是同一题

对一个版本的二元通过率，常见的大样本近似是：

```text
区间全宽 ≈ 2 × z × sqrt(p(1-p) / n)
```

`p` 是规划时假设的基线通过率，`n` 必须是近似独立且来自目标总体的任务数；`z` 由置信水平决定。动手前先定义独立评测单位：一次调用、一个任务还是一组同任务重复运行，不能混为一个分母。它描述的是**单个比例估计的精度近似**。小样本或 p 接近 0/1 时，Wald 正态近似可能失真；报告观察结果时优先使用 Wilson 或精确二项区间。更具体的比例区间边界见[评估置信度一节](/chapters/evaluation/confidence)。

若目标是让单个比例的**近似半宽**不超过某个值，可以用 `n ≈ z²p(1-p)/margin²` 做初步预算。以 90% 置信、规划基线 `p=0.9` 为例，半宽 ±10 个百分点约需 25 个独立任务，±5 个百分点约需 98 个；若基线未知，用 `p=0.5` 会给出该公式下更保守的方差规划。它们是近似的单比例精度计划，不是检测版本差异的样本量承诺。

**比较版本要另行设计。** 样本量取决于目标差异（最小关心差异）、基线率、显著性水平、power、单侧/双侧判断、实验单位、任务是否配对，以及重复运行/聚类和多指标问题。相同任务分别跑 A 与 B 时，通常要保留逐题配对结果，并用配对二元结果的方法分析；把每次调用都当成独立任务会低估不确定性。不同任务分给 A/B 时则需按独立样本的比较设计计算。不能因为「比较两个比例」就把单比例题量机械乘以 2。NIST 的比例检验规划明确把可检测差异、基线比例、显著性水平与检验功效作为输入；细节和配对比较见[评估置信度](/chapters/evaluation/confidence)及[成对比较](/chapters/evaluation/paired-comparison)。

## 一个实操上的折中

评测运行时间、调用成本和标注能力都有上限，可以按**用途**分层，而不是套一个固定题量：

- **快速冒烟集**：少量、稳定、能迅速发现关键路径崩坏的案例；10–20 题可作为起步量级，不表示它有统计检测能力。每次改动都跑，但把它当回归哨兵。
- **开发/回归集**：覆盖主要任务、常见输入和已知失败。通过难度、风险、业务来源等标签查看分层结果；题数随任务异质性与可用预算决定，100–300 不是通用合格线。
- **确认集**：与 prompt/规则调优隔离，预先规定何时打开和如何比较。反复查看并据此选择下一步后，它会变成反馈来源，需要刷新或另设确认集。
- **失败候选池**：从反馈、日志、红队或线上监控不断收集；去重、脱敏、复现并审核后，再决定纳入回归集还是风险专项集。池子持续增长不等于每条新日志都应执行，也不保证覆盖仍具代表性。

一个集合可以同时有「来源」与「用途」标签。例如来源是生产失败、用途是回归；来源是专家构造、用途是确认。每次报告应说明样本是否按线上分布加权，避免把主动过采样的高风险题混成总体成功率。

关键字段的职责：`id` 用于稳定追踪案例；`input` 保存脱敏后的输入；`expected` 与 `scorer` 分开记录参考答案和判定方法；`source_type`/`source_ref` 保留来源；`stratum` 支持按任务切片；`split` 记录开发、回归或确认用途；`added`/`reviewed_at` 支持版本与时效审查。评分标准变更也应有自己的版本号。

```text
evals/
  development.jsonl       # 可反复查看并调 prompt
  regression.jsonl        # 每次改动跑已知重要案例
  confirmation.jsonl      # 受控使用，记录访问与运行
  failure-candidates.jsonl # 待脱敏、去重、复现和审查的候选池
```

## 一个常被忽略的问题：评测集的时效性

评测集会过时，也可能被你调到「看起来很好」。系统、产品政策、用户构成、模型版本、工具和攻击面都会变化；但**旧案例不一定因此失去价值**。一个已修复的故障可以继续留在回归集中，防止复发；一个很少发生但后果严重的风险案例也值得保留。应该更新的是它的标签、预期行为、适用版本和代表性解释。

定期体检时检查：

1. 目标指标、目标流量与抽样权重是否仍匹配？线上流量结构变了没有？
2. 业务规则、工具、模型和评分器版本是否变化？参考答案是否仍有效？
3. 按任务类型、来源、风险、语言和难度切片后，哪些错误增加或长期没有覆盖？
4. 集合是否被用于开发反馈？若是，是否仍被误当成独立确认集？
5. 是否有重复、过时或无法判分的题；如果移除，是否仍保留了高影响回归保护？

**不要把一个固定通过率区间（例如 80%–95%）当成健康标准。** 通过率取决于任务选择、风险权重、版本和评分规则；100% 仍可作为已知回归门禁，但不能显示更高通过率的改进；低通过率可能说明系统不足，也可能是评分器/样本与目标不匹配。检查错误分布、独立单位数量、区间与用途后再决定加题、改评分器、重新抽样或保留原案例。

## 完整可运行代码

下面的示例只依赖 Python 标准库，离线计算一个比例的 Wilson 区间和单比例精度规划。19/20 输入只是对旧历史摘要做算术演示，**本节没有重放模型调用，旧观测仍不可复核**。

实跑状态：本轮 Python 3 本地执行；无 provider 调用。公式为单比例 Wald 近似规划，比较版本需另外设计。

```python
from math import ceil, sqrt
from statistics import NormalDist


def wilson_interval(successes, n, confidence=0.95):
    if type(successes) is not int or type(n) is not int or n <= 0 or not 0 <= successes <= n:
        raise ValueError("require integer counts with 0 <= successes <= n and n > 0")
    if not 0 < confidence < 1:
        raise ValueError("confidence must be between 0 and 1")
    z = NormalDist().inv_cdf(0.5 + confidence / 2)
    p = successes / n
    denom = 1 + z * z / n
    center = (p + z * z / (2 * n)) / denom
    half = z * sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / denom
    return max(0.0, center - half), min(1.0, center + half)


def approximate_n_for_margin(p, margin, confidence=0.90):
    """Approximate n for a one-proportion Wald half-width; not comparison power."""
    if not 0 < p < 1 or not 0 < margin < 1 or not 0 < confidence < 1:
        raise ValueError("p, margin, and confidence must be between 0 and 1")
    z = NormalDist().inv_cdf(0.5 + confidence / 2)
    return ceil(z * z * p * (1 - p) / (margin * margin))


if __name__ == "__main__":
    low, high = wilson_interval(19, 20)
    print("19/20 Wilson 95%% interval: %.1f%%–%.1f%%" % (100 * low, 100 * high))
    print(f"p=.9, 90% confidence, ±10pp planning n: {approximate_n_for_margin(.9, .10)}")
    print(f"p=.9, 90% confidence, ±5pp planning n: {approximate_n_for_margin(.9, .05)}")
```

输出：

```text
19/20 Wilson 95% interval: 76.4%–99.1%
p=.9, 90% confidence, ±10pp planning n: 25
p=.9, 90% confidence, ±5pp planning n: 98
```

**解释边界：** 区间仍假设独立且代表性抽样；如果按任务类型分层、同一任务重复多次、或人为过采样高风险情形，应按抽样设计和任务聚类分析。Wald 公式用于单比例初步规划，不是 Wilson 区间宽度的保证；要比较两个版本，见成对比较/置信度章节，并设定最小关心差异、alpha、power 和配对方案。

## 常见坑

- **只用公开基准。** 它不能替代目标业务的真实分布，也不能单独验证你的系统改动。
- **只收线上失败。** 它能形成高价值回归案例，但会偏向已被发现或被报告的问题；估计总体表现还需要代表性样本。
- **把主动过采样的难例算进总体通过率。** 按层报告，或有明确抽样概率时加权；否则数字回答不了线上平均表现。
- **用子串判定数值答案。** `15910` 包含 `1591`，却不等于 `1591`；分类、日期、金额和自然语言应定义各自的归一化、容差和人工复核规则。
- **用 20 道题声称能稳定发现某个幅度的版本退步。** 单比例估计的精度不等于 A/B 检验的功效；比较要按独立任务或配对任务设计。
- **只有通过率，没有样本和评分器版本。** 同一个 90% 可以来自不同任务、抽样权重与判分口径；保存逐题结果、失败签名、数据版本和 scorer 版本。
- **集合建好就不复查，或看到 100% 就删掉。** 过时案例要更新，已知高影响案例可继续作为回归门禁；确认集多次反馈后需更换或重新设定用途。
