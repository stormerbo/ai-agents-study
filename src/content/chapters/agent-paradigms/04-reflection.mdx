Reflection（自我复核）是在初稿之后，再让模型检查或修订结果。它和 Java 服务里“再跑一次同一个方法”不一样：模型会重新采样文本，但仍可能沿用同一份错误事实、同一段缺失上下文和同一种偏见。第二次回答不同，既不证明第一次错，也不证明第二次更可靠。

所以“反思有用吗”不是模型性格问题，而是验证设计问题。你给复核者什么输入、它要产出什么、谁判断修订正确、错误结果会不会被交付，这些要在系统里明确。增加证据可以帮助比较答案与来源，但**更多证据不等于独立验证**：同一模型可能误读证据，证据本身也可能错误或不可信。

## 先区分三种常被叫作“反思”的东西

1. **同答案自评**：把答案再给模型，问“对吗”。如果没有新的标准、证据或计算，它可能只是重复原判断；是否能发现某类错误要靠任务评测，不能先假设无用或有效。
2. **基于反馈的修订**：提供测试失败、校验器错误或真实环境结果，再请模型修订。错误信息能缩小搜索范围，但最终结果仍需重新通过验收。
3. **Reflexion 方法**：原论文讨论让语言模型根据环境反馈形成文字化反思，并用于后续尝试；关键是反馈信号进入后续决策，不等于任意“请检查”提示。它也不意味着反思文本一定正确或长期记忆一定安全。

这三种操作成本和可验证性都不同。多采样取一致答案（self-consistency）又是另一种方法：它生成多个候选再聚合，不能与对先前答案做反馈修订合并成一种“反思”。

## 历史观察：保留数字，不替它们补证据

旧记录（2026-10-09，`deepseek-flash`）称：ReAct 单独的旧检查器“通过”、token 摘要为 1,203；加入 Reflection 后“通过”、token 摘要为 2,568；另称 7 次里有 2 次改坏答案、另一组三次中两种输入都被旧检查器评为 3/3。逐次原始请求/响应、精确模型快照、完整 usage 和可复算的评分记录没有归档，因此这些只能当作历史摘要，不能换算成错误率、证明修订等价或推导普遍成本。

原先的检查器以字符串包含判分，不能保证城市和温度的字段映射正确。“2 次改坏”对应的修订文本曾记录为“无法核实第一位助手的答案”，原因是批判者缺少实时天气数据；但没有原始 transcript，无法独立确认当时传入的完整证据和上下文。应保留这个实现诊断作为线索，不将它写成已验证的模型行为。

旧稿把 +113% token 摘要解释为线性任务约 2 倍成本，并据此认为更长轨迹会让成本倍数继续上升。这些推论不成立：缺少逐次 usage 无法复算基线；而反思回合的边际开销取决于实际重发的上下文、输入/输出计量、缓存与目标 endpoint。保留原始摘要有助追溯，但不应用它比较范式。

## 设计一条真正可验收的复核路径

先选一个有明确判据的任务。例如将三城温度汇总成最高/最低城市和温差。原始观测可以由程序保留成结构化字段；答案先由确定性校验器检查。如果检查通过，任务目标已满足，就不必自动增加一个模型回合。如果检查失败，再根据失败类型决定补算、重新取数、让模型根据具体错误修订，或暂停交由人工确认。

复核请求应只包含当前错误所需的最小上下文：任务目标、候选答案、相关证据和明确的错误，不要默认复制整条会话。原始工具结果、用户材料都应视为待验证数据；转交前按数据分类做脱敏、访问控制和长度限制。把工具错误原文直接拼进 prompt 既可能泄露敏感内容，也会把不可信输入混入指令上下文。

复核响应需要像其他外部输入一样处理：确认 provider 响应完整且不是拒绝或截断，解析精确字段和允许的决策，再将修订答案交给原验收器重新检查。格式正确只证明结构；独立验收通过也只支持其检查范围内的结论。若质量目标是语气、覆盖度或法律解释这类难以代码判定的标准，应定义人工标注指南、盲评方式和分歧裁决流程，而不是把同一模型的“通过”当作 ground truth。

下面的完整 Python 例子用合成的天气观测验证宿主流程（**实跑状态：Python 3.14.7，本地离线执行，2026-10-21**）。它展示：确定性错误先被校验器发现；模拟的复核响应给出候选修订；候选必须再次通过校验才交付；不完整、拒绝或畸形响应都不能交付。FakeReviewer 是固定测试夹具，不是模型，也不证明真实模型会找到错误。

```python
"""Offline reflection gate fixture. Synthetic data; no model/provider calls."""
import json

OBSERVATIONS = [
    {"city": "北京", "day": "明天", "temp_c": 31},
    {"city": "上海", "day": "明天", "temp_c": 27},
    {"city": "广州", "day": "明天", "temp_c": 34},
]
TASK = "报告最高、最低城市与温差。"
REQUIRED = {
    "highest_city", "highest_temp_c", "lowest_city", "lowest_temp_c", "difference_c"
}


def expected_answer(observations):
    if not observations or any(not isinstance(row.get("temp_c"), int) for row in observations):
        raise ValueError("observations are incomplete")
    high = max(observations, key=lambda row: row["temp_c"])
    low = min(observations, key=lambda row: row["temp_c"])
    return {
        "highest_city": high["city"],
        "highest_temp_c": high["temp_c"],
        "lowest_city": low["city"],
        "lowest_temp_c": low["temp_c"],
        "difference_c": high["temp_c"] - low["temp_c"],
    }


def independent_validate(candidate, observations):
    if not isinstance(candidate, dict) or set(candidate) != REQUIRED:
        return ["answer schema mismatch"]
    expected = expected_answer(observations)
    return [key for key, value in expected.items() if candidate.get(key) != value]


def should_request_review(errors):
    # A deterministic discrepancy is a trigger; this policy is only a fixture.
    return bool(errors)


def build_review_input(task, candidate, observations, errors):
    # Pass relevant structured evidence, not the whole conversation/tool trace.
    return {
        "task": task,
        "candidate": candidate,
        "evidence": observations,
        "validation_errors": errors,
        "instruction": "Return JSON with decision, reason, revised_answer; do not invent missing evidence.",
    }


def parse_review(reply):
    """Provider adapter must map its API states into complete/truncated/refused."""
    if not isinstance(reply, dict) or reply.get("status") != "complete":
        return None
    text = reply.get("text")
    if not isinstance(text, str) or not text.strip():
        return None
    try:
        parsed = json.loads(text)
    except (ValueError, TypeError):
        return None
    if not isinstance(parsed, dict) or set(parsed) != {"decision", "reason", "revised_answer"}:
        return None
    if parsed["decision"] not in {"accept", "revise", "abstain"}:
        return None
    if not isinstance(parsed["reason"], str) or not parsed["reason"].strip():
        return None
    if parsed["decision"] == "revise" and not isinstance(parsed["revised_answer"], dict):
        return None
    if parsed["decision"] != "revise" and parsed["revised_answer"] is not None:
        return None
    return parsed


def resolve_review(original, reply, observations):
    review = parse_review(reply)
    if review is None or review["decision"] == "abstain":
        return None, False
    candidate = original if review["decision"] == "accept" else review["revised_answer"]
    errors = independent_validate(candidate, observations)
    return (candidate, True) if not errors else (None, False)


def main():
    wrong = {
        "highest_city": "北京", "highest_temp_c": 31,
        "lowest_city": "上海", "lowest_temp_c": 27, "difference_c": 4,
    }
    errors = independent_validate(wrong, OBSERVATIONS)
    assert should_request_review(errors)
    request = build_review_input(TASK, wrong, OBSERVATIONS, errors)
    assert set(request) == {"task", "candidate", "evidence", "validation_errors", "instruction"}

    # Fixed fixture reply, not a model completion.
    corrected = expected_answer(OBSERVATIONS)
    fake_reply = {
        "status": "complete",
        "text": json.dumps({
            "decision": "revise", "reason": "recompute from supplied observations",
            "revised_answer": corrected,
        }, ensure_ascii=False),
    }
    delivered, accepted = resolve_review(wrong, fake_reply, OBSERVATIONS)
    assert accepted and delivered == corrected
    print("initial_check=failed; review_triggered=True")
    print("revised_candidate=independently_checked; deliverable=%s" % accepted)

    for incomplete in (
        {"status": "truncated", "text": ""},
        {"status": "refused", "text": ""},
        {"status": "complete", "text": "not JSON"},
        {"status": "complete", "text": '{"decision":"revise"}'},
    ):
        candidate, can_deliver = resolve_review(wrong, incomplete, OBSERVATIONS)
        assert candidate is None and not can_deliver
    print("truncated/refused/malformed=held; providerCalls=0; externalNetworkCalls=0")


if __name__ == "__main__":
    main()
```

```text
initial_check=failed; review_triggered=True
revised_candidate=independently_checked; deliverable=True
truncated/refused/malformed=held; providerCalls=0; externalNetworkCalls=0
```

`independent_validate` 在本例里是独立于 FakeReviewer 的确定性计算，所以能判出城市和温差是否对应证据；在真实系统中，它的输入来源仍需可信、校验规则也要覆盖目标字段。对于开放式任务没有这样的 oracle 时，代码不该假装有精确答案；可以选择盲评、多个独立评审、抽样人工复核或上线后监控，但这些方法各自有偏差，需用目标任务验证。

## 把复核接入执行循环

不要默认每个模型回合后都再调用一次模型。先记录失败类型，再决定谁最适合处理：JSON 不合法由解析器拒绝；数字范围或字段关系由业务代码验证；缺少外部事实要重新查询可信来源；只有需要语义判断且任务风险允许自动处理时，才考虑模型复核。出现安全、权限或无法确认的副作用时，应走拒绝、暂停或人工路径，不能指望模型反思替代授权与恢复。

触发器要对应验收目标。确定性校验不通过可以触发修订，但“模型自称不确定”不是可靠的唯一门槛；它可能漏报不确定性。为可抽样审计的语义复核，应保留脱敏后的输入版本、rubric 版本、评审输出、独立 grader/人工结果和交付决定。把全部 trace 默认送入第二次 prompt 会扩大隐私暴露与 token 用量，且并不增加证据独立性。

若模型修改候选答案，不能只检查它是否复述了错误信息；必须用相同或更强的验收标准重新检查修订稿。若失败仍然存在，应限制重试次数和总预算，记录停止原因，并将未通过结果保持为未完成。重试上限按时延、成本、失败恢复和副作用风险设定，没有适用于所有任务的固定轮数。

## 成本要从实际请求计算

加一次模型复核至少会增加一次调用，但 token、费用和时延不是一个固定倍数。输入可能包含任务、候选答案、证据或历史；输出长短由模型和任务决定；缓存计量和不同 API 的 usage 字段也会影响账单。比较方案时要记录每次请求的模型快照、终止状态、输入/输出及缓存 usage、延迟、grader 结果和完整 trace，再按相同任务与验收标准计算。没有这些数据时，只能说“会多一次模型调用”，不能引用本节旧摘要推导 +113%、两倍或更长任务的成本曲线。

## 与 Self-Consistency 和 Reflexion 的边界

self-consistency 是从多个样本聚合答案；Reflection 常指基于已有结果与反馈再评估或修订；Reflexion 原论文则将文字化反馈带入后续尝试。它们的输出关系与评测目标不同。多个样本之间可能共享相同系统性错误；一个复核器也可能将错误答案包装得更有说服力。因此，“意见一致”不能代替证据核验，“修改成功”必须由任务级 grader 或人来判。

第 2 章记录的 self-eval 8/8 和温度/投票结果同样属于原始响应未归档的历史摘要。算术题能独立重算是一个可测试的设计方向，不是此前摘要已经证明 Reflection 有效的证据。要比较它与规则校验、重新检索或多样化候选，必须在同一数据集、同一 grader 下评测准确性、拒答、改坏率、成本和延迟。

## 本节小结

1. Reflection、基于反馈的修订、Reflexion 与 self-consistency 是不同操作，先说清楚要测哪一种。
2. 新证据可能帮助复核，但不能自动建立证据独立性；对可机械判定的要求使用独立程序校验。
3. 模型修订不是交付结果。响应需完整、结构符合约定，候选修改后还要通过验收。
4. 复核输入限于任务相关且经过授权的数据；不要默认转发完整对话、秘密或原始工具错误。
5. 记录实际 usage 和端到端结果。历史 1,203、2,568、2/7 与 3/3 摘要不能证明质量或普遍成本。

## 常见坑

- **把“再看一遍”当作独立验证。** 使用不同证据、算法或人能降低部分同源风险，但只有经过校准的任务级检查才能支持结论。
- **把证据加进 prompt 就认为足够。** 模型仍可能误读、证据可能过期或恶意；检查来源、版本、字段映射和规则覆盖范围。
- **把评审输出直接覆盖原答案。** 将其视为候选值；重新校验，不完整、拒绝或模糊响应要暂停交付。
- **把所有工具结果原文拼进评审提示。** 先做最小化、脱敏和可信边界处理，限制保留与访问。
- **按历史摘要声称 Reflection 成本翻倍。** 原始 usage 缺失，不能复算；只可确认每次实际调用都应纳入端到端用量统计。

[Reflexion 原论文](https://arxiv.org/abs/2303.11366)展示的是由环境反馈驱动、可供后续尝试利用的语言化反思，而不是保证模型自评正确的通用接口。[Anthropic 的 Agent 评测文章](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)强调针对完整任务轨迹和成功条件设计评测；它支持“检查端到端行为”的方法建议，不证明某种 Reflection 实现普遍更有效。
