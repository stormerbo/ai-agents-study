第 2 节说「按爆炸半径选层级」。这一节讲在那层隔离里，**权限具体怎么收到最小**。

核心只有一句话：**默认拒绝，按需放开，而且放开的那部分要能被验证。**

## 一个「看着对」的检查

最小权限最常见的实现形态是「限制在一个目录里」。而它最常见的写法是这样的：

```python
def naive_read(rel):
    full = os.path.join(SANDBOX, rel)
    if not full.startswith(SANDBOX):     # ← 看着很对
        return "拒绝"
    return open(full).read()
```

这段代码的意图完全正确，而且它确实是很多生产代码的样子。问题在 startswith 检查的是**字符串**，而不是**文件实际在哪**。

我用 6 种手法测了它：

| 攻击手法 | 朴素前缀检查 | 真实路径检查 |
|---|---|---|
| 正常读取（应该允许） | ✅ 读到 | ✅ 读到 |
| 用 .. 往回跳一级 | ❌ **读到了密钥** | ✅ 拒绝 |
| 往回跳两级 | ❌ **读到了密钥** | ✅ 拒绝 |
| 符号链接（沙箱内的 link 指向外部） | ❌ **读到了密钥** | ✅ 拒绝 |
| 绝对路径 | ✅ 拒绝 | ✅ 拒绝 |
| 带多余斜杠的越界（./.././） | ❌ **读到了密钥** | ✅ 拒绝 |

（实跑数据，2026-10-09。沙箱外放了一个含密钥的文件作为目标。）

**6 种手法里，朴素版放过了 4 种。** 而且放过的那些恰好都成功了 —— 一次成功的注入就能读到沙箱外的任意文件。

## 为什么会绕过

看第一行攻击的路径拼接结果：


```text
SANDBOX/../secret.env
```

这个字符串**确实以 SANDBOX 开头** —— 所以前缀检查通过了。但操作系统在打开它的时候会先解析 `..`，最终打开的是沙箱**外面**的那个文件。

**字符串检查和文件系统解析是两套规则。** 前缀检查在字符串空间里做判断，而文件系统在路径空间里做解析。两者不一致的地方就是漏洞所在。

符号链接是同一个问题的另一种形态：沙箱内的 link.txt 这个名字完全合法，但它**指向**外面。

## 修好的版本

两处关键改动：

```python
def safe_read(rel):
    base = os.path.realpath(SANDBOX)
    full = os.path.realpath(os.path.join(SANDBOX, rel))      # 改动一：解析掉 .. 和符号链接
    if full != base and not full.startswith(base + os.sep):  # 改动二：结尾加分隔符
        return "拒绝"
    if not os.path.isfile(full):                             # 改动三：只允许普通文件
        return "拒绝"
    return open(full).read()
```

**改动一（realpath）** 把 `..` 和符号链接都解析成真实路径，于是字符串检查和文件系统解析终于看的是同一个东西。

**改动二（结尾分隔符）** 防的是另一个漏：如果只用 `startswith(base)`，那么 `/tmp/sandbox-evil` 会被判断为「在 `/tmp/sandbox` 内」—— 因为它的字符串前缀确实匹配。加一个结尾的分隔符就把这种情况排除了。

**改动三（只允许普通文件）** 防的是「读目录」和「读设备文件」。后者会挂住 —— 比如读 `/dev/zero` 会一直读下去。

改完之后，**6 种手法全部被拒**（除了正常的那个）。

## 网络的最小权限

文件系统的坑在于「路径可以绕过检查」。网络的坑在于**默认是通的**。

一个「发 HTTP 请求」的工具如果不做限制，模型可以访问：

- **内网地址**（10.x、192.168.x、172.16-31.x）→ 探测内网服务
- **云元数据端点**（169.254.169.254）→ 这是最经典的一个：很多云上它能直接换到临时凭据
- **localhost** → 访问你这台机器上的其他服务（包括管理接口）
- **任意公网地址** → 数据外泄的出口

第 8 章实测过一个相关现象：给模型一个 URL 图像，**服务端会去下载它** —— 地址来自用户就意味着一个 SSRF 面（**SSRF**，服务端请求伪造：攻击者让你**服务端**去访问一个他自己够不着的地址，比如内网服务或云元数据端点，你的服务器成了他的跳板）。

网络最小权限的做法同样是「默认拒绝 + 白名单」：

```text
默认：禁止一切出站
放开：api.example.com、docs.example.com（写在配置里，可 review）
并且：禁内网网段、禁云元数据端点、禁 localhost —— 即使它出现在白名单里也要二次拒绝
```

最后那条「二次拒绝」是有意的：**白名单可能被改错，而这三类地址一旦可达，后果比其他地址严重得多。** 多一道检查的成本很低。

## 三条能带走的规则

**一，检查「解析后的东西」，不要检查「原始字符串」。** 文件要 realpath，URL 要解析出 host 再判断，SQL 要参数化。**共同的根因是：你检查的表示形式和实际使用的表示形式不一致。**

**二，比较路径时带结尾分隔符。** 用 startsWith 比较路径在多数场景下都是错的，除非第二个参数以分隔符结尾。

**三，默认拒绝，白名单放开。** 黑名单版本（「禁止这些路径」）一定会漏 —— 第 2 节那个 L1 层就是黑名单思路的示范。三条规则里，第一条是最根本的：**检查的表示形式和使用的表示形式必须是同一个**，否则中间那段差异就是攻击面。


## 四类必须单独处理的路径

上面那 6 种是最常见的手法，但实际要防的不止这些。有四类值得单独列出来，因为它们的绕过方式各不相同：

**一、符号链接。** 沙箱内的一个合法文件名，指向外部。防范方式是 realpath（解析后再判断），而不是检查名字。

**二、硬链接。** 同一个 inode 的另一个名字。它还多一个副作用：**写入会同时改到原文件**，所以「只读挂载」之外还要保证「不可写」。做法不是逐条禁路径，而是让越界写入在结构上不可能：把可写工作目录挂成**独立的文件系统**（如 tmpfs）—— 硬链接不能跨文件系统，于是沙箱内造不出指向宿主文件的硬链接；宿主侧再确认 `fs.protected_hardlinks=1`（默认值，防未授权硬链接）。

**三、大小写与 Unicode 归一化。** 有些文件系统大小写不敏感（macOS 默认），有些会把不同的 Unicode 表示归一化成同一个名字。如果你的白名单比较是字节级的，就会漏。

**四、特殊文件。** `/dev/zero`（无限读）、`/dev/random`（阻塞）、命名管道（FIFO，会挂住直到对端写入）。**防法是「只允许普通文件」**，而不是去枚举哪些特殊文件危险。

四类里，第一类和第四类最常见。而它们的防法都是**一句话的规则**（realpath、isfile），不是一长串黑名单 —— 这是最小的成本、最大的收益。
## 完整可运行代码

下面这段代码跑的就是上面那张对照表：两个版本的实现，6 种攻击手法。

```python
"""把一个「看着对」的沙箱检查攻破，再给出修好的版本。

这是第 16 章最核心的一次演示：**权限检查的直觉几乎总是错的。**
纯本地，不依赖任何外部服务。实跑状态：2026-10-09。
"""
import os, shutil, tempfile

ROOT = os.path.join(tempfile.gettempdir(), "sandbox-demo")
if os.path.exists(ROOT):
    shutil.rmtree(ROOT)
SANDBOX = os.path.join(ROOT, "sandbox")
os.makedirs(os.path.join(SANDBOX, "sub"))

# 沙箱外的「机密」：一个正常系统里到处都有的东西
with open(os.path.join(ROOT, "secret.env"), "w") as f:
    f.write("API_KEY=sk-live-9f3a...（这就是不该被读到的东西）\n")
with open(os.path.join(SANDBOX, "ok.txt"), "w") as f:
    f.write("这是沙箱内允许读的文件\n")

# 在沙箱内造一个指向外部的符号链接 —— 看起来完全无害
os.symlink(os.path.join(ROOT, "secret.env"), os.path.join(SANDBOX, "sub", "link.txt"))


def naive_read(rel):
    """第一版：把根目录拼上去，然后检查前缀。看着很对。"""
    full = os.path.join(SANDBOX, rel)
    if not full.startswith(SANDBOX):
        return "❌ 拒绝（前缀检查）"
    try:
        with open(full) as f:
            return "✅ 读到：" + f.read().strip()[:32]
    except Exception as e:
        return "读取失败：" + type(e).__name__


def safe_read(rel):
    """第二版：先规范化成真实路径，再检查它是否真在沙箱内。"""
    base = os.path.realpath(SANDBOX)
    full = os.path.realpath(os.path.join(SANDBOX, rel))
    # 注意结尾的分隔符：否则 /sandbox-evil 会被当成在 /sandbox 内
    if full != base and not full.startswith(base + os.sep):
        return "❌ 拒绝（真实路径越界）"
    if not os.path.isfile(full):
        return "❌ 拒绝（不是普通文件）"
    try:
        with open(full) as f:
            return "✅ 读到：" + f.read().strip()[:32]
    except Exception as e:
        return "读取失败：" + type(e).__name__


ATTACKS = [
    ("正常读取（应该在沙箱内）", "ok.txt"),
    ("用 .. 往回跳一级", "../secret.env"),
    ("往回跳两级", "sub/../../secret.env"),
    ("符号链接（沙箱内的 link 指向外部）", "sub/link.txt"),
    ("绝对路径", "/etc/hosts"),
    ("带多余斜杠的越界", "./.././secret.env"),
]

if __name__ == "__main__":
    print("沙箱目录：%s" % SANDBOX)
    print("沙箱外有一个 secret.env —— 它就是不能读到的东西")
    print()
    print("  %-34s %-30s %s" % ("攻击手法", "朴素前缀检查", "真实路径检查"))
    leak = 0
    for label, rel in ATTACKS:
        n = naive_read(rel)
        s = safe_read(rel)
        if n.startswith("✅") and "secret" in n + rel:
            pass
        print("  %-34s %-30s %s" % (label, n[:28], s[:30]))
    print()

    print("=== 关键点 ===")
    print("  朴素版把 '%s/../secret.env' 拼出来，它的前缀**确实是**沙箱路径 ——" % SANDBOX.split('/')[-1])
    print("  所以 startswith 检查通过了。前缀检查的问题在于：它检查的是**字符串**，")
    print("  而不是**文件实际在哪**。")
    print()
    print("  修好的版本有两处关键改动：")
    print("    1. realpath —— 把 .. 和符号链接都解析掉，得到真实路径")
    print("    2. 结尾加分隔符 —— 否则 /sandbox-evil 会被误判为在 /sandbox 内")
    print()
    print("  还有第三条不在路径里但同样重要：**只允许普通文件**。")
    print("  如果 path 指向一个目录或设备文件（比如 /dev/zero），读它会挂住。")
```


## 一个更省事的替代：能力列表

前面讲的都是「拒绝式」的做法 —— 列出允许的范围，其余拒绝。还有一个思路相反的：**不传路径，传句柄。**

具体说，工具不接收「路径」参数，而是接收一个**已经打开的文件对象**或一个不透明的能力 id。模型能操作的范围就物理上限于你已经打开的那些 —— 它没有「传一个别的路径」这个选项。

这个思路在操作系统里叫**能力（capability）模型**，它的好处是**越界在结构上不可能**，而不是「被检查拦住了」。第 4 章讲 poka-yoke（防呆设计：把操作设计成「错了也做不成」，而不是「错了被抓住」）时说过同一件事：让错误在结构上不可能，比让它被检测到更可靠。

代价是灵活性下降：你需要在调用工具之前就知道它要访问什么。对「读一个用户指定的文件」这类任务不适用，但对「处理这一批已选定的文件」非常合适。
## 网络最小权限的实现：从 URL 到 IP 的完整判据

上面那 4 行伪代码缺的是**判据**：host 怎么取、IP 怎么解析、三类二次拒绝怎么判。下面这段补上，纯本地可跑（DNS 结果用 `DEMO_DNS` 固定住以便复现；真实实现删掉那张表，走 `socket.getaddrinfo`）。实跑数据 2026-10-12。

```python
"""网络最小权限：解析 host -> 判白名单 -> 二次拒绝三类危险地址。

真实实现用 socket.getaddrinfo 解析；本地演示把 DNS 结果固定住（DEMO_DNS），
这样离线可复现。把 DEMO_DNS 设为 {} 就退化成真实 DNS 解析。
"""
import ipaddress, socket
from urllib.parse import urlparse

ALLOW_HOSTS = {"api.example.com", "docs.example.com", "rebind.example.com"}
DEMO_DNS = {                       # 离线演示用；真实环境删掉这张表
    "api.example.com": ["93.184.216.34"],
    "docs.example.com": ["93.184.216.34"],
    "rebind.example.com": ["10.0.0.5"],       # 白名单域名解析到内网 -> 必须二次拒绝
    "api.example.com.evil.com": ["93.184.216.34"],
}

def _literal_ipv4(host):
    """把 2130706433 / 0x7f000001 / 017700000001 这类整数写法还原成点分 IPv4。"""
    try:
        if host.lower().startswith("0x"):
            return str(ipaddress.IPv4Address(int(host, 16)))
        if host.isdigit():
            base = 8 if (len(host) > 1 and host.startswith("0")) else 10
            return str(ipaddress.IPv4Address(int(host, base)))
    except (ValueError, ipaddress.AddressValueError):
        return None
    return None

def resolve(host):
    host = host.strip("[]")
    if host in DEMO_DNS:
        return list(DEMO_DNS[host])
    lit = _literal_ipv4(host) or host
    try:
        return [str(ipaddress.ip_address(lit))]
    except ValueError:
        pass
    try:
        return sorted({i[4][0] for i in socket.getaddrinfo(host, None)})
    except socket.gaierror:
        return []

def dangerous(ip):
    a = ipaddress.ip_address(ip)
    if a.is_loopback: return "localhost"
    if a.is_link_local: return "云元数据/链路本地（169.254.0.0/16）"
    if a.is_private: return "内网网段"
    if a.is_reserved or a.is_multicast or a.is_unspecified: return "保留/组播地址"
    return None

def check_url(url):
    p = urlparse(url)
    if p.scheme != "https":
        return "拒绝", "非 https"
    host = (p.hostname or "").lower()
    if not host:
        return "拒绝", "没有 host"
    ips = resolve(host)
    if not ips:
        return "拒绝", "无法解析"
    for ip in ips:                       # 先做二次拒绝，再判白名单：
        d = dangerous(ip)                # 危险地址即使来自白名单域名也不放行
        if d:
            return "拒绝", "二次拒绝：%s（解析到 %s）" % (d, ip)
    if host not in ALLOW_HOSTS:
        return "拒绝", "不在白名单（host=%s）" % host
    return "允许", "白名单命中（%s -> %s）" % (host, ",".join(ips))

CASES = [
    "https://api.example.com/orders",
    "https://API.EXAMPLE.COM/orders",
    "https://docs.example.com/x",
    "https://evil.com/x",
    "https://api.example.com.evil.com/x",
    "https://rebind.example.com/x",
    "https://169.254.169.254/latest/meta-data/",
    "https://api.example.com@169.254.169.254/",
    "https://10.0.0.1/",
    "https://192.168.1.1/",
    "https://172.16.0.1/",
    "https://2130706433/",
    "https://0x7f000001/",
    "https://[::1]/",
    "http://api.example.com/x",
]

if __name__ == "__main__":
    for url in CASES:
        dec, why = check_url(url)
        print("  %-46s %-4s %s" % (url, dec, why))
```

实跑输出：

```text
  https://API.EXAMPLE.COM/orders                 允许   白名单命中（api.example.com -> 93.184.216.34）
  https://docs.example.com/x                     允许   白名单命中（docs.example.com -> 93.184.216.34）
  https://evil.com/x                             拒绝   不在白名单（host=evil.com）

  https://0x7f000001/                            拒绝   二次拒绝：localhost（解析到 127.0.0.1）
  https://[::1]/                                 拒绝   二次拒绝：localhost（解析到 ::1）
  http://api.example.com/x                       拒绝   非 https
```

三个绕过点在这段代码里为什么被挡住：

- `api.example.com@169.254.169.254`：`urlparse` 会把 userinfo 和 host 分开，`p.hostname` 取到的是 `169.254.169.254`，不是 `api.example.com` —— **永远用解析出来的 host，不要用字符串里看起来像域名的那一段。**
- `2130706433` / `0x7f000001`：点分十进制不是 IP 的唯一写法，`ipaddress` 直接解析会失败，所以先做一次整数还原。**这类绕过是「检查的表示形式和使用的表示形式不一致」的又一次出现**（本节前面那条规则的网络版）。
- `rebind.example.com`：域名在白名单里，但**解析结果**落在内网 —— 所以判据必须是「解析后的 IP」，而且要在**每次请求时**解析，不能只在配置加载时解析一次。真正的 DNS 重绑定会在两次解析之间换 IP，所以还要把「已解析并校验过的 IP」固化到连接层（例如 pin 住 IP、Host 头另设），而不是「校验完再按域名连一次」—— 中间那一次重新解析就是缺口。

### 网络版与文件版并列

| | 文件系统版 | 网络版 |
|---|---|---|
| 检查的原始值 | `path` 字符串 | `url` 字符串 |
| 必须解析成 | `realpath(path)` | `urlparse(url).hostname` 再解析成 IP |
| 白名单比较 | 真实路径前缀（带分隔符） | host 精确匹配 |
| 二次拒绝 | 不是普通文件 / 越界 | 内网 / 云元数据 / localhost |
| 已知绕过 | `..`、符号链接、前缀相似目录 | userinfo、整数 IP、DNS 重绑定 |
| 共同根因 | **检查的表示形式 ≠ 使用的表示形式** | 同左 |

## 能力式接口长什么样

L239 说「工具不接收路径，而是接收一个已经打开的文件对象」，具体签名是这种形态：

```python
# ❌ 拒绝式：模型传路径，校验在工具内部（校验写错就漏）
def read_file(path: str) -> str: ...

# ✅ 能力式：调用方（你的代码）先打开文件，工具只拿到句柄
import typing
def read_file(handle: typing.IO[bytes], max_bytes: int = 1_000_000) -> str:
    return handle.read(max_bytes).decode("utf-8", "replace")

# 调用侧：路径由你的代码决定，模型改不了
with open(resolve_task_file("notes.md"), "rb") as fh:
    read_file(fh)
```

区别在**谁能改变访问目标**：拒绝式里路径来自模型参数，校验是「后加的」；能力式里路径来自你的代码，模型手上没有「换一个路径」这个选项 —— 越界在结构上不可能。代价是灵活性：需要「读一个用户指定的文件」时用不了，需要「处理这一批已选定的文件」时正合适。

## 常见坑

- **用 startswith 检查路径。** 实测 6 种手法放过 4 种，而且是静默放过。
- **忘了路径比较要带结尾分隔符。** /tmp/sandbox-evil 会被误判为在 /tmp/sandbox 内。
- **只检查路径，不检查文件类型。** 读一个目录或设备文件会挂住（/dev/zero 会一直读）。
- **网络默认放开。** 一个「发 HTTP 请求」的工具默认能访问内网、云元数据端点和 localhost。
- **以为白名单就够了。** 白名单可能被改错，内网/元数据/localhost 这三类要二次拒绝。
- **只在代码里写「已做限制」，没有攻击测试。** 隔离的验证方式是攻击测试，不是配置检查。
