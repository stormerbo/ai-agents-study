拿到一份 PDF 时，常见做法有三种：按目标 API 的 `document` 格式提交 PDF、把 PDF 页面渲染成图像，或者先抽取文本再处理。**这三种表示的支持情况由具体 provider、模型和 API endpoint 决定**；“Anthropic 兼容”也不自动意味着支持 Anthropic 的所有 content block。

## 一组无法独立复核的历史对比

正文保留了 2026-10-08 的三路历史摘要，称输入是手写发票 PDF、问题相同，记录了如下 token 和回答。但逐次请求、原始响应、准确 endpoint 与模型后端指纹、完整 usage 及评分器没有归档，无法独立复核这些数字或确认三路输入处理完全等价。它们只代表当时记下的观察，不足以证明某 provider 静默丢弃了 PDF，也不能推出文本/图像路线的一般准确率或成本。

| 路线 | 历史摘要记录的 input tokens | 当时的判分记录 | 历史摘要的回答片段 |
|---|---:|---|---|
| A 直接发 PDF（document 块） | **59** | ❌ | 「无法确定（文档不受支持，未提供可读取的表格内容）」 |
| B 渲染成 PNG 发（image 块） | 337 | ✅ | 逐行读出了 A/B/C 的数量、单价与金额 |
| C 自己抽文本发（text 块） | 123 | ✅ | 「37.50,119.50」 |

（未独立复核的历史摘要，2026-10-08，模型别名 `deepseek-flash`；不能唯一确定模型快照。）

下面的 JSON 展示 Anthropic Messages API 的示意形态。其他 provider 可能不支持 `document` block、PDF URL 或同一 MIME 组合；上线前查目标 endpoint 的文档，并对请求错误、`stop_reason`、非文本/空响应和 usage 做显式处理。[Anthropic PDF 支持文档](https://platform.claude.com/docs/en/build-with-claude/pdf-support) 展示了该 API 支持 base64、URL 与 Files API 的 PDF 输入（查阅日期：2026-10-22）。

路线 A，`document` 块（把 PDF 本身交给模型）：

```json
{
  "type": "document",
  "source": {
    "type": "base64",
    "media_type": "application/pdf",
    "data": "<PDF 的 base64>"
  }
}
```

它也可以直接给 URL（是否支持取决于厂商与端点）：

```json
{
  "type": "document",
  "source": {
    "type": "url",
    "url": "https://example.com/invoice.pdf"
  }
}
```

路线 B，`image` 块（你先把 PDF 渲染成 PNG，再按第 1 节的方式发）：

```json
{ "type": "image",
  "source": { "type": "base64", "media_type": "image/png", "data": "<PNG 的 base64>" } }
```

路线 C，`text` 块（你自己抽出来的字符串）：

```json
{ "type": "text", "text": "Invoice INV-2026-1008\nItem  Qty  Amount\n..." }
```

`media_type` 是内容的 MIME 类型（Multipurpose Internet Mail Extensions），用于描述 `data` 的格式：PDF 通常标为 `application/pdf`，PNG 通常标为 `image/png`。格式或内容块不符合 endpoint 契约时，应检查 API 错误与响应；不能假设服务端会自动转换，也不能在没有证据时断言它静默丢弃。

> **边界声明**：官方资料说明 Anthropic Messages API 支持文档/PDF 输入；这不能证明其他 Anthropic 兼容 endpoint 支持同样的内容块，也不能反推历史别名 `deepseek-flash` 的行为。针对实际 endpoint，应核对其文档并分别记录请求错误、终止原因、输出内容与 usage。

## 不要从 token 数反推 PDF 被丢弃

历史摘要写的是 59 个输入 token，回答文本提到“文档不受支持”。由于原始请求和完整响应没有留存，**不能从 59 这个数字推出 PDF 字节未被解析或被丢弃**。PDF 的 token 用量可能包含抽取文本、页面图像或供应商特有计数；不能按文件字节大小推算 token，也不能拿一条摘要与问题本身的估算量直接相减得出服务端行为。

能给出的窄结论是：这份历史摘要记录了一次 PDF 路线回答“不受支持”；若应用收到相同响应，应将结果标记为未完成或 unsupported，并使用明确支持的备用路径。HTTP 成功仅代表请求被处理到某个 HTTP 响应状态，不能证明文档内容被完整理解。模型说“读不出”也不应作为唯一质量门禁：应用需检查终态、必要字段、来源引用与业务约束，无法验证时返回待处理状态。

## 文本路线要验证抽取产物

旧记录称 `pdfplumber` 从生成的 PDF 抽出了 159 个字符：

```text
pdfplumber 从同一份 PDF 抽出 159 字符，含 37.50: True
```

（历史本地摘要，2026-10-08；旧 API harness 的 C 路线直接从 `ROWS` 常量构造文本请求，而非把 `pdfplumber` 的提取结果发送给模型，所以这不是完整端到端的“抽取后总结”对比。）

文本抽取通常比发送整页图像更容易检查、记录和测试；但抽取器输出的顺序与表格结构取决于 PDF 编码、布局和工具配置。历史表里的 123 与 337 token 不可当作稳定价格比：样本只有一份，逐次 usage 缺失，而且旧脚本的图像路线由 `ROWS` 直接用 Pillow 绘制，并非从 PDF 渲染，文本路线也直接发送 `ROWS` 常量。两种变换不是从同一个 PDF 端到端得到的。

但它有一个前提，而且这个前提经常不成立：**PDF 里得有文本层。** 扫描件、截图导出的 PDF、以及很多「打印成 PDF」的报表，里面只有整页的图片，没有可抽取的文字。这种情况下 pdfplumber 会抽出空字符串，而路线 C 直接失效。

因此决策要看**下游字段与可验证性**，而不能只看抽取到多少字符：

| PDF 类型 | 判断方法 | 该走哪条路 |
|---|---|---|
| 文本层 PDF | 提取出目标字段，并通过应用定义的结构与业务校验 | **C**（便于程序检查；成本需实测） |
| 扫描 / 图片 PDF | 无文本层或抽取缺少必需字段 | OCR 或 **B**（渲染成图，依目标 API 支持） |
| 版面即信息（表格、表单） | 行列关系不满足 schema/算术或业务约束 | **B**，或使用保留坐标的解析并复核 |

不要把第三行简化为“抽取文本必然丢位置”：许多工具保留词坐标或能返回表格结构，但列重建仍会受跨列、合并单元格、重复表头、阅读顺序、旋转页面和字体编码影响。应检查产物是否符合该业务的 schema，并用独立约束（例如行金额之和是否等于总额）判定是否可自动采纳。

## 路线 B 的代价与收益

图像路线保留页面的视觉版面，但其 token、延迟和总成本需在目标 endpoint 与代表性文档上测量；本节的单份历史摘要不足以比较成本。

「渲染成 PNG」具体用什么？最小路径是 `pypdfium2`（BSD 许可、pip 可装、不依赖外部 poppler）：

```python
import io
import pypdfium2 as pdfium

def render_pdf(pdf_bytes, page_index=0, scale=2):
    pdf = pdfium.PdfDocument(pdf_bytes)
    page = pdf[page_index]
    # scale=2 表示 2 倍分辨率（约 144 dpi）；scale 不是越大越好，见下
    return page.render(scale=scale).to_pil()
```

多页文档可按页循环；`scale` 表示渲染分辨率取舍，像素增多可能提高细节，也会增大请求体。服务端是否缩放及图像 token 用量取决于目标 provider/model，须查对应文档并实测。PNG 字节数与模型 token 用量不是同一个指标，不能从文件字节大小推断 token 成本。

表格对齐、跨行单元格、印章、手写批注与复选框状态可能不在文本层中，图像路由则可能保留可视布局；这不代表视觉提取必然更准确。模型可能漏读、误读或幻觉，结构化字段必须另做 schema 和业务校验。第 4 节的实验也要按其样本和判分范围理解。

另一个实际差别是**可验证性**。路线 C 的结果可以和源文件逐字符 diff；路线 B 的结果只能和「你以为图里写了什么」比 —— 而那个「以为」本身可能来自同一张图。所以走视觉路线时，交叉校验不是可选项（第 5 节展开）。

## 用业务约束验证提取结果

不建议只凭“每页多少字符”或一组通用坐标阈值自动选择路线。文本存在不代表字段齐全，坐标聚类成功也不代表行列解析正确；阈值须用你的文档族校准。更实用的门禁是：抽取必需字段后，检查类型、必填项、标识符和业务不变量。校验失败时转 OCR/图像处理或人工复核，并保留失败原因。

下面是发票例子的纯 Python 校验器。它只校验已解析出的行与金额，不负责 PDF 抽取，也不证明供应商输出忠实；PDF parser 或模型输出都应先被视为不可信输入。

```python
from decimal import Decimal, DecimalException, InvalidOperation


def validate_invoice_rows(rows: list[dict], reported_total: str) -> tuple[bool, str]:
    """检查必需字段、有限非负金额和合计；返回可审计的失败原因。"""
    required = {"item", "quantity", "unit_price", "amount"}
    if not isinstance(rows, list):
        return False, "rows_type"
    if not rows:
        return False, "no_rows"
    amounts = []
    for index, row in enumerate(rows):
        if not isinstance(row, dict) or set(row) != required:
            return False, f"row_{index}_schema"
        if not isinstance(row["item"], str) or not row["item"].strip():
            return False, f"row_{index}_item"
        raw_numbers = (row["quantity"], row["unit_price"], row["amount"])
        if not all(isinstance(value, str) for value in raw_numbers):
            return False, f"row_{index}_number"
        try:
            quantity, unit_price, amount = (Decimal(value) for value in raw_numbers)
        except (InvalidOperation, ValueError):
            return False, f"row_{index}_number"
        if not all(value.is_finite() for value in (quantity, unit_price, amount)):
            return False, f"row_{index}_number"
        try:
            if quantity < 0 or unit_price < 0 or amount < 0:
                return False, f"row_{index}_negative"
            product = quantity * unit_price
        except DecimalException:
            return False, f"row_{index}_number"
        if not product.is_finite():
            return False, f"row_{index}_number"
        if product != amount:
            return False, f"row_{index}_arithmetic"
        amounts.append(amount)
    if not isinstance(reported_total, str):
        return False, "total_number"
    try:
        total = Decimal(reported_total)
    except (InvalidOperation, ValueError):
        return False, "total_number"
    if not total.is_finite():
        return False, "total_number"
    try:
        matches = sum(amounts, Decimal("0")) == total
    except DecimalException:
        return False, "total_number"
    return matches, "ok" if matches else "total_mismatch"


assert validate_invoice_rows(
    [
        {"item": "Widget A", "quantity": "12", "unit_price": "3.50", "amount": "42.00"},
        {"item": "Widget B", "quantity": "5", "unit_price": "8.00", "amount": "40.00"},
        {"item": "Widget C", "quantity": "3", "unit_price": "12.50", "amount": "37.50"},
    ],
    "119.50",
) == (True, "ok")
```

当前样例假设每行金额等于数量乘单价，且总额等于行金额之和；真实发票可能包含税费、折扣、舍入规则或其他费用，必须按业务规则调整不变量与精度策略。金额守恒只能发现部分错误：例如模型把一个商品金额同时改成 35.00、并相应伪造总额时，算术仍可能自洽。生产核验还要与可信业务系统、原始订单/账本或人工审批交叉校验，并记录来源页码与原始片段。

## 多页文档的用量要按页实测

不能把一页的历史 token 数乘以页数当作稳定成本：页面文本密度、图像尺寸、视觉内容、渲染 scale、重复表头、prompt、缓存和 provider 的 PDF 预处理都会改变用量。可记录每个请求的 provider/model、文档版本、页数、每种路由、完整 usage 字段、终态、延迟与判分结果，再对目标文档族统计分布。

对大文档，先定位相关页再处理可以减少不必要输入，但页检索本身会有漏召回风险。上线应评估“检索页召回 + 下游字段准确率”的联合结果，并为重要字段提供页码/片段证据；不能只看节省的 token 或检索分数。这与第 6 章的检索评测相连。
## 完整可运行代码

下面的脚本从同一份 PDF 生成三种输入：PDF document block、由该 PDF 实际渲染得到的 PNG、以及 `pdfplumber` 从同一 PDF 提取的文本。它调用一次每条路线并把逐次响应写入 JSONL；这只是目标 endpoint 的小型 smoke test，不是可靠性或成本评测。**实跑状态：本轮仅用 fake SDK 与 fake PDF 库做离线 harness 检查，没有调用 provider，也没有验证真实 PDF 库。** 用户运行会发送 3 次 API 请求并可能产生费用。

安装并锁定 `anthropic`、`pdfplumber`、`pypdfium2` 版本后，设置 `ANTHROPIC_API_KEY` 与 `VERIFY_MODEL`。如使用兼容 endpoint，需显式配置该 provider 支持的 base URL、认证和内容块；兼容 Messages API 不表示支持相同 PDF 能力。运行前请用合成文档并确认 endpoint 文档允许该输入方式。

```python
"""同一份 PDF 的三种表示；只做目标 endpoint 的单次 smoke test。"""

import anthropic
import base64
import json
import os
import pdfplumber
import pypdfium2 as pdfium
import re
from io import BytesIO
from pathlib import Path

client = anthropic.Anthropic()
MODEL = os.environ["VERIFY_MODEL"]
QUESTION = (
    '从发票中读取 Widget C 的 amount 和总额。'
    '只返回 JSON：{"amount":"...","total":"..."}。'
)
EXPECTED = {"amount": "37.50", "total": "119.50"}
ROWS = [
    "Invoice INV-2026-1008",
    "Item        Qty    Unit     Amount",
    "Widget A     12    3.50      42.00",
    "Widget B      5    8.00      40.00",
    "Widget C      3   12.50      37.50",
    "Total                       119.50",
]


def make_pdf(lines: list[str]) -> bytes:
    """Generate a tiny text-layer PDF fixture using only the standard library."""
    parts = ["BT", "/F1 12 Tf", "60 720 Td", "16 TL"]
    for line in lines:
        escaped = line.replace("\\", r"\\").replace("(", r"\(").replace(")", r"\)")
        parts.append(f"({escaped}) Tj T*")
    parts.append("ET")
    stream = "\n".join(parts).encode("latin-1")
    objects = [
        b"<< /Type /Catalog /Pages 2 0 R >>",
        b"<< /Type /Pages /Kids [3 0 R] /Count 1 >>",
        (
            b"<< /Type /Page /Parent 2 0 R /MediaBox [0 0 612 792] "
            b"/Resources << /Font << /F1 4 0 R >> >> /Contents 5 0 R >>"
        ),
        b"<< /Type /Font /Subtype /Type1 /BaseFont /Helvetica >>",
        (
            b"<< /Length "
            + str(len(stream)).encode()
            + b" >>\nstream\n"
            + stream
            + b"\nendstream"
        ),
    ]
    output = bytearray(b"%PDF-1.4\n")
    offsets = []
    for index, body in enumerate(objects, 1):
        offsets.append(len(output))
        output += f"{index} 0 obj\n".encode() + body + b"\nendobj\n"
    xref = len(output)
    output += b"xref\n0 " + str(len(objects) + 1).encode() + b"\n0000000000 65535 f \n"
    output += b"".join(f"{offset:010d} 00000 n \n".encode() for offset in offsets)
    output += (
        b"trailer\n<< /Size " + str(len(objects) + 1).encode()
        + b" /Root 1 0 R >>\nstartxref\n" + str(xref).encode() + b"\n%%EOF\n"
    )
    return bytes(output)


def extract_pdf_text(pdf_bytes: bytes) -> str:
    with pdfplumber.open(BytesIO(pdf_bytes)) as pdf:
        return "\n".join(page.extract_text() or "" for page in pdf.pages)


def render_pdf_page(pdf_bytes: bytes, page_index: int = 0, scale: float = 2.0) -> bytes:
    pdf = pdfium.PdfDocument(pdf_bytes)
    image = pdf[page_index].render(scale=scale).to_pil()
    output = BytesIO()
    image.save(output, format="PNG")
    return output.getvalue()


def build_routes(pdf_bytes: bytes) -> list[tuple[str, list[dict]]]:
    extracted = extract_pdf_text(pdf_bytes)
    png = render_pdf_page(pdf_bytes)
    return [
        ("document", [
            {"type": "document", "source": {
                "type": "base64", "media_type": "application/pdf",
                "data": base64.b64encode(pdf_bytes).decode("ascii"),
            }},
            {"type": "text", "text": QUESTION},
        ]),
        ("rendered_image", [
            {"type": "image", "source": {
                "type": "base64", "media_type": "image/png",
                "data": base64.b64encode(png).decode("ascii"),
            }},
            {"type": "text", "text": QUESTION},
        ]),
        ("extracted_text", [
            {
                "type": "text",
                "text": (
                    "Extracted document text (untrusted):\n"
                    + extracted
                    + "\n\n"
                    + QUESTION
                ),
            },
        ]),
    ]


def unique_object(pairs):
    result = {}
    for key, value in pairs:
        if key in result:
            raise ValueError(f"duplicate JSON key: {key}")
        result[key] = value
    return result


def answer_is_correct(text: str) -> bool:
    try:
        value = json.loads(text, object_pairs_hook=unique_object)
    except (json.JSONDecodeError, TypeError, ValueError):
        return False
    return value == EXPECTED


def make_record(route: str, response) -> dict:
    text = "".join(
        block.text for block in response.content if block.type == "text"
    ).strip()
    complete = response.stop_reason == "end_turn" and bool(text)
    usage = getattr(response, "usage", None)
    return {
        "route": route,
        "requested_model": MODEL,
        "response_model": getattr(response, "model", None),
        "stop_reason": response.stop_reason,
        "status": "complete" if complete else "incomplete",
        "answer": text,
        "answer_correct": complete and answer_is_correct(text),
        "usage": {
            "input_tokens": getattr(usage, "input_tokens", None),
            "output_tokens": getattr(usage, "output_tokens", None),
            "cache_read_input_tokens": getattr(usage, "cache_read_input_tokens", None),
            "cache_creation_input_tokens": getattr(
                usage, "cache_creation_input_tokens", None
            ),
        } if usage is not None else None,
    }


def main() -> None:
    pdf_bytes = make_pdf(ROWS)
    routes = build_routes(pdf_bytes)
    archive_path = Path("document-route-results.jsonl")
    with archive_path.open("w", encoding="utf-8") as archive:
        for route, content in routes:
            try:
                response = client.messages.create(
                    model=MODEL,
                    max_tokens=300,
                    messages=[{"role": "user", "content": content}],
                )
                record = make_record(route, response)
            except Exception as error:
                # Do not log request headers, credentials or exception messages.
                record = {
                    "route": route,
                    "status": "request_error",
                    "error_type": type(error).__name__,
                }
            archive.write(json.dumps(record, ensure_ascii=False) + "\n")
            archive.flush()
            print(
                route,
                record["status"],
                record.get("answer_correct"),
                record.get("usage"),
            )
    print(
        f"Per-route records saved to {archive_path}; "
        "inspect them before drawing conclusions."
    )


if __name__ == "__main__":
    main()
```

> **结果解释边界**：这段脚本对每条路线只调用一次，回答正确只说明这个合成样本在该次配置下命中。`usage` 缺字段会保留为 `null`，不能读成 0。完整评测需加入代表性 PDF、错误/模糊样本、重复运行、逐字段评分和独立复核，并记录 SDK/provider/model 与文档版本。

## 常见坑

- **把 HTTP 成功当成内容已读懂。** 成功状态只说明请求得到响应；仍需检查模型终态、必要字段、结构化校验、来源片段和业务约束。无法验证时应保留为待处理。
- **把模型说“读不出”当成唯一保护。** 应用要显式处理拒绝、截断、空文本和请求错误，并在字段缺失或校验失败时 fail closed。
- **以为 PDF 一定有文本层。** 扫描件可能需要 OCR 或页面图像处理；在处理前检查抽取产物是否覆盖目标字段。
- **抽到了文本就以为结构也对。** 阅读顺序和表格关系依 PDF 编码与抽取器而变；用字段 schema、算术约束、页码/片段证据及可信业务数据交叉校验。
- **把单个样本的 token 比例当成本模型。** 不能线性外推历史摘要的 token 数；按目标 provider/model、文档族和 route 实测完整 usage 与任务质量。
- **只凭字符数选择路线。** 路由应围绕下游字段、版面依赖、可验证性和失败处理设计；先用代表性样本评估，再决定是否组合文本、OCR、视觉或人工复核。
