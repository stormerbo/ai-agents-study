上一节已经撤回「160–2,000 px 分辨率不影响准确率」的通用结论：旧表是单次历史摘要、缺少逐次响应与重复实验，而且画布宽度和字号同时变化。本节也使用同一纪律：把旧数字当作待复核记录，不将它们解释成当前模型的错误率；重点放在错误分类、可检测边界和可验证的校验方法。

摘要称 60 行档一次得到 179/180、随后三次 180/180；120 行档报告 352/360、另一次 351/360。即使这些摘要数字准确，样本与重复次数也不足以估计生产错误率或分辨率效应。

## 为什么这比「读不出来」危险

把这一节和上一节放在一起看，风险轮廓就清楚了。

如果模型说「这张图我看不清」，你会立刻知道要换方案 —— 提高分辨率、切成几块、或者改走文本抽取。**错误是显式的，可以处理。**

旧摘要报告模型读出了 352/360 个单元格，列出的值都是合法数字；但无法复核每次完整响应、字段结构和评分实现。旧 grader 只做 JSON 片段解析与字段字符串比较，没有检查行数、额外字段或范围，因此不能断言输出通过了完整格式/类型/范围校验。

合法 JSON 与合法数字并不代表字段正确。范围规则和业务不变量可以发现部分错误，却不能保证发现所有错误；如果合计本身也来自同一次图像抽取，错误还可能相互抵消。视觉抽取应分别记录 schema 合法性、精确字段匹配和独立业务核验，再用另一个可信信源或人工复核处理高风险字段。

## 为什么偏偏是纯数字

如果业务值是数字，语法正确仍可能掩盖语义错误。`ITM-122` 有固定前缀和序号格式，但没有校验位；一位序号读错后仍可能长得合法。字母和数字都可能出现视觉混淆，具体混淆取决于字体、尺寸、压缩和模型；需要从实际样本分类，不应根据这份未复核的八个样例归纳普遍原因。关键数值一旦进入计算链，错误可能传播，因此校验应放在下游使用之前。

给关键字段加校验信息可以提高某些错误的可检测性，但它不会让视觉识别本身更准确。固定宽度、分隔符和校验位各自只能检查特定约束；评估前要明确要防哪类错误，避免把格式检查说成正确性保证。

**做法**：如果业务可以控制票据内容，可以附加校验位来发现一部分转录错误；它不是真实性证明，也不能保证视觉模型读对。算法与边界测试集中放在下方的完整脚本中，避免维护两份实现。

Luhn 是校验和，不是加密或真实性证明。对这个实现，单个数字字符被替换时会改变校验结果；多个字符同时出错仍可能碰撞，校验位也可能被替换。不能用「约 1/10」概括碰撞率：概率取决于错误模式，不是对所有识别错误成立的常数。它只能补充独立业务校验，不能代替可信来源核对。

## 这个错误在循环里会怎么放大

旧摘要中的单次错误占比是 8/360；它不是可推广的生产错误率。无论实际发生率是多少，错误值进入后续推理都会被继承；风险取决于任务链的校验与恢复机制。

**第一次放大：错误进入后续所有推理。** 一旦 836 被写进上下文，后面每一轮都基于它计算。第 5 章讲过「用代码注入事实」能治幻觉 —— 那条经验在这里反过来成立：**一个错误的事实会被后续所有推理继承，而且它比幻觉更难发现，因为它看起来像真的。**

**第二次放大：没有独立信源时难以及时发现。** 文字文件通常能与原文逐字符对照；视觉输入还可由人工、独立 OCR 或可信业务记录复核，但让同一个模型重复解释并不构成独立证据。是否有第二信源取决于业务系统设计，应在执行下游动作前明确校验路径。

这两次放大合起来，就是下一节要解决的问题：把视觉接进循环时，必须同时接进**校验**。
## 完整可运行代码：本地评分与 Luhn 校验

实跑状态：`verify_multimodal_vision_failures_review_20261021.py` 执行了本地代码块与勘误断言；未调用模型，不读取真实图片，也未重放旧 API 结果。

下面脚本不调用模型，也不重现旧视觉结果。它检查三件能在本地证明的事：八组历史摘要中的单字符替换是否会被 Luhn 校验发现；对全部 0000–9999 四位正文逐位替换是否会被发现；严格 grader 是否拒绝不完整/额外行，并把合法但错误的字段单独计分。

```python
import json


def check_digit(digits: str) -> str:
    """为非空十进制数字串生成 Luhn 校验位。"""
    if (
        not isinstance(digits, str)
        or not digits
        or any(char < "0" or char > "9" for char in digits)
    ):
        raise ValueError("digits must be a non-empty ASCII decimal string")
    total = 0
    for i, ch in enumerate(reversed(digits)):
        value = int(ch)
        if i % 2 == 0:
            value *= 2
            if value > 9:
                value -= 9
        total += value
    return str((-total) % 10)


def valid(code: str) -> bool:
    """校验 body + check digit；不接受分隔符或空串。"""
    return (
        isinstance(code, str)
        and len(code) >= 2
        and all("0" <= char <= "9" for char in code)
        and check_digit(code[:-1]) == code[-1]
    )


def invalid_schema_result():
    return {
        "status": "invalid_schema",
        "correct_cells": None,
        "total_cells": None,
    }


def score(expected, candidate, finish_reason):
    """只对 end_turn、精确行数和精确字段集合的 JSON 数组评分。"""
    if finish_reason != "end_turn":
        return {"status": "incomplete", "correct_cells": None, "total_cells": None}
    if not isinstance(candidate, list) or len(candidate) != len(expected):
        return invalid_schema_result()

    keys = {"item", "qty", "amount"}
    for row in candidate:
        if not isinstance(row, dict) or set(row) != keys:
            return invalid_schema_result()
        if not all(isinstance(row[key], str) for key in keys):
            return invalid_schema_result()

    mismatches = []
    correct = 0
    for i, truth in enumerate(expected):
        for key in ("item", "qty", "amount"):
            if candidate[i][key] == truth[key]:
                correct += 1
            else:
                mismatches.append({
                    "row": i + 1,
                    "field": key,
                    "expected": truth[key],
                    "actual": candidate[i][key],
                })
    return {
        "status": "complete",
        "correct_cells": correct,
        "total_cells": len(expected) * 3,
        "mismatches": mismatches,
    }

if __name__ == "__main__":
    historical_pairs = [
        ("838", "836"), ("260", "250"), ("388", "398"), ("428", "426"),
        ("8838", "9838"), ("986", "586"), ("699", "698"), ("359", "389"),
    ]
    rejected = 0
    for truth, misread in historical_pairs:
        printed = truth + check_digit(truth)
        wrong_read = misread + printed[-1]  # 假设校验位本身识别正确
        assert valid(printed)
        assert not valid(wrong_read)
        rejected += 1

    single_digit_mutations = 0
    for value in range(10_000):
        body = f"{value:04d}"
        printed = body + check_digit(body)
        for position, original in enumerate(printed):
            for replacement in "0123456789":
                if replacement == original:
                    continue
                mutated = printed[:position] + replacement + printed[position + 1:]
                assert not valid(mutated)
                single_digit_mutations += 1

    # Luhn 是模 10 校验，不防任意多字符错误；此处是一组碰撞示例。
    assert valid("00000") and valid("81000")

    expected = [{"item": "ITM-122", "qty": "838", "amount": "88.38"}]
    parsed = [{"item": "ITM-122", "qty": "836", "amount": "88.38"}]
    scored = score(expected, parsed, "end_turn")
    assert scored["correct_cells"] == 2 and scored["total_cells"] == 3
    assert score(expected, [], "end_turn")["status"] == "invalid_schema"
    assert score(expected, parsed, "max_tokens")["status"] == "incomplete"

    print(
        "historical_single_digit_pairs_rejected=%d/%d"
        % (rejected, len(historical_pairs))
    )
    print(
        "single_digit_mutations_detected_"
        "for_4_digit_bodies=%d/%d"
        % (single_digit_mutations, single_digit_mutations)
    )
    print("two_digit_collision=valid(00000),valid(81000)")
    print(
        "strict_score="
        + json.dumps(scored, ensure_ascii=False, sort_keys=True, indent=2)
    )
    print("missing_row=invalid_schema; truncated=max_tokens/incomplete")
```

## 常见坑

- **把历史摘要当作已复核事实。** 旧的 352/360 与 36/36 缺逐次原始输出，不能说明当前模型质量。
- **把 JSON 解析成功当成完整评分。** 旧 grader 没有检查行数、额外字段或完整 schema，合法语法不等于内容正确。
- **把旧分辨率摘要当作因果结论。** 160–2,000 px 的单次报告不能证明尺寸不影响质量。
- **把一次对比度测试当作鲁棒性保证。** `#ddd` 的历史摘要不能推广到其它图像、模型或扫描条件。
- **把少数样本占比称为错误率。** 同一图像的多次调用、页面模板和任务都可能相关；逐样本记录后再设计统计比较。
- **把固定前缀说成校验位。** `ITM-122` 没有校验和，格式看起来规整不等于可以发现合法数字替换。
- **把校验和当成真实性保证。** 先明确它能发现的错误，再与独立数据源、业务规则和人工复核配合。
