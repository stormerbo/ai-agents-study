切分是检索链路中的一个设计变量：它影响索引单元、证据的边界、元数据继承与上下文拼装。切分过粗可能带入无关内容，切分过细可能丢失局部语境；但解析、索引、召回、过滤、重排和生成也都会影响结果，不能把检索上限归因于切分一个因素。

本节的历史比较标注为本站 28 篇正文与 BM25。原始文档快照、逐题请求/排名、gold span、tokenizer/打分器配置和 scorer 版本未归档，表中质量数字无法从当前工作树独立复算。它们只作为说明“评测粒度会改变观察结果”的历史摘要，不证明某种切分策略普遍更优。为什么先讲词法基线，见第 1 节末尾。

## 历史摘要：评测粒度会改变“命中”的含义

先定义两个容易混淆的指标（第 4 节展开）：当每条查询只有一个 gold 证据单元时，**hit-rate@k** 表示 top-k 中至少出现该单元的查询比例；有多个相关单元时，**recall@k** 通常按已找回的相关单元数除以相关单元总数计算。旧表只有“每条查询是否命中某个 gold”的汇总，更准确应称 hit-rate@k，不能在没有相关单元集合定义时直接称 recall。**MRR** 是每条查询第一个相关结果排名倒数的平均。旧表中的 `10/15` 表示 15 条查询中 10 条命中，不足以说明稳定的总体差异。

旧记录的第一种指标是「正确答案在哪一篇，检索结果里有没有这一篇」。以下两张表是未能独立复算的历史汇总：15 条查询的清单、证据标注、各策略 chunk 映射、检索排序与判分脚本未归档。文件级和章节级的单位不同，也不能据此推断切分策略的因果效果：

| 策略 | 命中率@1 | 命中率@3 | 命中率@5 | 命中率@10 |
|---|---:|---:|---:|---:|
| 固定 400 字符、无重叠 | 10/15 | 12/15 | 13/15 | 14/15 |
| 固定 400 字符、重叠 80 | 9/15 | 12/15 | 13/15 | 14/15 |
| 按结构边界切 | 11/15 | 12/15 | 12/15 | 14/15 |

旧表中文件级命中数字接近，但我们无法检查其查询和判分细节。按文档 ID 命中与按 chunk/evidence span 命中回答的是不同问题；不能仅靠这两张缺原始记录的表把差异归因于评测粒度。若模型收到的是 chunk，评测应映射到稳定证据 span，并额外报告来源文档命中。

旧报告还列出章节级统计（金标据称是答案所在的 `##` 小节，平均 524 字符）；由于原始清单和映射缺失，下面的数值同样仅作历史摘要：

| 策略 | 命中率@1 | 命中率@3 | 命中率@5 | MRR |
|---|---:|---:|---:|---:|
| 固定 400 字符、无重叠 | 5/15 | 6/15 | 8/15 | 0.389 |
| 固定 400 字符、重叠 80 | 4/15 | 8/15 | **11/15** | 0.440 |
| 按结构边界切（软上限 800 字符） | 5/15 | 6/15 | 7/15 | 0.372 |
| 按结构边界切（软上限 1500 字符） | 3/15 | 6/15 | 7/15 | 0.294 |

旧汇总称同一策略在文件级为 13/15、章节级为 8/15。这个差异说明**评测单元会改变“命中”的含义**，但因原始查询、gold 标注与检索结果未归档，不能独立确认差值，也不能据此说一半问题普遍找不到。评测时应以稳定的原文证据 span/来源 ID 为 gold，再把每种切分方案的结果映射回该证据；不要为了适配某个 chunker 而重标 gold，否则不同策略的分数失去可比性。

### 标注须知

这五条只是格式示例，数量不能用作建议阈值。评测集应按真实流量、风险和任务类型覆盖分层；难例比例、样本量和标注流程需由目标任务决定。可采用双人独立标注与分歧裁决，降低提问者单人标注的确认偏差。

1. **答案跨多个位置时，把所有必要证据都标出来。** 保存原文 span 与支持的事实；chunker 变化后重新映射 span，不改变 gold。若某个答案确实需要文档级汇总，单独标为聚合任务并定义其完成条件。
2. **关键词重合但答案不在，按「不相关」标。** 标错的代价是你会去优化一个不存在的问题：指标说召回到了，人读原文却找不到答案。
3. **标注者与样本量。** 可由熟悉任务的人起草，但应让第二人独立复核或抽样裁决；样本量与困难样本比例按流量、风险和评测目标确定，15–30 条只是探索性起点，不是可靠性门槛。
4. **切分变化时不要跟着重写 gold。** gold 应锚定原文中的证据 span、来源版本与必要的上下文；各策略的 chunk ID 和边界变化后，重新计算哪些 chunk 覆盖这些 span。若确实改变问题/答案定义，应作为新数据集版本并保留映射，不能把改过的标注分数与旧分数直接对比。

## 历史摘要：召回、相关内容比例与覆盖是不同维度

旧表称重叠策略的命中率@5 为 11/15，但该小样本和检索结果无法复核；重叠可能让相邻块重复携带证据，也可能增加冗余。需在固定 gold、检索预算与去重规则下实测，不能把该差异当作重叠的普遍效果。

旧记录还列出两个 top-1 字符重叠代理指标；当前缺少原始 chunk 和 gold span，无法复算：

- **top-1 字符精度代理**：top-1 chunk 与 gold evidence span 的字符交集长度 / chunk 字符长度。
- **top-1 字符覆盖代理**：top-1 chunk 与 gold span 的字符交集长度 / gold span 字符长度。

这两个是基于字符区间重叠的代理指标，不等价于语义相关性或答案充分性；应先定义重叠规则、重复文本处理、多 span 汇总方式和编码单位。

| 策略 | 块数 | 平均块长（字符） | 命中率@5（旧摘要） | 字符精度代理（旧摘要） | 字符覆盖代理（旧摘要） |
|---|---:|---:|---:|---:|---:|
| 固定 400 字符、无重叠 | 361 | 385 | 8/15 | 0.10 | 0.07 |
| 固定 400 字符、重叠 80 | 439 | 390 | 11/15 | 0.13 | 0.11 |
| 按结构边界切（软上限 800 字符） | 314 | 391 | 7/15 | **0.35** | **0.34** |
| 按结构边界切（软上限 1500 字符） | 288 | 436 | 7/15 | 0.22 | 0.25 |

旧表的 0.35 与 0.10 是未复核的字符代理摘要；缺少 gold span、chunk 原文与去重口径，不能解释成“三分之一相关”或模型实际收到的相关 token 比例。

上下文中额外文本可能增加输入处理量；缓存、服务端计量与费用依 endpoint 和调用轨迹而异。应分别记录原始 usage、缓存与实际账单，不能从字符精度代理直接推导每轮成本。

旧摘要呈现出命中与字符代理间的取舍，但当前材料不足以复核排序、重排或生成效果。设计时先给任务定义必要证据和上下文预算，再在同一数据集上比较 evidence hit、上下文覆盖、冗余与端到端质量；不能仅凭某个代理指标决定上线策略。

## 无 gold 标注的结构代理：句末标点率

上面那组实验需要人工标注 15 条查询的金标章节。有没有不需要标注、又能反映切分质量的做法？有。

这里的脚本会计算**句末标点率**：非空 chunk 的最后一个非空白字符是否属于指定标点集合。它无需人工 gold，但只测一个词面代理，**不能证明块语义完整**；它不检查块首、标题/表格/代码结构、列表依赖、引用上下文或答案是否自包含。旧报告中的三行结果无法在当前文档版本上复算：

| 文件 | 固定 400 / 无重叠 | 固定 400 / 重叠 80 | 结构边界 / 上限 800 |
|---|---:|---:|---:|
| retrieval/01-why-retrieval（8,060 字符） | 25% | 36% | **83%** |
| context-engineering/04-compaction（5,928 字符） | 30% | 29% | **60%** |
| llm-api-basics/01-tokens-and-context（12,108 字符） | 21% | 24% | **78%** |

（旧摘要标注为 2026-10-08；原始文档快照与运行记录未归档，以下数值不可独立复核。）

即使脚本算出低句末标点率，也只能提示你抽样检查切分边界；不能推断“四分之三是半句话”，因为它没有检查句首，也未建立语义完整性 gold。对自己的语料，可把它作为结构诊断指标之一，并配合人工边界审阅和检索/答案评测。

## 完整可运行代码

这个标准库示例只演示字符长度切分、二/三级 Markdown 标题与空行分组、句末标点率。它不是通用 Markdown parser：不处理表格/列表/MDX 语义、token budget、来源 span 映射或结构化 chunk metadata。结构切分的 `max_len` 是软上限；超长段落或为保留标题与首段关联而合并的小节单元都可能超过它。

```python
"""三种教学切分策略：块数、平均字符数与句末标点率。

用法：保存为 chunk-demo.py 后运行 python3 chunk-demo.py <某个 .mdx 或 .txt 文件>
只用标准库。

「句末标点率」的定义：非空块右侧去除空白后，以指定中文句末标点结尾的块占比。它不衡量块是否在段落边界，更不能单独证明语义完整。

实跑状态：2026-10-21；只运行本地示例，不调用模型 provider。
"""

import re
import sys

FENCE = re.compile(r"```[\s\S]*?```")


def strip_code(text):
    """把代码块替换成等长空格：保住字符偏移，同时不让代码参与切分。"""
    return FENCE.sub(lambda m: " " * len(m.group(0)), text)


def fixed(text, size, overlap):
    if size <= 0 or overlap < 0 or overlap >= size:
        raise ValueError("require size > 0 and 0 <= overlap < size")
    step = size - overlap
    out = []
    for i in range(0, len(text), step):
        piece = text[i:i + size]
        if piece.strip():
            out.append(piece)
        if i + size >= len(text):
            break
    return out


def structural(text, max_len):
    """按 Markdown 标题切；超长的小节按空行切，并尽量让标题跟随首段。"""
    if max_len <= 0:
        raise ValueError("max_len must be positive")
    out = []
    for sec in re.split(r"\n(?=#{2,3} )", text):
        if len(sec) <= max_len:
            if sec.strip():
                out.append(sec)
            continue
        paragraphs = re.split(r"\n\n+", sec)
        if len(paragraphs) > 1 and re.match(r"^#{2,3} ", paragraphs[0]):
            paragraphs[0] += "\n\n" + paragraphs.pop(1)
        buf = ""
        for para in paragraphs:
            if buf and len(buf) + len(para) + 2 > max_len:
                out.append(buf)
                buf = para
            else:
                buf = buf + "\n\n" + para if buf else para
        if buf.strip():
            out.append(buf)
    return out


def sentence_end_rate(chunks):
    """词面统计，不代表语义完整。"""
    nonempty = [chunk.rstrip() for chunk in chunks if chunk.strip()]
    if not nonempty:
        return 0.0
    marks = ("。", "！", "？", "!", "?", ".")
    return sum(chunk.endswith(marks) for chunk in nonempty) / len(nonempty)


if __name__ == "__main__":
    path = sys.argv[1] if len(sys.argv) > 1 else "src/content/chapters/retrieval/01-why-retrieval.mdx"
    with open(path, encoding="utf-8") as handle:
        raw = handle.read()
    raw = re.sub(r"^---[\s\S]*?---", lambda m: " " * len(m.group(0)), raw)
    text = strip_code(raw)
    print("文件: %s，%d 字符" % (path, len(text)))
    print()
    print("%-22s %6s %10s %12s" % ("策略", "块数", "平均字符数", "句末标点率"))
    for name, chunks in [
        ("固定 400 字符 / 无重叠", fixed(text, 400, 0)),
        ("固定 400 字符 / 重叠 80", fixed(text, 400, 80)),
        ("结构边界 / 软上限 800 字符", structural(text, 800)),
    ]:
        avg = sum(len(c) for c in chunks) / len(chunks) if chunks else 0
        print("%-22s %6d %10.0f %11.0f%%" % (name, len(chunks), avg, sentence_end_rate(chunks) * 100))
```

用法与实跑输出：

```text
固定 400 字符 / 重叠 80          23        389           9%

```

## 块大小需要按任务验证

旧摘要中的 800/1500 对照没有原始 chunks、gold span 和指标口径，不能证明块长增加导致质量下降。较大的块可能保留跨段上下文，也可能引入无关内容；较小的块可能更精确，也可能缺少必要定义。应同时检查任务所需证据是否完整、来源元数据是否保留、上下文预算与端到端效果。

实用起点是让每个 chunk 带足够回答目标查询的证据和局部上下文，同时保留文档 ID、版本、章节路径与原文偏移。按结构边界切是候选策略之一；跨段问题可考虑 parent-child、相邻块扩展或检索后上下文拼装。字符长度只是教学示例的约束单位，生产限制应按目标 tokenizer 与模型预算校准。

下面用构造场景说明如何人工检查证据上下文，不表示旧实验中真实存在的 chunk：

- **候选完整单元**：一段包含指标定义、计算单位和限制的短节，可映射到一个或多个 chunk；评估它是否足以支持具体问题，而不是只看标题/段落是否完整。
- **反例**：若块从一个指代词或列表中间开始，且缺失被指代的定义/标题，审阅者可能无法独立解释；标出原文 span 与缺少的上下文，再用检索任务验证是否影响答案。

检查候选 chunk 时，可问：**在目标权限和任务条件下，它是否包含足够证据回答这个 query，并保留来源与必要上下文？** 若不足，原因可能是切分、检索、权限过滤或上下文拼装，需要分别定位；不能只凭人工可读性断言 chunker 错了。

## 常见坑

- **把默认切分参数当作适合自己语料的答案。** 工具提供的默认值是实现选择；例如 LangChain 当前文档以 `RecursiveCharacterTextSplitter` 作为多数用例的起点，RAGFlow 当前 Chunker 文档说明 token-based 是其默认方法。它们是各自版本的产品说明，不构成跨语料通则。按文档类型、模型 token 上限、检索任务和评测结果做配对验证。
- **把代码块和表格当普通散文任意切开。** 可先按结构解析并保留必要的语言/列头/行关联；确实要拆分时显式重复上下文元数据，并用样例检查解析后内容。
- **只评文档 ID 命中。** 若最终送入模型的是 chunk，评估要把检索结果映射到稳定的 gold evidence span；本节文件级/章节级数字只是不可复核的历史摘要。
- **只盯命中率。** 还需评估证据覆盖、上下文冗余、任务成功率与按 endpoint 记录的 usage/成本；字符重叠代理不能代替它们。
- **把 chunk 大小当作一个固定字符数。** 例子按字符切只是可读的本地演示；生产上要同时看 tokenizer、模型上下文预算、表格/代码结构、检索效果和重叠去重。
- **把切分与排序分开优化。** 保持 query、gold evidence、过滤条件和候选预算一致，分别检查召回、排序、过滤与端到端答案；单个小样本摘要不能证明某组件无效。
