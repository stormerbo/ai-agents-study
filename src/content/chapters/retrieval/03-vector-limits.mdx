上一节留下了一个历史摘要：四种切分策略的章节级 hit-rate@1 被记录为 3/15 到 5/15。原始查询、语料快照、gold 映射与 scorer 未归档，无法独立复算；即使接受这个摘要，它也不能证明正确段落通常排不到第一位。本节把它作为待复核背景，不当作当前检索性能基线。

这一节讨论两类独立问题：相关证据能否进入候选集，以及候选集内能否排到合适位置。查询改写只是需要在目标流量中验证的一类输入。

这些问题是作者构造的口语化改写，不是采集到的用户查询。它们可以用作一组探索性测试样例，但不能证明真实用户通常如何提问；正式评测应从目标流量抽样并做隐私处理与分层。

旧摘要中的 Jaccard 值为 0.012 到 0.041，但由于自定义 tokenizer 与输入快照缺失，不能把它们解释为通用的中文词面重合程度。低重合可以提示词法检索可能缺少匹配线索；是否会无结果、排位低或被其他信号补回，要看具体 analyzer、索引与查询。

这组旧摘要不足以判断调参能否解决问题。更稳妥的工程做法是把 lexical analyzer、查询改写、向量召回和过滤分别纳入同一评测集比较，而不是先假定任一路径必然失效。

## 字面匹配能做什么、不能做什么

下面只给出待验证的设计假设，不把这组历史 BM25 摘要推广为通则；本节没有真实 embedding 端点或可复算的向量实验：

| 查询类型 | 词法检索 | 向量检索 | 本节证据 |
|---|---|---|---|
| 与索引文本共享关键词 | 可能匹配，具体取决于 analyzer 与排序 | 可能匹配语义近邻 | 需在同一语料实测 |
| 改写、同义表达 | 可能因词面差异漏掉相关文档 | 可能补回候选，也可能误召回 | 本节旧表只记录词法结果；向量效果未测 |
| 专有名词、错误码、订单号 | 若索引保留标识符，精确匹配可能有优势 | 向量是否保留区分度取决于模型与标识符 | 任务假设，需用目标标识符集验证 |
| 需要跨句/跨段证据 | 可能召回局部词项 | 可能召回语义相关片段 | 需评估证据完整性与端到端答案 |

精确标识符要单独测试：有些 embedding 模型会保留常见代码/名称信息，有些未必能稳定区分稀有编号；不能仅从“语义向量”推断某个订单号必然失败。准备含精确 ID、近似 ID、错别字和自然语言改写的 query 集，分别检查 lexical、vector 与 hybrid 的候选召回和误命中。

词法与向量可以互补，因此混合检索是值得评测的候选架构；它不是所有系统的默认答案。若 query 主要是精确 ID、数据集很小或系统已有权威 SQL/API 路径，其他方案可能更合适。比较时固定数据、过滤、候选预算与判分口径。

上表列的是需验证的任务假设；下面补充向量检索的基本机制、索引近似性和评测边界。

## 向量检索的最小可用知识

把向量检索机制拆成四步：

1. **切块**（上一节）→ 2. **每块过一遍嵌入模型，得到一个定长向量** → 3. **把查询也过同一个模型** → 4. **按距离排序取 top-k**。

检索常见的向量打分/距离包括余弦相似度、内积和欧氏距离。该用哪一种取决于嵌入模型的训练目标、是否归一化及向量库配置；不要假设所有模型都以余弦为最佳度量。

- **余弦相似度**：两个非零向量的点积除以各自模长，范围为 -1 到 1；值越大表示方向越一致。零向量需要单独处理。
- **内积**：`x·y`，向量长度会影响分数；若两边都做 L2 归一化，内积等于余弦相似度。

例如 [OpenAI Embeddings FAQ](https://help.openai.com/en/articles/6824809-embeddings-faq) 说明其当前 API embeddings 默认做 L2 归一化，因此在该契约下 dot product 与 cosine 给出相同排序；不能推广到其他 embedding provider。

**ANN（近似最近邻，approximate nearest neighbor）** 通过少访问部分向量或压缩表示降低搜索开销，可能带来召回损失；具体速度、内存和召回取决于索引类型、参数、硬件与数据分布。[Faiss 索引选择指南](https://github.com/facebookresearch/faiss/wiki/guidelines-to-choose-an-index)同时介绍精确 Flat 基线与 HNSW/IVF 等近似索引。不要把“十万条”当作通用切换阈值：先用精确搜索做基线，再在目标硬件和真实数据上测延迟、内存与 recall@k。



1. **验证版本与一致性**：固定模型 ID/版本、输入预处理、维度与归一化配置；重复请求并记录漂移。若 provider 不承诺逐位确定性，可比较向量差异和 top-k 稳定性，不能据一次变化就断言索引不可复现。
2. **验证向量空间兼容性**：比较向量要求相同维度，但维度相同不代表模型空间兼容。更换模型/版本时，使用版本化索引并重算文档向量；迁移期间可双写或并行评测，不要把新旧空间的向量混在同一查询里。
3. **构造目标任务集**：包含改写、错别字、精确 ID、缩写和跨段证据；对照 lexical/vector/hybrid 的 evidence hit、误召回与延迟。本节旧表只测特定词法流程，未测向量能救回多少。

### 混合召回：两路各取 top-K，再合并

两路候选的分数**不同量纲**（BM25 是 0 到十几的无界分，余弦是 -1 到 1），不能直接相加。两种常用归一化：

- **min-max 归一化**：把每路分数线性拉到 0 到 1，再按权重相加。简单，但对**异常值敏感** —— 一路里有一个极高分会把其余压扁。
- **RRF（倒数排名融合，reciprocal rank fusion）**：忽略各路原始分值，按 `Σ 1/(k₀ + rank)` 汇总候选排名。[原始 RRF 论文](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf)在 pilot 中固定 `k₀=60`，这不是普遍最优值；将它作为简单基线，并按目标数据比较不同 k 与分数融合。RRF 不需要跨路分数校准，但仍受各路排序质量、候选深度和截断影响。

下面是本地教学骨架，不调用 provider。`embed()` 是字符哈希假向量，只展示固定维度、相似度计算、候选合并和去重，不代表语义嵌入效果。换成真实 embedding API 还需处理认证、批量、限流、错误/重试、模型版本、向量维度与索引迁移，不能只替换一个函数就直接上线。

```python
# hybrid_recall.py
"""两路召回（词法 + 向量）→ RRF 融合 → 去重 → 送重排。

自包含：只需标准库。embed() 是本地假嵌入（字符哈希），
不要把这一段假实现当作可替换即上线的 provider adapter；真实接入还需适配批量、错误、限流、版本、维度与索引迁移。

实跑状态：控制流已跑通（本机 Python 3.14.7）；嵌入是占位实现，
所以距离数值无意义 —— 它演示的是合并与去重，不是语义效果。
"""

import hashlib
import math
import re

DIM = 64
RRF_K = 60  # 原论文 pilot 值；实际应用应在目标数据上调参

DOCS = {
    "确定性": "把温度设为 0 并不保证两次调用给出完全相同的结果。",
    "缓存": "前缀缓存命中时，未命中的输入会大幅下降。",
    "切分": "文档被从段落中间切开后，单独看这一块往往已经看不出它在讲什么。",
    "重排": "先宽召回再精细排序，两步的目标不同。候选集大小决定了重排的上限。",
    "确定性-改写": "模型的输出带有厂商侧的非确定性，设温度并不能消除。",
}


def tokenize(text):
    text = text.lower()
    out = re.findall(r"[a-z0-9_]+", text)
    for run in re.findall(r"[\u4e00-\u9fff]+", text):
        out.extend(run[i:i + 2] for i in range(len(run) - 1))
    return out


def embed(text):
    """占位嵌入：把 token 哈希到固定维度再归一化。

    真实环境里换成一次 /embeddings 请求；这里保证：
      - 维度固定（DIM）
      - 同样输入两次结果一致
      - token 哈希会发生碰撞，距离只是一种玩具数值，不能解释语义
    但它不携带语义 —— 这正是要你用真模型替换的地方。"""
    vec = [0.0] * DIM
    for tok in tokenize(text):
        h = int(hashlib.md5(tok.encode()).hexdigest()[:8], 16)
        vec[h % DIM] += 1.0
    norm = math.sqrt(sum(x * x for x in vec)) or 1.0
    return [x / norm for x in vec]


def cosine(a, b):
    if len(a) != len(b):
        raise ValueError("vector dimensions must match")
    return sum(x * y for x, y in zip(a, b))


def lexical_recall(query, k=20):
    """简化词法：按共享 token 数排序（真实实现用 BM25，见第 1 节）。"""
    q = set(tokenize(query))
    scored = []
    for doc_id, text in DOCS.items():
        overlap = len(q & set(tokenize(text)))
        if overlap:
            scored.append((overlap, doc_id))
    scored.sort(key=lambda x: (-x[0], x[1]))
    return [d for _, d in scored[:k]]


def vector_recall(query, k=20):
    qv = embed(query)
    scored = [(cosine(qv, embed(text)), doc_id) for doc_id, text in DOCS.items()]
    scored.sort(key=lambda x: (-x[0], x[1]))
    return [d for s, d in scored[:k]]


def rrf(*rankings):
    """倒数排名融合：公式只用排名，不依赖各路原始分数。"""
    scores = {}
    for ranking in rankings:
        for rank, doc_id in enumerate(ranking, 1):
            scores[doc_id] = scores.get(doc_id, 0.0) + 1.0 / (RRF_K + rank)
    return sorted(scores, key=lambda d: (-scores[d], d))


if __name__ == "__main__":
    query = "温度设成 0 结果就确定了吗"
    lex = lexical_recall(query)
    vec = vector_recall(query)
    merged = rrf(lex, vec)
    print("词法候选:", lex)
    print("向量候选:", vec)
    print("融合去重后:", merged)
    print("送去重排的候选数:", len(merged), "（并入本行去重）")
```

本地代码输出（Python 3.14.7，2026-10-21；这里仍是哈希占位向量，候选顺序没有语义含义）：

```text
词法候选: ['确定性', '确定性-改写', '重排']
向量候选: ['确定性', '确定性-改写', '重排', '切分', '缓存']
融合去重后: ['确定性', '确定性-改写', '重排', '切分', '缓存']
送去重排的候选数: 5
```

这段只有 5 篇玩具文档，所以 `k=20` 会取回全部可用候选，不能用来展示宽召回的收益或比较候选深度。它只演示三件事：

1. **按排名融合**：RRF 不直接把 BM25 与余弦等异量纲分数相加；它仍需要用目标数据选择候选深度和 `k₀`。
2. **合并候选**：实际系统要记录各路来源，才能分析互补与重复。
3. **保留可追溯 ID 并去重**：否则重排预算可能浪费在同一证据的重复副本上。召回是否“取宽”需要用 gold evidence 与延迟/成本预算验证。

## 历史摘要：宽候选 + 重排的效果

召回器负责把相关候选送进下一阶段，重排器负责在收到的候选中重新排序。候选召回、过滤与重排可独立诊断；“多召回”会增加噪声和成本，因此应在固定 gold、候选预算和延迟条件下评估。

旧报告称将同一组 10 条人工改写查询的词法 top-20 交给模型重排。当前工作树只找到生成请求的脚本，没有原始逐次响应、完整候选快照、确切模型配置和可重算 scorer；以下数字不能独立复核，因此不作为重排器当前效果证据。

| 指标（旧摘要，未复核） | 重排前 | 重排后 | 候选集上限 |
|---|---:|---:|---:|
| 正确答案在 top-3 | 0/10 | **4/10** | — |
| 正确答案在 top-20 内 | 4/10 | — | **4/10** |
| 这 10 次调用的输入 token | — | 25,505 | — |
| 这 10 次调用的输出 token | — | 10,208 | — |

（旧记录标注为 2026-10-08；原始响应与逐题判分未归档。候选列表固定并不自动证明变化只来自重排，仍需记录模型配置、终止原因与 scorer。）

历史摘要报告重排前 top-3 为 0/10、top-20 命中为 4/10、重排后 top-3 为 4/10。因逐次响应、模型指纹、候选映射与 scorer 缺失，无法验证是否“打满天花板”；数学上的候选上限只说明若 gold 不在输入候选中，reranker 无法选中它。

两阶段检索有一个确定的集合边界：reranker 只能重排它收到的候选，不能补出缺失文档。召回质量、过滤、切分和 gold 映射仍需分别测量；该原理不依赖这组无法复核的 4/10 摘要。

### 重排的输入长什么样

下面是一个构造的编号列表，不是历史请求快照；实际 API 消息应由当前检索结果、过滤规则与稳定文档 ID 生成：

```text
问题：同一个问题问两遍，答案会不会一模一样

候选：
1. [确定性] 把温度设为 0 并不保证两次调用给出完全相同的结果。厂商侧仍存在非确定性。
2. [缓存] 前缀缓存命中时，未命中的输入会大幅下降。任何一处前缀改动都会让它全部失效。
3. [切分] 文档被从段落中间切开后，单独看这一块往往已经看不出它在讲什么。
4. [重排] 先宽召回再精细排序，两步的目标不同。候选集大小决定了重排的上限。
5. [确定性-改写] 模型的输出带有厂商侧的非确定性，设温度并不能消除。
```

配套的 system 提示只有一句（`listing` 就是上面这份编号清单）：

```text
你是检索重排器。只输出最相关的前 1 个候选编号，JSON 数组，例如 [2]。不要解释。
```

关于这份提示词，有四条可验证要点：

1. **要求编号而不是原文** —— 让模型复制原文既贵又容易改写内容；编号还能让你机械地映射回文档 id。
2. **要求机器可读的 JSON 数组** —— 解析后还要校验终止原因、数组类型、编号范围、重复项与候选映射；仅用正则提取数字会把解释文字、越界编号或截断都误当成合法答案。
3. **候选顺序可能影响结果。** 这不是本节实测（本次没做对照组），是可验证的假设：换一种排序方式重跑同一批查询，看 top-3 命中率有没有变化。要验证它，先把候选顺序**固定下来并写进日志**，否则你无法解释结果波动来自哪里。
4. **避免只在调参集报告效果** —— 在开发集调整提示词与候选格式，最后用未参与调参的查询集评估；是否过拟合由留出集结果判断。

## 重排的预算取决于输入长度与模型响应

旧记录称 10 次重排共使用输入 25,505 / 输出 10,208 tokens；缺少逐次原始响应与 usage，不可独立复核，也不代表其他 endpoint 的计量口径。

通常，候选文本总量增加会推高输入 tokens，但实际增量受每段长度、格式、缓存和 endpoint tokenizer/usage 契约影响；不能仅按候选条数推算费用。输出长度则取决于输出格式、候选数、模型行为和预算。工程上可比较不同候选深度下的 evidence recall、重排质量、输入/输出 usage、延迟及费用，再选满足 SLA 的点；“几十条”不是通用阈值。

## 完整可运行代码

这个示例使用 `urllib.request` 直接发送 `x-api-key`。Python 文档说明，添加到 `Request` 的普通请求头也会随 HTTP 重定向请求发送，因此不能假设认证头会因主机变化而自动剥离。本例用自定义 `HTTPRedirectHandler` 拒绝自动重定向；若 endpoint 返回 3xx，`opener.open` 会失败并由上层按请求失败处理。应把 base URL 配成规范地址。该防护只针对 Python urllib 的行为，其他 HTTP 客户端需查各自文档并测试。

```python
"""两阶段检索：宽召回 + 模型重排。

演示词法候选、玩具字符共现候选与 reranker 接口。旧记录中的“词法无命中”和模型结果无法在当前语料与环境下独立复算。

只用标准库。需要在进程环境中设置 `ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN` 与 `VERIFY_MODEL`；本地离线运行不需要凭据。

历史 API 结果标注为 2026-10-08 / deepseek-flash，但本轮没有原始逐次响应或精确配置可复核；本地 BM25/字符共现部分可离线运行，provider 部分需用户自行提供兼容端点与凭据。
"""

import json
import math
import os
import re
import urllib.request

DOCS = {
    "确定性": "把温度设为 0 并不保证两次调用给出完全相同的结果。厂商侧仍存在非确定性。",
    "缓存": "前缀缓存命中时，未命中的输入会大幅下降。任何一处前缀改动都会让它全部失效。",
    "切分": "文档被从段落中间切开后，单独看这一块往往已经看不出它在讲什么。",
}
QUERY = "同一个问题问两遍，答案会不会一模一样？"


def tokenize(text):
    """ASCII 词 + 汉字二元组。"""
    text = text.lower()
    out = re.findall(r"[a-z0-9_]+", text)
    for run in re.findall(r"[\u4e00-\u9fff]+", text):
        out.extend(run[i:i + 2] for i in range(len(run) - 1))
    return out


def bm25(docs, query, k=3):
    toks = {i: tokenize(t) for i, t in docs.items()}
    avgdl = sum(len(t) for t in toks.values()) / len(toks)
    df = {}
    for t in toks.values():
        for term in set(t):
            df[term] = df.get(term, 0) + 1
    k1, b = 1.2, 0.75
    scored = []
    for i, t in toks.items():
        tf = {}
        for x in t:
            tf[x] = tf.get(x, 0) + 1
        s = 0.0
        for term in set(tokenize(query)):
            if term not in tf:
                continue
            n = df.get(term, 0)
            idf = math.log(1 + (len(docs) - n + 0.5) / (n + 0.5))
            f = tf[term]
            s += idf * (f * (k1 + 1)) / (f + k1 * (1 - b + b * len(t) / avgdl))
        if s > 0:
            scored.append((s, i))
    scored.sort(reverse=True)
    return [i for _, i in scored[:k]]


def wide_recall(docs, query, k=3):
    """玩具候选生成：只按共享汉字数排序，不是向量检索或生产召回器。

    它只演示下游 reranker 接受候选列表；真实召回策略和候选预算必须另行评估。
    """
    chars = set(re.findall(r"[\u4e00-\u9fff]", query))
    scored = [(len(chars & set(re.findall(r"[\u4e00-\u9fff]", t))), i) for i, t in docs.items()]
    scored.sort(reverse=True)
    return [i for s, i in scored[:k] if s > 0]


class RejectRedirects(urllib.request.HTTPRedirectHandler):
    """拒绝重定向，避免认证头被转发到另一个 URL。"""
    def redirect_request(self, req, fp, code, msg, headers, newurl):
        return None


def rerank(query, candidates):
    """调用 Anthropic Messages 兼容端点；返回原始 usage 和 stop_reason。"""
    listing = "\n".join("%d. %s" % (n, c) for n, c in enumerate(candidates, 1))
    body = json.dumps({
        "model": os.environ["VERIFY_MODEL"],
        # 输出预算要按目标 endpoint 的终止状态验证；不能假定思考一定消耗多少
        "max_tokens": 4000,
        "system": "你是检索重排器。只输出最相关的前 1 个候选编号，JSON 数组，例如 [2]。不要解释。",
        "messages": [{"role": "user", "content": "问题：" + query + "\n\n候选：\n" + listing}],
    }).encode()
    req = urllib.request.Request(
        os.environ["ANTHROPIC_BASE_URL"].rstrip("/") + "/v1/messages",
        data=body,
        headers={"content-type": "application/json",
                 "x-api-key": os.environ["ANTHROPIC_AUTH_TOKEN"],
                 "anthropic-version": "2023-06-01"},
    )
    opener = urllib.request.build_opener(RejectRedirects())
    with opener.open(req, timeout=180) as resp:
        data = json.loads(resp.read())
    usage = data.get("usage", {})
    text = "".join(b["text"] for b in data.get("content", []) if b.get("type") == "text")
    return text, usage, data.get("stop_reason")


def parse_rerank_response(text, stop_reason, candidate_count):
    """只接受正常终止的完整 JSON 数组，且编号必须唯一、在候选范围内。"""
    if stop_reason != "end_turn":
        return None
    try:
        ids = json.loads(text)
    except json.JSONDecodeError:
        return None
    if not isinstance(ids, list) or not ids or len(ids) > 1:
        return None
    if any(type(item) is not int or item < 1 or item > candidate_count for item in ids):
        return None
    if len(set(ids)) != len(ids):
        return None
    return ids


if __name__ == "__main__":
    print("问题:", QUERY)
    strict = bm25(DOCS, QUERY, k=3)
    print("① 词法检索（BM25）:", strict if strict else "空 —— 一条都没召回")

    cands = wide_recall(DOCS, QUERY, k=3)
    print("② 玩具候选生成（共享汉字数）:", cands, "→ 候选中包含「确定性」")

    if cands and os.environ.get("ANTHROPIC_AUTH_TOKEN"):
        text, usage, stop = rerank(QUERY, [DOCS[i] for i in cands])
        picks = parse_rerank_response(text, stop, len(cands))
        if picks is None:
            print("③ 重排失败或未完成；不把响应当作空结果。stop_reason=%s" % stop)
        else:
            print("③ 模型重排候选 ID:", picks)
        print("endpoint 原始 usage:", json.dumps(usage, ensure_ascii=False, sort_keys=True))
    else:
        print("③ 未调用 provider；没有重排结果。")
```

## 历史错误摘要：截断响应被当成空数组

旧记录称第一次重排时 10 条都解析成空数组，但当前工作树没有完整原始响应、终态记录与评分日志，无法独立确认当时是否全部返回 `max_tokens`。不应把这段历史描述当成已复现的 provider 错误：

```text
⚠️ 被截断: 同一个问题问两次，结果会不会一模一样
❌ 同一个问题问两次，结果会不会一模一样  原排名=#13  模型选=[]
（10 条全部如此）
```

空数组可能表示“确实无候选”“模型返回非法格式”“解析器失败”或“响应被截断”；只有检查目标 endpoint 的终止字段和原始结构，才能区分。`max_tokens` 通常标记输出达到预算上限，但它本身不能证明是隐藏思考耗尽了预算。端到端实现应将非正常终止、拒绝、JSON 解析失败和候选 ID 越界分开记录；不要把它们静默转换成“没有相关内容”。

## 常见坑

- **把一组改写查询当成用户流量代表。** 本节 10 条是人工构造的探索样例，不是用户日志，也不能估计生产失败率。
- **把旧 BM25 结果推广为所有词法检索。** Analyzer、字段、切分与排序配置都会改变排名；用目标查询集验证。
- **假设向量检索能自动救回改写。** 需要在当前 embedding model、query/doc 指令、切分、过滤与 gold evidence 上实测。
- **指望重排解决“召回不到”。** reranker 不能选出未进入候选集的证据；用固定 gold 检查候选覆盖。
- **按候选条数直接算成本。** 看实际请求文本长度和 endpoint usage；保存原始 usage 字段，不跨 provider 相加。
- **把截断当成“无相关结果”。** 检查终止原因、拒绝状态、结构解析与候选 ID 校验，再决定是否重试或回退。
- **对所有文档一律使用重排。** 候选深度、质量、延迟和费用需要按业务 SLA 联合选择。
