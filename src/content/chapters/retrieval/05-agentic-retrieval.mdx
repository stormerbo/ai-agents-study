前面四节把检索当成一条**固定管线**：查询进来、召回、重排、送进上下文。这条管线什么时候跑、跑几次，都是你的代码决定的。

“Agentic retrieval”没有一个跨论文与框架完全统一的边界。本节把相关设计拆开，避免混为一谈：固定检索；先改写查询再检索一次；根据查询或风险选择不检索/检索一次/多步检索；以及用前一轮证据决定下一轮查询的迭代检索。一次改写不等于多跳检索，模型调用检索工具也不自动等于多轮推理。

研究里的实现也不都只是给通用 API 加一条 prompt。Adaptive-RAG 用复杂度分类器在不检索、单步和多步策略间选择；Self-RAG 则训练模型生成检索与反思标记。这些论文结果只适用于各自模型、数据集和实验设置，不能直接推出你的服务该让模型自行决定检索。见 [Adaptive-RAG](https://aclanthology.org/2024.naacl-long.389.pdf) 与 [Self-RAG](https://arxiv.org/abs/2310.11511)。

本节保留 2026-10-08 的本地历史记录作为待核实线索，再用一个不调用模型的可运行夹具讲清控制流和失败边界。

## 历史对照：三种形态的旧记录（未独立复核）

旧记录声称使用同一批 10 条口语化查询，并对三种做法各运行 3 次。原始 query 清单、语料版本、金标证据、逐轮请求/响应、排序与 scorer 均未归档；它与前一节相同的 10 条 query 也无法由现存记录核对。因此下面是**不可独立复核的历史摘要**，不是本站当前夹具或已重放实验：

- **臂 A**：原问题直接拿去检索（无 query rewrite）
- **臂 B**：让模型把问题改写成 3 条检索词，再合并检索结果
- **臂 C**：允许模型提出检索 query 或 DONE，最多 3 轮

下表保留旧表原值。`命中（3 轮）`指三次重复记录，不是 top-3；其余列的汇总窗口也未确认：

| 旧记录的做法 | 命中记录（三次） | 旧表均值（分母未核实） | 调用数（窗口未知） | 输入 token（口径未知） | 输出 token（口径未知） |
|---|---|---:|---:|---:|---:|
| A 原问题直接检索 | 0 / 0 / 0 | **0/10** | 0 | — | — |
| B 改写查询后检索一次 | 6 / 5 / 8 | **6.3/10** | 10.0 | 754 | 4,276 |
| C 多轮自主检索 | 3 / 4 / 3 | **3.3/10** | 18.7 | 5,660 | 7,527 |

（旧记录自述于 2026-10-08 使用 `deepseek-flash`；调用数、token 数是单次、均值还是三次合计，以及缓存 token 的口径均无法由原始数据确认。）

旧记录把命中定义为正确答案所在小节进入最终候选集，但金标、候选生成、最终候选深度和聚合方式没有留档。即使暂按表中数字解读，也不能由此说查询改写通常有效、agentic 方法较差，或差异由“模型选择不查”导致：A/B/C 同时改变了模型调用、查询数量、控制策略、历史上下文和可能的候选合并方式，缺少公平的配对设计。

不要用这张表作成本预测。特别是旧记录中的输入 token 比值 `5,660 / 754` 只有在二者统计口径、运行次数、缓存 usage、最终答案调用与所有轮次完全一致时才可比较；当前资料无法验证这些前提。

## 一个可复现的控制流失败

如果控制器只接受 `SEARCH: ...`，并把任何其他输出都解释为 `DONE`，模型拒绝、格式错误、截断或临时错误都可能被误记成“正常结束”。这是一种协议设计风险；它不能证明旧实验中发生过多少次，也不能证明模型当时是在“自认为知道答案”。

旧记录曾列出两条轨迹：一条首轮输出 DONE，一条检索一次后输出 DONE。由于逐次请求/响应未归档，它们是未复核摘要。下面的本地脚本用固定 FakePlanner 重现这类**控制流形状**，不模拟模型判断，也不测回答质量。

**第一条轨迹：一次都没查。**

```text
问题: 同一个问题问两遍结果会一样吗
  轮1  查询=DONE（未检索）    命中=[]    多跳=否
```

**第二条轨迹：查了一次就停。**

```text
问题: 温度设成 0 会不会更稳定
  轮1  查询=temperature 0 是否更稳定 大语言模型 确定性    命中=[确定性]    多跳=否
  轮2  查询=DONE（未检索）                               命中=[]          多跳=否
```

**第三条轨迹：一种证据驱动的多轮形状**（构造示例，未实跑；前两条也是未独立复核的历史轨迹）：

```text
问题: Plan A 退役后，它的替代方案有什么配额限制？
  轮1  查询=Plan A replacement     命中=[migration]  多跳=否
      证据=版本 4.2 中 Plan A 被 Plan B 替代
  轮2  查询=Plan B quota           命中=[quota]      多跳=是
      证据=Plan B 的每月配额为 5,000 个任务
```

此夹具的第二条 query「Plan B quota」由第一轮返回的正文中的实体 Plan B 决定；它只是演示数据依赖，不是模型实测，也不证明多轮优于一次检索。

控制流夹具只说明“模型给出 DONE 时宿主可能停止检索”这件事。它不判断模型为什么给 DONE，也不说明首轮强制检索在所有产品里都正确。是否允许跳过检索应由任务契约决定：例如，答案必须来自私有且新鲜的资料时，可让宿主强制走授权后的检索路径；一般知识问答或已验证的无需检索任务，跳过可能是允许状态。不能只靠模型自报信心来满足权限、引用或拒答要求。

## 那什么时候该用多轮

多轮检索更有理由被评估的情形包括：第一轮新证据会改变查询或工具参数；问题需要跨文档聚合；或探索任务要根据中间结果逐步缩小范围。这是提出实验假设的信号，不是保证多轮更准确、更快或更便宜的判据。

- **多跳事实查询**：先找出实体或版本，再据此查替代方案；验证第二步是否真的依赖第一步的结果。
- **跨文档聚合**：比较两份或多份权威材料，需保留每条证据的来源与冲突。
- **探索任务**：目标会随中间发现变化；需让用户确认范围或设置预算。

反过来，若任务契约要求只基于某一权威资料回答，单次检索可能足够；但仍应在目标集上检查证据覆盖、权限过滤和答案质量。更稳妥的结构通常是由宿主规定安全边界与预算，策略可选择 no-retrieval / one-shot / iterative；模型可以提出下一条查询，但不应单独决定授权范围或将失败状态伪装成 DONE。

## 多轮设计要控制哪些边界

旧表不足以推出通用规则。以下是可检验的工程约束，适用与否仍取决于任务契约：

1. **明确何时必须检索。** 若答案必须来自私有、实时或可审计来源，由宿主根据任务类型与授权强制执行检索；若产品允许回答一般知识或无答案状态，可保留跳过路线。不要把检索授权交给模型，也不要只用模型自报信心决定能否跳过来源检查。
2. **把硬预算放在代码里。** 限制最大模型调用数、检索次数、累计输入/输出 token、deadline 与候选总量。每轮分别做授权与 tenant 过滤；`max_rounds` 只限制循环轮数，不能替代成本、超时或访问控制。
3. **每轮记录可诊断字段。** 保存 trace ID、查询（按隐私策略脱敏）、候选 ID 与来源版本、阶段/终态、耗时和目标 endpoint 的原始 usage。区分 DONE、拒绝、截断、工具错误、空结果与预算耗尽；不能将解析失败都记作正常完成。
4. **把答案质量与成本放在同一任务集比较。** 固定语料快照、query、gold evidence、授权边界和最终答案 scorer；比较固定检索、一次改写、模型路由和迭代检索。报告逐题配对结果以及证据覆盖、答案质量、拒答、工具/模型调用数、累计 usage、延迟与错误率。
5. **防止无进展循环与证据污染。** 检查重复查询/重复候选并设置停机策略；将检索文本作为不可信输入，引用时保留来源与版本。查询计划可由模型提出，过滤和执行由宿主裁定。

因此，多轮是一个需要用目标任务验证的策略选项。只有测得它带来的答案或任务收益超过额外调用、延迟、复杂度和权限风险时，才值得保留；单次历史小样本不能替你做这个决策。

```python
# retrieval_policy.py
"""策略轮廓：query rewrite、候选合并与迭代检索的接口边界。

本段依赖调用方提供 client、search 和受权限过滤的 docs；不是独立程序。
本轮用 fake client 核对解析与控制流边界；未连接 provider 或生产检索库。
"""

import json
import re


def parse_queries(text, limit=3):
    """只接受完整 JSON 数组；格式不合约就让调用方回退到原 query。"""
    try:
        queries = json.loads(text)
    except json.JSONDecodeError:
        return []
    if not isinstance(queries, list) or len(queries) > limit:
        return []
    if not all(isinstance(q, str) and q.strip() for q in queries):
        return []
    return [q.strip() for q in queries]


def merge_hits(round_results, k):
    """按传入顺序去重；这不是 RRF，也不代表相关性排名。"""
    if type(k) is not int or k < 1:
        raise ValueError("k must be a positive integer")
    seen, merged = set(), []
    for _round_no, hits in round_results:
        for doc_id in hits:
            if doc_id not in seen:
                seen.add(doc_id)
                merged.append(doc_id)
    return merged[:k]


def arm_b(client, model, question, search, k=5):
    """一次改写后做多路检索；输出顺序由 search adapter 的约定决定。"""
    response = client.messages.create(
        model=model,
        max_tokens=500,
        system="把问题改成最多 3 条检索 query，只输出 JSON 字符串数组。",
        messages=[{"role": "user", "content": question}],
    )
    text = "".join(block.text for block in response.content if block.type == "text")
    queries = parse_queries(text) if response.stop_reason == "end_turn" else []
    queries = queries or [question]
    rounds = [(1, search(query)) for query in queries]
    return merge_hits(rounds, k)


def arm_c(client, model, question, search, docs, max_rounds=3, k=5):
    """每轮把实际证据正文交给 planner；ID 列表本身不是证据上下文。"""
    if type(max_rounds) is not int or max_rounds < 1:
        raise ValueError("max_rounds must be a positive integer")
    rounds = [(1, search(question))]  # 仅当任务策略要求首轮检索时才强制这样做
    merged = merge_hits(rounds, k)
    status = "round_limit"
    for round_no in range(2, max_rounds + 1):
        evidence = "\n".join(
            "[%s] %s" % (doc_id, docs[doc_id])
            for doc_id in merged
            if doc_id in docs
        )
        response = client.messages.create(
            model=model,
            max_tokens=300,
            system="输出 SEARCH: <query> 或 DONE；若格式不符，宿主会报协议错误。",
            messages=[{"role": "user", "content":
                       "问题：%s\n已检索证据：\n%s" % (question, evidence)}],
        )
        if response.stop_reason != "end_turn":
            return merged, "provider_nonterminal"
        text = "".join(block.text for block in response.content if block.type == "text").strip()
        if text == "DONE":
            status = "done"
            break
        match = re.fullmatch(r"SEARCH:\s*(.+)", text)
        if not match:
            return merged, "protocol_error"
        rounds.append((round_no, search(match.group(1).strip())))
        merged = merge_hits(rounds, k)
    return merged, status
```

## 将策略、检索与答案生成拆开

上面的 `arm_c` 是接口轮廓，不是实验复现。它的首轮示例直接用原 query 检索；这与 `arm_b` 的“三条改写 query”条件不同，因此不能说只改了“第一次由谁决定”。需要比较策略时，应把差异写清楚：

| 策略 | 宿主负责 | 要验证的问题 |
|---|---|---|
| 固定一次检索 | 规定检索时机、候选数和权限过滤 | query 与固定管线是否覆盖支持证据？ |
| 单次改写后检索 | 限制改写数与输出协议，查询仍由宿主执行 | 改写对候选覆盖、答案质量和时延的净影响是什么？ |
| 自适应路由 | 按已验证规则或分类器选择跳过、单次或多步 | 路由误判代价、类别分布与总体收益如何？ |
| 迭代多跳 | 将经授权的真实证据回送 planner，限制预算与轮数 | 下一步 query 是否确实依赖前一轮证据？ |

代码中的去重只按到达次序保留第一个 ID；它不计算 RRF、分数融合或相关性重排。`arm_c` 必须把实际文档正文（而非只有 ID）传回 planner，且解析失败或非正常 API 终态不能记为 DONE。即便 planner 返回 DONE，检索规划结束也不等于回答正确：宿主还要根据任务契约决定回答、澄清或拒答，并验证来源、权限和终态。

## 成本与评测口径

如果客户端每轮重发完整消息历史，前面轮次的内容会再次成为请求输入；累计 input usage 可能随轮数增加。服务端状态、prompt cache 与 endpoint 的计量规则会影响实际处理量和费用，所以不能把“重发”直接等同于“重复付费”，也不能把本节旧表中的 `5,660 / 754` 当成可信倍数。测量时要记录每个 API 请求的原始 usage、缓存读写、输出、费用与延迟，并按目标端点的文档解释。

章 3 的“按需取 vs 预加载”记录也只是一组无法独立复核的单次样本；其中约 20% 的交叉位置是样本点间的插值，不是 agentic retrieval 的阈值。多轮策略与预加载比较时，要用同一任务集、质量门槛和 endpoint，逐题核算端到端成本，不能从“资料比例”单独决定。

## 完整可运行代码

```python
"""用 FakePlanner 演示检索策略控制流；不调用模型或外部检索服务。

它验证的是宿主如何区分 DONE、预算终止与协议错误，不验证模型会不会作出好决策，也不生成最终答案。
实跑状态：Python 3.14.7，本轮离线运行。
"""

import re

DOCS = {
    "cache": "缓存：前缀变化可能影响缓存复用；实际行为依赖 endpoint。",
    "rerank": "重排：只能重排候选集合中已经存在的证据。",
}


def search(query):
    """本地确定性 fixture；不是 BM25，也不代表真实检索质量。"""
    q = query.lower()
    found = []
    if "缓存" in q or "前缀" in q:
        found.append("cache")
    if "重排" in q or "候选" in q:
        found.append("rerank")
    return found


def parse_action(text):
    """协议错误与 DONE 分开处理，避免把坏输出静默当成正常停止。"""
    text = text.strip()
    if text == "DONE":
        return ("done", None)
    match = re.fullmatch(r"SEARCH:\s*(.+)", text)
    if match:
        return ("search", match.group(1).strip())
    return ("error", None)


class FakePlanner:
    """只用可预测规则演示状态转移，不模拟模型能力。"""
    def __init__(self, outputs=None):
        self.outputs = iter(outputs) if outputs is not None else None

    def decide(self, question, evidence):
        if self.outputs is not None:
            return next(self.outputs, "DONE")
        content = "\n".join(evidence.values())
        if "缓存" in content and "重排" not in content:
            return "SEARCH: 重排候选集"
        return "DONE"


def run_retrieval(question, planner, must_retrieve, max_searches=3):
    if type(max_searches) is not int or max_searches < 1:
        raise ValueError("max_searches must be a positive integer")

    evidence, events = {}, []

    def execute(query):
        hits = search(query)
        for doc_id in hits:
            evidence.setdefault(doc_id, DOCS[doc_id])
        events.append({"query": query, "hits": hits})

    if must_retrieve:
        execute(question)

    status = "search_budget_exhausted"
    while len(events) < max_searches:
        action, value = parse_action(planner.decide(question, evidence))
        if action == "error":
            status = "protocol_error"
            break
        if action == "done":
            status = "done" if evidence else "done_without_evidence"
            break
        execute(value)
    return {"status": status, "events": events, "evidence": evidence}


if __name__ == "__main__":
    optional = run_retrieval(
        "同一个问题问两遍结果会一样吗", FakePlanner(), must_retrieve=False
    )
    multi_hop = run_retrieval(
        "缓存失效", FakePlanner(), must_retrieve=True, max_searches=3
    )
    malformed = run_retrieval(
        "未知问题", FakePlanner(["可能不用查"]), must_retrieve=False
    )
    print("可跳过检索:", optional["status"], "searches=", len(optional["events"]))
    print("证据驱动多步:", multi_hop["status"], "searches=", len(multi_hop["events"]),
          "evidence=", sorted(multi_hop["evidence"]))
    print("格式错误:", malformed["status"], "searches=", len(malformed["events"]))
```

预期离线输出：

```text
可跳过检索: done_without_evidence searches= 0
证据驱动多步: done searches= 2 evidence= ['cache', 'rerank']
格式错误: protocol_error searches= 0
```

这里 `done_without_evidence` 只说明检索 planner 停止；如果业务要求依据权威资料回答，调用方必须拒绝把它当成功回答。`protocol_error` 应交给宿主做有限重试或安全失败，不能包装成“模型决定不需要检索”。而 `search_budget_exhausted` 表示已达到本地检索次数上限，后续回答是否允许仍由任务契约决定。真实实现还要加入授权过滤、来源版本、模型/API 错误分类、deadline、累计 token/费用预算、审计脱敏和最终答案评测。

## 常见坑

- **把一次小样本当成策略定论。** 旧表缺少可复核输入、轨迹与评分，不能证明模型常常跳过检索或多轮普遍较差。按任务风险与来源要求评测是否允许跳过。
- **把 DONE、协议错误与空结果混成一类。** 记录每轮的查询、候选、来源版本与 API 终态；协议错误不能伪装成正常停机。
- **只限制轮数。** 还需限制总调用数、token/费用、候选量和 deadline；访问控制与租户过滤要在每次检索时执行。
- **把请求重发直接当成重复计费。** 按 endpoint 记录原始 usage、缓存字段、输出、账单和延迟，再解释累计成本。
- **仅凭问题长短决定用单次还是多轮。** 看中间证据是否改变下一步，并在目标任务集上比较最终答案与额外开销。
- **把别处的交叉点当阈值。** 章 3 的约 20% 是无法独立复核单次样本的插值，不是此策略的通用参数。
