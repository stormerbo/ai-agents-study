前面两节讲的都是「怎么把要求说清楚」。这一节讲一个更根本的思路：

> **别把提示词当权限边界。** 设计窄而清楚的操作接口，并由宿主校验身份、对象、状态与授权，让不符合业务约束的请求不能产生副作用。模型仍可能生成无效参数；真正的防护发生在服务端。

poka-yoke（防呆）常用来描述通过流程或结构减少操作错误。软件里的约束只能覆盖你明确建模并在执行路径上验证的部分；模型仍可提出无效请求，宿主必须拒绝它。

这个思路可用于工具接口设计，但要区分两种保证：schema 表达限制的是单次输入形状；服务端策略决定请求是否有权作用于真实对象。本节保留两组历史样本作为探索记录，再用离线例子展示宿主如何拒绝越权/过期/重放请求。

## 历史观察一：危险动作的两种接口

任务：删掉工作目录里的临时导出文件。目录中有三个文件，只有一个是目标。

| 方案 | 接口设计 |
|---|---|
| **A 按路径删** | `delete_file(path)` —— 直接接受任意路径 |
| **B 先看清再按编号删** | `list_files()` 返回文件编号与名称；`delete_file(file_id)` 只接受**上一步返回的编号** |

让用户给出一个**不精确**的文件名（`tmp-export.csv`，而真实文件是 `tmp-export-2026-10-07.csv`）：

| 变体 | 轨迹 | 结果 |
|---|---|---|
| **A** | （没有调用工具） | 「删除是不可撤销的，我不想删错文件。请告诉我完整路径」 |
| **B** | `list_files()` | 「没有找到 `tmp-export.csv`，但有一个名字相近的：`tmp-export-2026-10-07.csv`（编号 f_002）」 |

（2026-10-08 DeepSeek 兼容端点历史 stdout 摘要；逐次请求、响应与评分器未归档，本轮无法独立复核。）

历史摘要称两个变体都没有删除文件，但原始响应缺失，不能确认其完整上下文、工具执行范围或判分过程。这不能推出模型通常会谨慎，也不能证明接口阻止了删除。

该摘要报告 A 请求补充完整路径、B 列出相似候选；由于原始轨迹不可复核，这只能作为设计假设。即使 B 的报告准确，它展示的是发现候选的体验差异，并未测量删除安全性。

候选列表能减少模型猜对象的需要，但 `file_id` 仍是模型可生成的字符串；它不是“连表达都做不到”。真正的保证是宿主验证引用属于当前可信用户/任务、未过期且指向获准对象，并在副作用前执行授权与确认。历史输出里的 `f_002` 还是可枚举编号，未测试猜测或跨会话重放。

一个随机引用只能降低猜测概率，不能代替对象级授权。至少要同时满足：

1. **引用难以猜测且短时有效。** 使用足够随机的服务端引用可降低盲猜风险；这只是防猜测，不是权限。不要把可预测的数据库 ID 当作授权凭证。
2. **引用绑定可信身份、任务与动作。** 身份和任务上下文来自 host，而不是模型参数；每次使用都核对用户、租户、目标对象、动作、有效期与对象当前 ACL。授权必须在资源服务端执行。[OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。

换句话说，引用是缩窄目标的句柄，不是自行授权的证据。像预签名 URL 一样，持有者可能就能使用 bearer capability；保护秘密、绑定策略并检查具体操作都很重要。[AWS S3 presigned URLs](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)。

## 历史观察二：互斥参数的三种修法

一个查询员工的工具，支持按姓名或按工号查询 —— 但两者**互斥**，同时传是无效的。

旧记录的表述是同一类查询。下表的原始请求/响应与 scorer 未归档，且正文只保留一个请求文本却给出 `/3` 汇总，分母口径无法重建；以下数字仅作为未复核的历史摘要：

| 定义 | 历史摘要中的输出 | 当次字段组合 |
|---|---|---|
| **① 不修**：两个普通可选字段 | `{"by_name":"张三","by_id":"E1002"}` | 摘要称 3/3 同时传 |
| **② 写描述**：注明「二选一，不要同时传」 | `{"by_id":"E1002"}` | 摘要称 0/3 同时传 |
| **③ 拆工具**：`find_by_name` / `find_by_id` 各一个 | `find_by_name({"name":"张三"})` | 单次入参不含 `by_id`；整体流程仍可调用两者 |

（历史 stdout 摘要，`deepseek-flash`，2026-10-08；原始响应及三个样本的逐项映射缺失，无法独立重算。）

① → ② 只是改变自然语言约定。③ 让单次工具输入不再含这两个互斥字段，但这不保证模型不会分别调用两个工具；若它们属于同一个业务操作，host 仍须校验整个工作流。历史 0/3 小样本不能比较普遍效果：

拆工具消除了单次参数对象内的这一种组合形状；它没有消除跨调用组合，也没有证明模型行为稳定。更强的保证来自 endpoint 实际执行的 schema 约束与 host 的业务校验。

提示约定可能受模型、场景和上下文影响，但本节没有测量这种漂移。若业务要求恰好一个分支，可用目标 provider 支持的联合结构并由宿主验证；拆工具只限制每个调用的字段集合，不能阻止同一任务调用多个工具。

## 一条可操作的改造清单

拿到一个危险或容易误用的工具，按顺序问：

| 问题 | 如果是「是」 | 例子 |
|---|---|---|
| **它接受任意标识符吗？** | 改成只接受由系统发放的标识符 | `delete_file(path)` → `delete_file(file_id)` |
| **模型需要猜什么吗？** | 补一个查询工具，让它先查后做 | 加 `list_files()` 返回编号与摘要 |
| **有相互依赖或互斥参数吗？** | 用目标 endpoint 支持的联合结构或拆成窄工具；host 校验单次调用和跨调用流程 | `find(by_name?, by_id?)` |
| **动作影响大或难以撤销吗？** | 按风险策略增加人工确认、可恢复机制或干跑；dry-run 不能代替授权 | `preview_delete()` 后再由 host 审批执行 |

相互独立的可选布尔参数可形成 `2^n` 种组合；无效组合的数量取决于业务规则，且通常可由运行时校验拦截。对互斥字段，可用标准 JSON Schema 的 `oneOf` 描述单次对象约束，但具体工具 API 是否支持该子集必须另行确认；即便单次对象有效，host 仍要检查跨调用的业务流程。[JSON Schema Validation 2020-12](https://json-schema.org/draft/2020-12/json-schema-validation)。

## 可运行的宿主侧防护示例

下面的脚本默认只运行内存 fixture，不调用 provider、不触碰真实文件。`list_files` 返回的随机引用只是缩小候选范围；真正的执行仍由宿主按可信身份、任务会话、对象权限和独立审批判定。模型能生成任意字符串，不能把“难猜”说成“不可表达”。

**实跑状态（2026-10-20）：** 本节完整 Python 围栏已在本地离线执行，覆盖猜测/会话/身份/策略/审批/重放/过期/并发/输入/清理场景；可选 Anthropic 适配层仅用 FakeClient 验证协议分支，没有发起 provider 请求。

Anthropic 的 `tool_use.id` 用于把结果配回对应调用，因此宿主应在任何副作用前确认本轮所有 ID 都存在且唯一；不能先执行前一个调用，再发现后一个 ID 无法配对。`end_turn` 也可能没有可展示正文，示例会返回 `completed_without_text`，不把空字符串当成功答案，也不盲目重试；真实应用应由调用方选择是否补充 continuation prompt 或转入人工处理。[Anthropic tool call handling](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls)；[Anthropic stop reasons](https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons)。

```python
# poka_yoke_refactor.py
"""本地演示：用不可猜、短时、按用户+会话绑定的引用缩小删除目标范围。

这只是内存中的教学模型，不操作真实文件，也不是生产授权实现。
"""

import json
import os
import secrets
import threading
import time
from collections.abc import Mapping
from typing import Callable

FILES = {
    "monthly-report-2026-03.csv": "report",
    "tmp-export-2026-10-07.csv": "temporary",
    "user-backup-2026-09-30.zip": "backup",
}

TOOLS = [
    {
        "name": "list_files",
        "description": "列出当前用户有权查看的文件候选；只读，不删除。",
        "input_schema": {"type": "object", "properties": {}, "required": []},
    },
    {
        "name": "delete_file",
        "description": (
            "请求删除本次任务候选列表中的文件。file_id 必须来自本次 list_files；"
            "宿主还会检查当前用户权限，并通过独立确认流程批准后才执行。"
        ),
        "input_schema": {
            "type": "object",
            "properties": {
                "file_id": {"type": "string", "description": "本任务候选列表返回的 opaque id"},
            },
            "required": ["file_id"],
        },
    },
]


class FileService:
    def __init__(self, now: Callable[[], float] = time.time, ttl_seconds: int = 120):
        self.files = dict(FILES)
        self.grants: dict[tuple[str, str, str], dict] = {}
        self.now = now
        self.ttl_seconds = ttl_seconds
        self.lock = threading.Lock()

    @staticmethod
    def may_list(actor_id: str) -> bool:
        # Demo policy only. Production policy comes from the trusted identity/ACL layer.
        return actor_id == "demo-user"

    def may_delete(self, actor_id: str, filename: str) -> bool:
        # Example least-privilege rule: this demo user may delete temporary exports only.
        return actor_id == "demo-user" and self.files.get(filename) == "temporary"

    def list_files(self, actor_id: str, session_id: str) -> str:
        if not self.may_list(actor_id):
            return json.dumps({"error": "forbidden"}, ensure_ascii=False)

        now = self.now()
        with self.lock:
            self.grants = {
                key: grant for key, grant in self.grants.items()
                if grant["expires_at"] > now
            }
            rows = []
            for filename, kind in sorted(self.files.items()):
                file_id = secrets.token_urlsafe(32)
                key = (actor_id, session_id, file_id)
                self.grants[key] = {
                    "filename": filename,
                    "expires_at": now + self.ttl_seconds,
                }
                rows.append({"file_id": file_id, "name": filename, "kind": kind})
        return json.dumps({"files": rows}, ensure_ascii=False)

    def delete_file(
        self,
        actor_id: str,
        session_id: str,
        file_id: object,
        approval_gate: Callable[[str, str, str], bool],
    ) -> tuple[str, bool]:
        if not isinstance(file_id, str) or not file_id or len(file_id) > 256:
            return json.dumps({"error": "invalid_file_id"}), True

        key = (actor_id, session_id, file_id)
        with self.lock:
            grant = self.grants.get(key)
            if grant is None or grant["expires_at"] <= self.now():
                self.grants.pop(key, None)
                return json.dumps({"error": "unknown_or_expired_reference"}), True
            filename = grant["filename"]
            if filename not in self.files or not self.may_delete(actor_id, filename):
                return json.dumps({"error": "forbidden"}, ensure_ascii=False), True
            snapshot = dict(grant)

        # Ask outside the lock; approval is host/UI state and is never a model argument.
        try:
            approved = approval_gate(actor_id, session_id, filename)
        except Exception:
            return json.dumps({"error": "approval_unavailable"}), True
        if approved is not True:
            return json.dumps({"error": "approval_required"}), True

        # Recheck the exact grant, expiry, file and policy after the approval wait.
        # The lock makes this demo's consume+delete atomic within one process.
        with self.lock:
            current = self.grants.get(key)
            if current != snapshot or current["expires_at"] <= self.now():
                self.grants.pop(key, None)
                return json.dumps({"error": "unknown_or_expired_reference"}), True
            if filename not in self.files or not self.may_delete(actor_id, filename):
                return json.dumps({"error": "forbidden"}, ensure_ascii=False), True
            del self.files[filename]
            del self.grants[key]  # one-use in this process; durable retries need an idempotency design.
        return json.dumps({"deleted": filename}, ensure_ascii=False), False

    def close_session(self, actor_id: str, session_id: str) -> None:
        with self.lock:
            self.grants = {
                key: grant for key, grant in self.grants.items()
                if key[:2] != (actor_id, session_id)
            }


def dispatch_tool(
    service: FileService,
    actor_id: str,
    session_id: str,
    name: object,
    arguments: object,
    approval_gate: Callable[[str, str, str], bool],
) -> tuple[str, bool]:
    if not isinstance(arguments, Mapping):
        return json.dumps({"error": "invalid_arguments"}), True

    if name == "list_files":
        if arguments:
            return json.dumps({"error": "unexpected_arguments"}), True
        if not service.may_list(actor_id):
            return json.dumps({"error": "forbidden"}), True
        return service.list_files(actor_id, session_id), False

    if name == "delete_file":
        if set(arguments) != {"file_id"}:
            return json.dumps({"error": "invalid_arguments"}), True
        return service.delete_file(
            actor_id, session_id, arguments["file_id"], approval_gate
        )

    return json.dumps({"error": "unknown_tool"}), True


def run_with_anthropic(
    task: str,
    service: FileService,
    actor_id: str,
    session_id: str,
    approval_gate: Callable[[str, str, str], bool],
    max_rounds: int = 6,
) -> str:
    try:
        return _run_with_anthropic(
            task, service, actor_id, session_id, approval_gate, max_rounds
        )
    finally:
        service.close_session(actor_id, session_id)


def _run_with_anthropic(
    task: str,
    service: FileService,
    actor_id: str,
    session_id: str,
    approval_gate: Callable[[str, str, str], bool],
    max_rounds: int,
) -> str:
    """Optional Anthropic client-tools loop. actor_id/session_id come from the host, never the model."""
    import anthropic

    client = anthropic.Anthropic(
        api_key=os.environ.get("ANTHROPIC_API_KEY") or os.environ.get("ANTHROPIC_AUTH_TOKEN"),
        base_url=os.environ.get("ANTHROPIC_BASE_URL"),
    )
    model = os.environ["VERIFY_MODEL"]
    messages = [{"role": "user", "content": task}]

    for _ in range(max_rounds):
        response = client.messages.create(
            model=model, max_tokens=4000, tools=TOOLS, messages=messages,
        )
        if response.stop_reason == "end_turn":
            text_blocks = [
                block.text for block in response.content
                if block.type == "text" and isinstance(block.text, str)
            ]
            if not any(text.strip() for text in text_blocks):
                return "completed_without_text"
            return "completed: " + "".join(text_blocks)
        if response.stop_reason != "tool_use":
            # max_tokens/refusal/pause/unknown are not successful task completion.
            return f"not_completed: stop_reason={response.stop_reason}"

        calls = [block for block in response.content if block.type == "tool_use"]
        if not calls:
            return "not_completed: tool_use_without_tool_block"

        # Validate the complete response before dispatching any side effect.
        call_ids = [getattr(call, "id", None) for call in calls]
        if any(not isinstance(call_id, str) or not call_id.strip() for call_id in call_ids):
            return "not_completed: invalid_tool_use_id"
        if len(set(call_ids)) != len(call_ids):
            return "not_completed: duplicate_tool_use_id"

        messages.append({"role": "assistant", "content": response.content})
        results = []
        for call in calls:
            content, is_error = dispatch_tool(
                service, actor_id, session_id, call.name, call.input, approval_gate
            )
            results.append({
                "type": "tool_result",
                "tool_use_id": call.id,
                "content": content,
                "is_error": is_error,
            })
        messages.append({"role": "user", "content": results})

    return "not_completed: max_rounds"


def local_checks() -> None:
    service = FileService()
    session_a = secrets.token_urlsafe(24)  # created and retained by the host
    session_b = secrets.token_urlsafe(24)
    files = json.loads(service.list_files("demo-user", session_a))["files"]
    temporary = next(row for row in files if row["kind"] == "temporary")
    backup = next(row for row in files if row["kind"] == "backup")
    approve = lambda actor, session, filename: actor == "demo-user" and filename.startswith("tmp-")

    # Guessed IDs, paths, other sessions and other actors cannot authorize deletion.
    assert service.delete_file("demo-user", session_a, "f_002", approve)[1]
    assert service.delete_file("demo-user", session_a, temporary["name"], approve)[1]
    assert service.delete_file("demo-user", session_b, temporary["file_id"], approve)[1]
    assert service.delete_file("other-user", session_a, temporary["file_id"], approve)[1]

    # A valid reference still needs policy approval; denial leaves the reference usable.
    denied, is_error = service.delete_file(
        "demo-user", session_a, temporary["file_id"], lambda *_: False
    )
    assert is_error and "approval_required" in denied
    assert temporary["name"] in service.files

    # Even a valid reference cannot delete a protected backup.
    protected, is_error = service.delete_file(
        "demo-user", session_a, backup["file_id"], lambda *_: True
    )
    assert is_error and "forbidden" in protected
    assert backup["name"] in service.files

    # Approved target is atomically consumed in this process; replay is rejected.
    deleted, is_error = service.delete_file(
        "demo-user", session_a, temporary["file_id"], approve
    )
    assert not is_error and temporary["name"] not in service.files
    replay, is_error = service.delete_file(
        "demo-user", session_a, temporary["file_id"], approve
    )
    assert is_error and "unknown_or_expired_reference" in replay

    unknown, is_error = dispatch_tool(
        service, "demo-user", session_a, "not_registered", {}, approve
    )
    malformed, is_error2 = dispatch_tool(
        service, "demo-user", session_a, "delete_file", {"file_id": []}, approve
    )
    assert is_error and "unknown_tool" in unknown
    assert is_error2 and "invalid_file_id" in malformed

    service.close_session("demo-user", session_a)
    assert not any(key[:2] == ("demo-user", session_a) for key in service.grants)

    clock = [100.0]
    expiring = FileService(now=lambda: clock[0], ttl_seconds=5)
    exp_session = secrets.token_urlsafe(24)
    exp_file = json.loads(expiring.list_files("demo-user", exp_session))["files"][0]
    clock[0] += 6
    expired, is_error = expiring.delete_file(
        "demo-user", exp_session, exp_file["file_id"], approve
    )
    assert is_error and "unknown_or_expired_reference" in expired

    # Two concurrent attempts with one grant produce at most one in-process delete.
    from concurrent.futures import ThreadPoolExecutor
    raced = FileService()
    race_session = secrets.token_urlsafe(24)
    race_files = json.loads(raced.list_files("demo-user", race_session))["files"]
    race_target = next(row for row in race_files if row["kind"] == "temporary")
    with ThreadPoolExecutor(max_workers=2) as pool:
        outcomes = list(pool.map(
            lambda _: raced.delete_file(
                "demo-user", race_session, race_target["file_id"], approve
            ),
            range(2),
        ))
    assert sum(not failed for _, failed in outcomes) == 1
    print("local checks passed: guess/session/actor/policy/approval/replay/expiry/concurrency/input/cleanup")


if __name__ == "__main__":
    local_checks()
```


运行脚本会执行本地断言。Anthropic loop 是可选适配层；实际删除仍依赖宿主传入的 `approval_gate`。示例的 `actor_id` 必须来自经过认证的 host context，`session_id` 必须由 host 管理，二者都不能从模型参数读取。

内存字典和线程锁只适用于这个单进程 fixture。多副本部署要用共享的、可原子消费的 grant/业务存储，并让授权判断与资源状态变更处于一致的事务边界；文件系统实现还要处理路径规范化、符号链接和并发替换。若使用自包含 MAC/HMAC token，它能保护内容完整性，不能加密其中的文件名，也不会自动实现撤销、一次性消费或并发幂等；这些能力需要期限检查及服务端状态/事务。该 token 也不能替代资源服务端的用户与对象授权。[RFC 2104](https://www.rfc-editor.org/rfc/rfc2104)。

## Schema 校验和接口质量规则

上一节保留的旧 DeepSeek 兼容端点摘要称，`required` 里出现未列在 `properties` 的名称时返回 HTTP 200；该原始响应缺失，本轮未复现。更重要的是，JSON Schema 允许 `required` 列出 `properties` 未声明的名称；在默认 `additionalProperties` 语义下，这不自动构成无效 schema。若工具契约要求每个必填字段都带有明确类型和描述，可以额外把 `required ⊆ properties` 作为本地质量规则，而不要说成 JSON Schema 标准要求。

对 poka-yoke 的启示很直接：**结构能消除的错误才叫结构性防护，剩下的必须由运行时代码拦。** 落到具体动作是两件事 ——

- 注册工具时运行本地质量检查，并另行验证目标 provider 支持的 schema 子集。
- 收到 `tool_use.input` 后，在副作用前校验 JSON 类型、必填/未知字段、业务约束、身份与对象授权。非 strict 模式下不能假设 schema 会替宿主拒绝输入；Anthropic `strict: true` 也仅保证其文档列出的受支持 schema 子集。[Anthropic strict tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/strict-tool-use)。

所以更准确的目标是：通过接口和可执行规则缩小错误空间，再由宿主对剩余无效或越权请求 fail closed；不要把模型的参数表达能力当成安全边界。

## 常见坑

**只做存在性校验就以为防住了。** 可预测编号只证明对象存在，不证明当前用户有权执行该动作。随机引用只降低盲猜概率，不能代替每次请求的对象级授权；即使引用难以猜测，也可能被泄露或从上下文重放。

**把 poka-yoke 理解成「写更严厉的提示词」。** 提示是引导；服务端身份、对象和动作校验才是执行边界。随机引用不是权限本身，也不保证模型不能生成无效参数。

**把小样本误读成模型普遍谨慎。** 本节危险动作记录缺原始响应且未重放；最多说明摘要未记录实际删除。模型不调用工具不是安全保证，host 仍须拦截未授权或未审批的副作用。

**把多个可选字段的组合交给模型猜。** 本节历史摘要的 3/3 数字口径不可重建，不能量化一般错误率。把业务不变量写成 union/互斥校验，并覆盖所有调用路径。

**把拆工具当成完整流程保证。** 拆分能约束单次入参，但同一轮或同一任务仍可能调用多个工具。对“只能选其一”的业务动作，host 需要一个跨调用的状态/幂等边界。

**把候选 ID 当成用户确认。** 目标被列出并不等于用户批准删除；高影响动作应按风险要求确认、支持恢复或隔离执行。dry-run 只能预览，不是执行授权。
