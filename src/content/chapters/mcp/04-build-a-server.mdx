这一节把一个 MCP server 写出来。目的不是让你以后都手写 —— 而是让你知道**一个 server 最少要实现什么**，以及本地与远程两种形态的差别在哪。

## 最少要实现什么

按 2026-07-28 的形态，一个能用的 server 需要四样东西：

**一、一个传输层。** 本地 server 用 stdio：从 stdin 读换行分隔的 JSON，往 stdout 写换行分隔的 JSON。**注意是分隔符，不是长度前缀** —— 一条消息一行，这让它可以直接用 `echo` 手工调试。

**二、一个方法分发。** 按 `method` 字段路由到处理函数。最少要实现 `tools/list`、`tools/call`，以及 `server/discover`。

**三、每请求的版本校验。** 从 `params._meta["io.modelcontextprotocol/protocolVersion"]` 取版本；每个请求还必须带 `io.modelcontextprotocol/clientCapabilities`。必需字段缺失返回 `-32602`，版本不支持返回 `-32022`。**没有握手，所以这是每个请求都要做的事。**

**四、一个错误映射。** JSON-RPC 的错误码（`-32601` 方法不存在、`-32602` 参数错误）+ 协议自定义的错误（版本不支持）。

这四项概括的是本节这个现代 stdio 工具 server 的最小请求路径，不是所有 MCP server 的完整生产要求。协议还规定缓存提示、安全和 transport 等要求；实际 server 还需结合授权、输入/输出验证和副作用设计。完整行为不等于“百行代码即可合规”。

## 本地 server 与远程 server

两者的 JSON-RPC 方法与业务结果复用同一套协议语义，但传输封装并不一样；下面的可运行实现**仅实现 stdio**，不是远程 HTTP server。信任模型也不同：

| | 本地（stdio） | 远程（HTTP） |
|---|---|---|
| 启动方式 | host 拉起一个子进程 | host 连一个 URL |
| 信任假定 | 你装的软件，与你同权限 | 对方控制的端点 |
| 网络 | 不经网络 | 走网络，延迟与可用性都要考虑 |
| 凭证 | 通常靠本地环境 | 需要认证与授权 |
| 升级 | 你决定什么时候升 | 对方决定什么时候变 |

**关键差别在第二行。** 本地 server 跑在你的机器上、用你的权限 —— 它能做的事和你自己写的代码一样多。这不是「更安全」，只是**风险的来源不同**：本地是你自己装的，远程是别人给你的。

所以选择时该问的不是「哪个更安全」，而是：**这个 server 是谁写的、跑在谁的机器上、用谁的权限？** 第 5 节会把这两个风险来源分开讲。

远程 transport 还有独立的协议要求：2026-07-28 Streamable HTTP 每个 JSON-RPC 请求都通过 POST 发送，客户端须带 `Accept: application/json, text/event-stream`、`MCP-Protocol-Version` 与 `Mcp-Method`；`tools/call` 还须带 `Mcp-Name`。服务端须校验 `Origin`，并处理 JSON 或 SSE 响应。上面的 stdio 代码没有实现这些 HTTP 行为、认证或授权，不能直接当成远程 server 部署。

## 一个容易忽略的工程细节：stdout 是协议通道

本地 server 用 stdout 传协议消息，这意味着一件事：**你不能在 server 里随便 print。**

一句调试用的 `print("loading tools...")` 会变成一条无法解析的协议消息，客户端会报解析错误 —— 而错误信息完全不会提示「是因为你 print 了」。这是写本地 MCP server 时最常见的一个坑，而且它的表现（JSON 解析失败）与真正的原因（多了一行日志）之间没有明显联系。

正确做法是把日志写到 **stderr**。几乎所有 stdio 协议的实现都遵循这个约定：**stdout 给协议，stderr 给日志。**

这个坑值得单独记一笔，因为它是「传输层与业务逻辑共享一个通道」的典型症状 —— 而这个设计选择其实是对的（stdio 最简单、最通用），代价是使用者要知道这个约定。

## 实测：一个最小实现的完整往返

手写 server/client 的本地回归跑通了七个场景，包括无状态校验和 MRTR。官方 Python SDK 2.3.0 的双向 stdio 互操作记录来自 2026-10-19 的旧版本代码：SDK client 调用当时的教学 server 的 `tools/list` 与 `tools/call` 成功；教学 client 调用当时的 SDK server 的 `tools/list` 与 `tools/call` 也成功。该历史结果不验证本轮修改后的实现；这份手写代码也不是当前官方 SDK 的替代品。

```text
不带必需的 _meta 字段          → error  Invalid params (-32602)
带错误的协议版本              → error  UnsupportedProtocolVersion (-32022)
带正确版本                    → result {"tools": [...]}
server/discover               → result {"supportedVersions": [...], "capabilities": {...}}
get_weather(北京,明天)         → result {"resultType": "complete", "content": [...]}
未知工具                      → error  Unknown tool: nope (-32602)
未知方法                      → error  Method not found (-32601)

MRTR：
第一次调用 transfer_money      → result {"resultType": "input_required", ...}
补上确认后重调                 → result {"resultType": "complete", ...}
```

（本地代码场景为实跑数据，2026-10-09；SDK 双向互操作为实跑数据，2026-10-19。官方 SDK 测试只覆盖 `tools/list` 和 `tools/call`，不等于整套协议兼容性认证；本节 MRTR 仍由手写实现回归。）

注意第六行和第七行的区别：**未知工具是 `-32602`（参数错误），未知方法是 `-32601`（方法不存在）**。这不是随意的 —— 工具是 `tools/call` 的参数，所以「工具不存在」属于参数问题；而 `resources/subscribe` 不存在是方法层面的问题。分清楚这两类，客户端才能给出有意义的提示。

## 完整可运行代码

下面是一个教学 server 和驱动它的 client。把第一个代码块存为 `mcp_server.py`，第二个存为 `mcp_client.py`，在同一目录运行 `python3 mcp_client.py`。两者通过真正的子进程管道通信。

```python
"""一个最小 MCP server（stdio + 换行分隔的 JSON-RPC 2.0）。

按 2026-07-28 的**无状态**路径实现：
  - 不执行 initialize 握手；每个请求在 _meta 中带协议版本与客户端能力
  - 不支持的版本返回 JSON-RPC error code -32022
  - server/discover 与 tools/list 返回规范要求的缓存元数据
  - 需要 client 输入时返回 input_required，client 用新 request id 携带 inputResponses 与原 requestState 重试

教学实现不是官方 SDK 的兼容性认证；当前代码仅覆盖声明的无状态 stdio 工具路径。
"""
import json, math, sys

SUPPORTED_VERSIONS = ["2026-07-28"]

TOOLS = [
    {"name": "get_weather",
     "description": "查询某个城市某一天的最高气温。",
     "inputSchema": {"type": "object",
                     "properties": {"city": {"type": "string"},
                                    "day": {"type": "string", "enum": ["明天", "后天"]}},
                     "required": ["city", "day"]}},
    {"name": "transfer_money",
     "description": "演示转账确认流程；本示例不会执行真实转账。",
     "inputSchema": {"type": "object",
                     "properties": {"to": {"type": "string"}, "amount": {"type": "number"}},
                     "required": ["to", "amount"]}},
]

TEMP = {("北京", "明天"): 31, ("上海", "明天"): 27}


def error(req_id, code, message, data=None):
    err = {"code": code, "message": message}
    if data:
        err["data"] = data
    return {"jsonrpc": "2.0", "id": req_id, "error": err}


def result(req_id, payload):
    # serverInfo 放在每个成功响应 result 的 _meta 中；它用于识别/诊断，不是安全凭据。
    payload = dict(payload)
    meta = dict(payload.get("_meta", {}))
    meta["io.modelcontextprotocol/serverInfo"] = {"name": "demo-server", "version": "1.0.0"}
    payload["_meta"] = meta
    return {"jsonrpc": "2.0", "id": req_id, "result": payload}


def tool_failure(req_id, message):
    """把可供调用方修正的输入/业务错误作为 tool result 返回。"""
    return result(req_id, {"resultType": "complete", "isError": True,
                           "content": [{"type": "text", "text": message}]})


def handle(req):
    """处理一个请求。注意：这里是**无状态**的 —— 没有 session 对象可查。"""
    if not isinstance(req, dict) or req.get("jsonrpc") != "2.0" or not isinstance(req.get("method"), str):
        return error(None, -32600, "Invalid Request")
    method = req.get("method")
    req_id = req.get("id")
    if isinstance(req_id, bool) or not isinstance(req_id, (str, int)):
        return error(None, -32600, "Invalid Request id")
    params = req.get("params", {})
    if not isinstance(params, dict):
        return error(req_id, -32602, "params must be an object")
    meta = params.get("_meta", {})
    if not isinstance(meta, dict):
        return error(req_id, -32602, "params._meta must be an object")
    version = meta.get("io.modelcontextprotocol/protocolVersion")
    client_caps = meta.get("io.modelcontextprotocol/clientCapabilities")

    # --- 无状态化的核心：版本校验发生在**每个请求**上，而不是握手时 ---
    if not isinstance(version, str) or not version or not isinstance(client_caps, dict):
        return error(req_id, -32602, "Missing required per-request _meta fields")
    if version not in SUPPORTED_VERSIONS:
        return error(req_id, -32022, "Unsupported protocol version",
                     {"requested": version, "supported": SUPPORTED_VERSIONS})

    if method == "server/discover":
        return result(req_id, {"resultType": "complete",
                               "supportedVersions": SUPPORTED_VERSIONS,
                               "capabilities": {"tools": {}},
                               "ttlMs": 300000, "cacheScope": "public"})

    if method == "tools/list":
        # 缓存元数据是 ListToolsResult 的规范字段；public 表示结果不随用户身份变化。
        return result(req_id, {"resultType": "complete", "tools": TOOLS,
                               "ttlMs": 300000, "cacheScope": "public"})

    if method == "tools/call":
        name = params.get("name")
        args = params.get("arguments", {})
        if not isinstance(name, str) or not isinstance(args, dict):
            return error(req_id, -32602, "tools/call requires a string name and object arguments")

        if name == "get_weather":
            city, day = args.get("city"), args.get("day")
            if not isinstance(city, str) or not city.strip() or day not in ("明天", "后天"):
                return tool_failure(req_id, "get_weather 输入无效：city 不能为空，day 只能是明天或后天")
            out = TEMP.get((city, day))
            if out is None:
                # 业务执行失败仍是一个 tool result；用 isError 告诉调用方不要把它当成功数据。
                return result(req_id, {"resultType": "complete", "isError": True,
                                       "content": [{"type": "text", "text": "没有该城市/日期的天气数据"}]})
            return result(req_id, {"resultType": "complete", "isError": False,
                                   "content": [{"type": "text", "text": json.dumps({"temperature": out}, ensure_ascii=False)}]})

        if name == "transfer_money":
            amount, recipient = args.get("amount"), args.get("to")
            if (not isinstance(recipient, str) or not recipient.strip()
                    or isinstance(amount, bool) or not isinstance(amount, (int, float))
                    or not math.isfinite(amount) or amount <= 0):
                return tool_failure(req_id, "transfer_money 输入无效：收款方不能为空，amount 必须是正数")
            # MRTR：结果通过 InputResponses map 回来；这只是教学交互，不是真实转账授权。
            input_responses = params.get("inputResponses", {})
            if not isinstance(input_responses, dict):
                return error(req_id, -32602, "inputResponses must be an object")
            response = input_responses.get("confirm")
            expected_state = json.dumps({"to": recipient, "amount": amount},
                                        sort_keys=True, ensure_ascii=False)
            if response is None:
                return result(req_id, {
                    "resultType": "input_required",
                    "inputRequests": {"confirm": {
                        "method": "elicitation/create",
                        "params": {"mode": "form",
                                   "message": "确认给 %s 转账 %s 元？" % (args.get("to"), args.get("amount")),
                                   "requestedSchema": {"type": "object",
                                                       "properties": {"confirmed": {"type": "boolean"}},
                                                       "required": ["confirmed"]}}}},
                    "requestState": expected_state})
            # 生产系统应对有安全意义的状态做签名/MAC；这里仅演示逐字回传与绑定参数。
            if params.get("requestState") != expected_state:
                return error(req_id, -32602, "requestState missing or does not match this action")
            if response.get("action") != "accept" or not response.get("content", {}).get("confirmed"):
                return result(req_id, {"resultType": "complete",
                                       "content": [{"type": "text", "text": "用户未确认；未执行"}]})
            return result(req_id, {"resultType": "complete",
                                   "isError": False,
                                   "content": [{"type": "text", "text": "教学模拟：确认已通过；本示例未连接转账系统，不会发生真实转账（%s 元给 %s）"
                                                % (amount, recipient)}]})

        return error(req_id, -32602, "Unknown tool: %s" % name)

    return error(req_id, -32601, "Method not found: %s" % method)


def main():
    for line in sys.stdin:
        line = line.strip()
        if not line:
            continue
        try:
            req = json.loads(line)
        except Exception as e:
            print(json.dumps(error(None, -32700, "Parse error: %s" % e)), flush=True)
            continue
        print(json.dumps(handle(req), ensure_ascii=False), flush=True)


if __name__ == "__main__":
    main()


```

```python
"""一个最小的 MCP client：用真正的子进程 + 管道驱动 server。

它验证的是 stdio 传输 + 无状态协议的几个机制点。实跑状态：2026-10-09。
"""
import json, subprocess, sys

SERVER = [sys.executable, "mcp_server.py"]  # 把上面那份 server 存成同目录的 mcp_server.py


class Client:
    def __init__(self):
        self.proc = subprocess.Popen(SERVER, stdin=subprocess.PIPE, stdout=subprocess.PIPE,
                                     text=True, bufsize=1)
        self.n = 0

    def send(self, method, params=None, version="2026-07-28", with_meta=True):
        """每个请求自己带 _meta —— 这就是无状态化的形态。"""
        self.n += 1
        p = dict(params or {})
        if with_meta:
            p["_meta"] = {"io.modelcontextprotocol/protocolVersion": version,
                          "io.modelcontextprotocol/clientCapabilities": {"elicitation": {}}}
        req = {"jsonrpc": "2.0", "id": self.n, "method": method, "params": p}
        self.proc.stdin.write(json.dumps(req, ensure_ascii=False) + "\n")
        self.proc.stdin.flush()
        line = self.proc.stdout.readline()
        return json.loads(line)

    def close(self):
        self.proc.stdin.close()
        self.proc.wait(timeout=5)


def show(label, resp, ok_expect=None):
    if "error" in resp:
        e = resp["error"]
        tag = "error"
        detail = "%s (%d) %s" % (e["message"], e["code"], json.dumps(e.get("data"), ensure_ascii=False)[:90])
    else:
        tag = "result"
        detail = json.dumps(resp["result"], ensure_ascii=False)[:110]
    judge = ""
    if ok_expect is not None:
        judge = "  ✅" if (tag == ok_expect) else "  ❌（期望 %s）" % ok_expect
    print("  %-34s %-7s %s%s" % (label, tag, detail, judge))
    return resp


if __name__ == "__main__":
    c = Client()
    print("=== 1. 无状态化：版本校验发生在每个请求上 ===")
    show("不带 _meta 直接调 tools/list", c.send("tools/list", with_meta=False), "error")
    show("带错误的协议版本", c.send("tools/list", version="2020-01-01"), "error")
    show("带正确版本", c.send("tools/list", version="2026-07-28"), "result")
    print()
    print("=== 2. server/discover：让 server 自己声明 ===")
    show("server/discover", c.send("server/discover"), "result")
    print()
    print("=== 3. tools/call ===")
    show("get_weather(北京,明天)",
         c.send("tools/call", {"name": "get_weather",
                               "arguments": {"city": "北京", "day": "明天"}}), "result")
    show("get_weather(广州,明天)：无数据但调用正常返回",
         c.send("tools/call", {"name": "get_weather",
                               "arguments": {"city": "广州", "day": "明天"}}), "result")
    show("未知工具", c.send("tools/call", {"name": "nope", "arguments": {}}), "error")
    show("未知方法", c.send("resources/subscribe"), "error")
    print()
    print("=== 4. MRTR：多轮往返请求 ===")
    first = c.send("tools/call", {"name": "transfer_money",
                                  "arguments": {"to": "张三", "amount": 5000}})
    show("第一次调用", first, "result")
    r = first["result"]
    print("    resultType = %s" % r.get("resultType"))
    if r.get("resultType") == "input_required":
        print("    ⚠️ server 没有主动发请求，而是把「需要输入」作为返回值交回来")
        print("    客户端补上输入后**再调一次**（发起权始终在客户端）")
        show("补上确认后重调", c.send("tools/call",
                                     {"name": "transfer_money",
                                      "arguments": {"to": "张三", "amount": 5000},
                                      "requestState": r["requestState"],
                                      "inputResponses": {"confirm": {
                                          "action": "accept", "content": {"confirmed": True}}}}), "result")
    c.close()


# ==== 5. 安全边界：host 能看到什么、看不到什么 ====
def security_probe():
    c = Client()
    resp = c.send("tools/list")
    tools = resp["result"]["tools"]
    print()
    print("=== 5. 接入第三方 server：host 能看到什么 ===")
    print("  tools/list 返回了 %d 个工具。host 能看到的核心字段：" % len(tools))
    for t in tools:
        print("    · name=%s" % t["name"])
        print("      description=%s" % t["description"])
        print("      inputSchema=%s" % json.dumps(t["inputSchema"], ensure_ascii=False))
    print()
    print("  host **看不到**的：")
    print("    · 实现是什么（工具名只是声明，代码在对方那里）")
    print("    · 有没有副作用（get_weather 看起来只读，但描述不能作为保证）")
    print("    · 它会怎么处理参数（同一个参数可能触发完全不同的行为）")
    print()
    print("  ⚠️ transfer_money 这个名字暴露了它的危险性；")
    print("     但一个叫 optimize_storage 的工具完全可能有同样的破坏力 ——")
    print("     而 description 是**对方写的**，不是事实。")
    c.close()


if __name__ == "__main__" and len(sys.argv) > 1 and sys.argv[1] == "security":
    security_probe()
```


### 怎么把 server 注册进 host

server 写好了，host 要能发现并拉起它。多数 host 用一份配置文件描述「有哪些 server、用什么命令启动」，形态大致是这样（示例：构造数据，未实跑；字段名随 host 不同）：

```json
{
  "mcpServers": {
    "demo": {
      "command": "python3",
      "args": ["/absolute/path/to/mcp_server.py"],
      "env": {"LOG_LEVEL": "info"}
    }
  }
}
```

三个字段的含义：`command` 是可执行文件（这里用 `python3`）；`args` 是启动参数，server 文件要写**绝对路径** —— 相对路径会随 host 的工作目录变化而失效；`env` 是额外环境变量。**日志不能靠 stdout**：前面讲过 stdout 是协议通道，要写到 stderr。

### host 侧那一跳：tool_use → tools/call → tool_result

这是本章和第 4 章之间的接缝，也是本节的最后一个缺口 —— 上面那个 client 是**测试驱动**，不是 host 的适配代码。真实 host 里它长这样：

MCP 要区分两种失败：畸形请求、未知工具等协议/参数问题用 JSON-RPC `error`；工具已经执行但遇到输入、外部 API 或业务错误时，仍返回 `result`，并把 `isError` 设为 `true`。下面的 host shim 会把这两种状态分别映射到模型 API 的错误结果。MCP 的 `content` 可以是文本、图片、音频、资源链接或结构化内容；示例只连接文本块，生产适配器必须按目标模型 API 保留或映射其他类型。

```python
def handle_tool_use(tool_use, client):
    """模型返回的 tool_use → JSON-RPC tools/call → 回填 tool_result。

    模型看到的东西完全不变：仍是「工具定义 + 调用结果」（第 1 节）。
    变的只是执行这一步跨了一次进程边界。
    """
    resp = client.send("tools/call", {
        "name": tool_use["name"],          # 模型的请求里就带着工具名与参数
        "arguments": tool_use["input"],
    })
    if "error" in resp:
        # 协议层错误翻成 is_error 的 tool_result，而不是抛异常 ——
        # 模型需要看到失败才能换一条路径
        return {"type": "tool_result", "tool_use_id": tool_use["id"],
                "is_error": True,
                "content": json.dumps(resp["error"], ensure_ascii=False)}
    out = resp["result"]
    if out.get("resultType") == "input_required":
        # 这是 MCP 协议层的待处理结果，不是模型工具的最终结果。
        # 交给 host/SDK 的交互策略；获得输入后，用新 JSON-RPC id 重试原请求。
        return {"kind": "mcp_input_required", "tool_use_id": tool_use["id"],
                "request": {"name": tool_use["name"],
                            "arguments": tool_use["input"],
                            "requestState": out["requestState"],
                            "inputRequests": out["inputRequests"]}}
    # 教学桥接器只把文本块传给模型；生产 host 应按模型 API 支持的内容类型映射
    # image/audio/resource_link/embedded resource/structuredContent，不能静默丢失。
    text_blocks = [item["text"] for item in out.get("content", [])
                   if item.get("type") == "text" and isinstance(item.get("text"), str)]
    return {"kind": "tool_result",
            "tool_result": {"type": "tool_result", "tool_use_id": tool_use["id"],
                            "is_error": bool(out.get("isError", False)),
                            "content": "\n".join(text_blocks)}}
```

两个判据值得记住：`tool_use_id` 必须回填成模型那次调用的 id（否则模型对不上是哪一问）；`input_required` 应留在 host 的 MCP 交互层处理，不能伪装成已完成的模型 `tool_result`。拿到输入后，host/SDK 才用新的 JSON-RPC id 重试原 MCP 请求，并在 MCP 完成后把最终结果回填给模型。具体是否请求人工输入、如何呈现或自动提供输入，由 host 与 SDK 的策略决定；MRTR 本身不保证人工审批。

## 为什么要手写一遍

第 13 章给过理由，这里更具体：**因为你要能判断 server 出问题时报的错是什么意思。**

接一个第三方 server，现代路径可能返回 JSON-RPC error code `-32022`（Unsupported protocol version）。它表示请求声明的版本不被接受；接着可用 `server/discover` 查看 server 声明支持的版本，再判断 client 与 server 的兼容范围。

写过之后你会知道：这个错误来自**每个请求**上的 `_meta.protocolVersion` 校验，所以它意味着「你发的版本和对方支持的版本没有交集」。修法也很明确：调 `server/discover` 看对方的 `supportedVersions`，然后改你发的版本。整个过程不需要读对方源码。

**手写一遍的收益不是「以后都自己写」，而是「出问题时你知道该看哪个字段」。** 这与第 11 章手写循环的收益是同一类。

## 怎么调试一个 server

stdio 传输有个很好的性质：**它可以直接手工测。**

```bash
# 一条消息一行，直接喂给 server
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"server/discover","params":{"_meta":{"io.modelcontextprotocol/protocolVersion":"2026-07-28","io.modelcontextprotocol/clientCapabilities":{}}}}' \
  | python3 mcp_server.py
```

返回值就是一行 JSON。这个能力在排查「是协议层的问题还是业务层的问题」时非常有用 —— 如果手工发一条请求能得到正确响应，那问题在客户端；如果不能，问题在 server。

三条排查顺序：

1. **手工发一条 `server/discover`。** 能通说明传输和版本没问题。
2. **手工发 `tools/list`。** 看工具列表是否符合预期（以及有没有变化）。
3. **手工发 `tools/call`。** 看具体调用返回什么。

三步覆盖了绝大多数问题，而且**不需要启动 host**。这也是为什么 stdio 协议在设计上偏向「一条消息一行」—— 它让调试成本降到最低。
## 常见坑

- **在 server 里用 print 打日志。** stdout 是协议通道，一行多余的输出就会导致解析失败，而报错信息不会告诉你原因。日志写 stderr。
- **以为需要 SDK 才能写 server。** JSON-RPC envelope 易读不代表生产实现简单；使用 SDK 可以减少手写协议细节，但仍要校验 SDK 版本、transport 与应用安全策略。
- **只在启动时校验版本。** 无状态之后每个请求都要校验，因为没有握手可以做这件事。
- **把「未知工具」和「未知方法」用同一个错误码。** 前者是 -32602（参数问题），后者是 -32601（方法不存在），客户端需要区分。
- **以为本地 server 更安全。** 它跑在你的机器上用你的权限 —— 风险来源不同，不是更安全。
- **忽略远程 server 的升级节奏。** 本地 server 什么时候升级由你决定；远程的由对方决定，这可能随时改变行为。
