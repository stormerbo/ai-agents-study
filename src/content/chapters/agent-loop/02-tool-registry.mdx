第 4 章讲过工具的描述与 schema。这一节讲**装工具的那个东西** —— 注册表。

它看起来只是一个字典（名字到函数），但一个能用的注册表至少要组织四类职责：

1. **对外给出规格**：把受控的工具描述翻译成模型能读的 schema
2. **对内分发调用**：按本轮允许的名字找到实现
3. **执行前校验与授权**：检查参数，并由宿主按当前主体、租户、资源和策略再次做访问控制
4. **表达结果与失败类型**：区分成功、确定失败、可安全重试与结果未知

schema 与分发很适合集中管理；授权策略可以由注册表提供动作元数据，但不能只凭“名字在表里”就放行。

## 规格与实现要分开

一个常见写法是把两者混在一起：函数签名就是 schema。这在简单场景下能用，但很快会撞墙 —— 因为**模型需要的信息和函数需要的信息不是一回事**。

比如一个查询函数：

```python
def get_weather(city: str, day: str) -> dict:
    ...
```

这个普通函数签名只告诉我们 `day` 是字符串，没有表达它只接受「明天」和「后天」。Python `Literal` 或框架注解有时能映射成 enum；这里展示显式 schema，是为了让模型侧契约与运行时校验可以分别检查，而不是说类型系统无法表达枚举。第 4 章的历史小样本记录 enum 约束下 3/3 合法、自由字符串 0/3；该结果只适用于当时模型、提示和样本，不是通用效果保证。

所以注册表里存的是**两份东西**：给模型看的 schema，和给代码用的函数。它们由同一个条目关联，但不是同一个东西。

## 校验要挡在模型和执行之间

第二件容易被跳过的事：**参数校验。**

为什么仍要在本地校验？普通、非 strict 的工具调用并不保证 provider 会强制执行 schema 中的范围、模式或格式约束；具体行为取决于 endpoint、模型与请求设置。Anthropic 的 `strict: true` 等受支持模式可以约束 schema 子集内的工具输入，但不能替代本地校验、业务规则和授权。模型仍可能给出语义上错误、过期或无权访问的资源标识。

如果直接把它传进函数，你会得到一个 Python 异常 —— 而那个异常对模型毫无意义。执行前还要基于当前调用主体与目标资源做授权，不能把 schema 校验或工具在注册表中存在当成授权。教学流程可以写成：

```python
def execute(principal, name, args):
    entry = registry.get(name)
    if entry is None:
        return known_tool_error("当前未开放该工具")
    problems = validate(args, entry.schema)
    if problems:
        return known_tool_error("参数不合法：%s" % problems)
    decision = authorize(principal, entry.action, resource_from(args))
    if not decision.allowed:
        return known_tool_error("当前主体无权执行该操作")
    if entry.requires_approval and not approval_is_current(principal, entry, args):
        return pause_for_approval()  # 尚未执行；不能伪装成成功
    try:
        return run(entry.fn, args)
    except KnownToolFailure as exc:
        return tool_error_result(str(exc))  # 确定失败，可按策略决定是否重试
    except OutcomeUnknown:
        raise PauseAndReconcile()  # 先查账/下游状态，不把未知结果交给模型重试
```

`known_tool_error(...)` 表示宿主已确定这次没有执行或得到确定失败；回填时应按 provider 协议格式化，例如 Anthropic 的 `tool_result`。授权拒绝、参数错误和下游超时不能混成一种可重试错误；若请求可能已提交但回执丢失，先由宿主暂停并对账，不能让模型自行决定是否重放。

## 失败必须被翻译

第三件事：**把异常统一成模型能读的形态。**

工具失败至少要分成四种结果，而不能只分“预期/意外”：

- **参数或业务拒绝**：宿主已确定工具没有执行，说明哪个规则未通过；只有策略允许时才把它作为工具错误交给模型修正。
- **确定的下游失败**：有可信回执证明操作失败，可回传错误并按重试策略处理。
- **结果未知**：例如写请求超时但接收方可能已提交；暂停模型续跑，按稳定操作键查询/对账，不能直接重放。
- **宿主缺陷或权限异常**：记录最小必要诊断并失败关闭；不要把堆栈或敏感细节泄漏给模型。

是否继续是宿主的控制流决定，不是“循环遇到任何工具错误都必须继续”。只有错误语义已知、权限边界仍成立，而且后续动作安全时，才把可操作的错误结果交给模型。

## 注册表是执行入口，不自动构成授权边界

工具调用把动作描述成有名字和 schema 的调用，但“模型能看见哪些工具”不等于“当前主体被授权做什么”。工具集合可能随租户、用户、任务、远端能力或运行期策略变化；即使工具名在表里，参数指向的资源也必须再次检查。模型提出的是动作请求，宿主仍要验证身份、租户、资源范围、权限、预算和审批。

工具清单可以减少模型能提出的动作形态，但不是授权证明。将数据库函数注册成 `refund_order` 也不代表任意用户都能退款；查询订单工具也不能省略租户过滤。真正的边界来自宿主在每次执行时对主体与资源做的授权判断。

一个真实的坏例子是「万能 SQL 工具」：

```python
Tool("run_sql", "执行任意 SQL", lambda q: db.execute(q))
```

它的动作空间实际上等于整个数据库。第 9 章那套闸门在这里同样适用：**工具定义的粒度就是你的权限粒度。** 与其给一个万能工具加一堆正则检查，不如把它拆成几个语义明确的工具（查询订单、退款），让越界在结构上不可能发生 —— 这正是第 4 章讲的 poka-yoke（可以理解为「防呆设计」：不靠事后检查拦住错误，而是改结构让错误压根无从发生）。

## 一个真实的错误案例：直接抛异常

我第一版实现里的 `execute` 是这样的：

```python
def execute(name, args):
    return REGISTRY[name][1](**args)     # 名字错 → KeyError；参数错 → TypeError
```

跑起来第一个任务就挂了，报的是：

```text
KeyError: 'get_weather_by_city'
```

模型把工具名记长了一点。如果这个异常穿透到循环外面，整轮任务终止；而在修正后的实现里，它收到的是：

```json
{"error": "没有名为 get_weather_by_city 的工具。可用工具：get_weather"}
```

在这次历史运行里，模型下一轮改用了正确工具名；这是一个样例观察，不代表所有模型或提示都能稳定自我修正。可推广的工程结论是：宿主应把确定的工具错误按协议回填，同时用轮数、权限和副作用策略控制后续调用。

## 注册表要不要管并发

第 1 章讲过，一次回复里可以有多个工具调用块，API 不要求宿主按固定顺序执行。注册表可以提供每个工具的并发元数据，调度器再结合本轮实际参数、资源依赖与失败策略决定是否并发。

API 可以在一轮返回多个调用，但不替宿主规定执行顺序。Anthropic 文档列出并发、按出现顺序串行、或混合执行几种选择；工具之间的依赖、副作用和共享状态决定哪种策略合适。

**全串行**最容易推理，适合有顺序依赖或暂时无法证明安全的动作。**并发**能降低互相独立操作的等待时间，但失败时同批其他操作可能已经完成。**混合执行**可以把互不依赖的调用并发成批，并在有顺序依赖的调用前后设置屏障。

“只读即可并行、有副作用就串行”只能当保守启发式，不是充分判据：读请求也可能消耗配额或持有共享资源；两个写入可能在互不重叠资源上安全并发，也可能竞争同一业务状态。应显式判断数据依赖、资源冲突、可交换性、接收方幂等契约、速率限制与取消语义。无法判断时选择串行。

并行执行时，**每个结果必须按自己的 `tool_use_id` 关联**。结果块在回填消息中的排列顺序可以按原请求顺序保持，便于阅读；不要用完成先后或列表位置代替 ID 配对。代码示例还把连续的可并发调用作为一批，遇到串行调用就先等待该批完成，以免把前后有依赖的步骤重排。任何调用执行前都要完成整批协议字段检查（至少包括 ID 存在且唯一），以免先产生副作用、后发现结果无法可靠配对。

### 「可并行」这个标记落在哪

下面的 `parallel_safe` 只是教学调度器的**粗粒度提示**，不是完整的并发安全证明。生产元数据还应明确资源/键范围、顺序依赖、限流、幂等和失败恢复契约。示例把未标注的工具按串行处理，作为本例的保守默认：

```python
entry = {
    "schema": schema,
    "fn": fn,
    "parallel_safe": schema.get("parallel_safe", False),   # 默认 False：不声明就串行
}
```

不能只问“会不会改变外部状态”。至少要检查调用之间是否共享资源、存在先后依赖或非交换写入，以及并发请求是否受接收方契约与限流约束。教程示例仅给无共享状态的只读查询标 `True`，其余默认串行；在实际系统里仍要按具体参数和资源动态判定。

有了这个字段，同一轮里的多个 `tool_use` 就能按它分组调度。下面这段是自包含的调度示例。它先检查整批调用 ID，再做任何工具分发；它**假设工具名、参数 schema 与授权已经由前置宿主门禁验证**，不能直接接收未经校验的原始模型块：

```python
"""按 parallel_safe 分组的教学调度器；串行调用是顺序屏障。

自包含，不需要凭据。
实跑状态：2026-10-12。

调用前仍须由宿主完成 schema 校验与逐次授权；本例只负责 ID 完整性和调度。
"""
import json
import time
from concurrent.futures import ThreadPoolExecutor


class Registry:
    def __init__(self):
        self.entries = {}

    def tool(self, name, fn, parallel_safe=False):
        # 本例约定：True 表示可与同一连续批次中的同类工具并发；生产系统需更细的资源冲突契约。
        self.entries[name] = {"fn": fn, "parallel_safe": parallel_safe}

    def execute(self, name, args):
        return self.entries[name]["fn"](**args)


class DispatchNeedsReconciliation(RuntimeError):
    def __init__(self, failed_ids, partial_results):
        super().__init__("调用结果未知；先对账再恢复：%s" % failed_ids)
        self.failed_ids = failed_ids
        self.partial_results = partial_results


def validate_tool_use_ids(blocks):
    """整批预检 ID，避免副作用发生后才发现结果无法安全配对。"""
    seen = set()
    for block in blocks:
        if not isinstance(block, dict):
            raise TypeError("tool_use 必须是对象")
        call_id = block.get("id")
        if not isinstance(call_id, str) or not call_id.strip():
            raise ValueError("tool_use.id 必须是非空字符串")
        if call_id in seen:
            raise ValueError("tool_use.id 必须在本批次唯一")
        seen.add(call_id)


def dispatch(blocks, registry):
    """校验整批 ID 后，只把连续的并发安全调用组成一批。"""
    validate_tool_use_ids(blocks)
    results = {}
    index = 0
    while index < len(blocks):
        block = blocks[index]
        entry = registry.entries.get(block["name"])
        if entry is None:
            results[block["id"]] = {"error": "工具未开放", "execution": "not_executed"}
            index += 1
            continue

        if not entry["parallel_safe"]:
            try:
                results[block["id"]] = registry.execute(block["name"], block["input"])
            except Exception as exc:
                raise DispatchNeedsReconciliation([block["id"]], results) from exc
            index += 1
            continue

        batch = []
        while index < len(blocks):
            candidate = blocks[index]
            candidate_entry = registry.entries.get(candidate["name"])
            if candidate_entry is None or not candidate_entry["parallel_safe"]:
                break
            batch.append(candidate)
            index += 1

        with ThreadPoolExecutor(max_workers=len(batch)) as pool:
            futures = {
                pool.submit(registry.execute, item["name"], item["input"]): item
                for item in batch
            }
            failed_ids = []
            for future, item in futures.items():
                try:
                    results[item["id"]] = future.result()
                except Exception:
                    # The function may have committed before raising. Do not guess or retry here.
                    results[item["id"]] = {"error": "执行结果未知", "execution": "outcome_unknown"}
                    failed_ids.append(item["id"])
            if failed_ids:
                raise DispatchNeedsReconciliation(failed_ids, results)
    return results


def backfill(blocks, results):
    """按原请求顺序回填协议结果；未知执行结果必须先对账，不能到这里。"""
    validate_tool_use_ids(blocks)
    output = []
    for block in blocks:
        result = results[block["id"]]
        if isinstance(result, dict) and result.get("execution") == "outcome_unknown":
            raise RuntimeError("未知副作用结果不得回填为普通 tool_result")
        item = {
            "type": "tool_result",
            "tool_use_id": block["id"],
            "content": json.dumps(result, ensure_ascii=False),
        }
        if isinstance(result, dict) and result.get("execution") == "not_executed":
            item["is_error"] = True
        output.append(item)
    return output


def slow_read(city):
    time.sleep(0.4)
    return {"city": city, "temp_c": 31}


def write_record(id):
    time.sleep(0.4)
    return {"created": id}


if __name__ == "__main__":
    reg = Registry()
    reg.tool("read_a", slow_read, parallel_safe=True)
    reg.tool("read_b", slow_read, parallel_safe=True)
    reg.tool("write", write_record)          # 没标 → 默认串行

    blocks = [{"id": "t1", "name": "read_a", "input": {"city": "北京"}},
              {"id": "t2", "name": "read_b", "input": {"city": "上海"}},
              {"id": "t3", "name": "write",  "input": {"id": "ORD-1"}}]

    t0 = time.time()
    results = dispatch(blocks, reg)
    print("整轮用时：%.2f 秒" % (time.time() - t0))
    print("回填顺序：%s" % [b["id"] for b in blocks])
    print("结果：%s" % results)
```

实跑输出（2026-10-12）：

```text
整轮用时：0.81 秒
回填顺序：['t1', 't2', 't3']
结果：{'t1': {'city': '北京', 'temp_c': 31}, 't2': {'city': '上海', 'temp_c': 31}, 't3': {'created': 'ORD-1'}}
```

这是 2026-10-12 一次本地运行的观察：两个只读查询各睡 0.4 秒时，查询并发后再执行写入，测得 0.81 秒；全串行的约 1.2 秒是按三个 0.4 秒等待相加的估算，不是另一组实测。它只演示这段 sleep 脚本的调度关系，不代表真实工具延迟或总体性能。`dispatch` 以 `tool_use_id` 关联结果，回填再按请求顺序输出，避免把响应顺序误当调用身份。

## 完整可运行代码

下面的本地注册表示例演示 schema 暴露、按名字分发、最小参数校验，以及已知失败与未知结果的区别。它没有实现身份认证、租户授权或审批；真实宿主需要在每次工具执行前调用相应策略。

```python
"""工具注册表：schema、分发、校验、异常翻译。

纯本地逻辑，不需要凭据。它把第 2 节讲的四件事各实现一遍。

实跑状态：2026-10-09，已跑通。
"""


class KnownToolFailure(Exception):
    """接收方已明确证明操作失败，宿主可向模型回传错误。"""


class OutcomeUnknown(Exception):
    """调用可能已产生效果，但宿主没有可信回执。"""


class PauseAndReconcile(RuntimeError):
    """宿主应暂停 provider 续跑并查询 operation ledger/下游状态。"""


class Registry:
    def __init__(self):
        self.entries = {}

    def tool(self, schema):
        """装饰器：把 schema（给模型看）和函数（给代码用）绑在一起。"""
        def wrap(fn):
            self.entries[schema["name"]] = {"schema": schema, "fn": fn}
            return fn
        return wrap

    def specs(self):
        """对外：只暴露 schema，不暴露实现。"""
        return [e["schema"] for e in self.entries.values()]

    def execute(self, name, args):
        """对内：分发 + 校验 + 异常翻译。三件事都在这里。"""
        entry = self.entries.get(name)
        if entry is None:
            return {"error": "没有名为 %s 的工具。可用工具：%s" % (name, ", ".join(self.entries)), "is_error": True}

        problems = self.validate(args, entry["schema"]["input_schema"])
        if problems:
            return {"error": "参数不合法：%s" % "；".join(problems), "is_error": True}

        try:
            return entry["fn"](**args)
        except KnownToolFailure as exc:
            return {"error": str(exc), "is_error": True}
        except OutcomeUnknown as exc:
            raise PauseAndReconcile("工具结果未知；先对账，不要交给模型盲目重试") from exc
        except Exception as exc:
            # 未知异常可能发生在下游提交之后；先失败关闭并对账。
            raise PauseAndReconcile("宿主异常，工具结果未知；先对账") from exc

    @staticmethod
    def validate(args, schema):
        """教学用根层校验：必填、部分类型、枚举；不是完整 JSON Schema validator。"""
        problems = []
        if not isinstance(args, dict):
            return ["工具输入必须是 JSON 对象"]
        for key in schema.get("required", []):
            if key not in args:
                problems.append("缺少必填字段 %s" % key)
        properties = schema.get("properties", {})
        if schema.get("additionalProperties") is False:
            problems.extend("未知字段 %s" % key for key in args if key not in properties)
        for key, spec in properties.items():
            if key not in args:
                continue
            want = spec.get("type")
            if want == "string" and not isinstance(args[key], str):
                problems.append("%s 应该是字符串，收到 %r" % (key, args[key]))
            if want == "integer" and type(args[key]) is not int:
                problems.append("%s 应该是整数，收到 %r" % (key, args[key]))
            if want == "number" and (isinstance(args[key], bool) or not isinstance(args[key], (int, float))):
                problems.append("%s 应该是数字，收到 %r" % (key, args[key]))
            if want == "boolean" and not isinstance(args[key], bool):
                problems.append("%s 应该是布尔值，收到 %r" % (key, args[key]))
            if want == "object" and not isinstance(args[key], dict):
                problems.append("%s 应该是对象，收到 %r" % (key, args[key]))
            if want == "array" and not isinstance(args[key], list):
                problems.append("%s 应该是数组，收到 %r" % (key, args[key]))
            if "enum" in spec and not any(
                Registry.same_json_value(args[key], allowed) for allowed in spec["enum"]
            ):
                problems.append("%s 必须是 %s 之一，收到 %r"
                                % (key, spec["enum"], args[key]))
        return problems

    @staticmethod
    def same_json_value(left, right):
        """JSON boolean 与 number 不同；Python 中 True == 1，因此不能直接用 in。"""
        if isinstance(left, bool) or isinstance(right, bool):
            return type(left) is type(right) and left is right
        if isinstance(left, (int, float)) and isinstance(right, (int, float)):
            return left == right
        if type(left) is not type(right):
            return False
        if isinstance(left, list):
            return len(left) == len(right) and all(
                Registry.same_json_value(a, b) for a, b in zip(left, right)
            )
        if isinstance(left, dict):
            return left.keys() == right.keys() and all(
                Registry.same_json_value(left[key], right[key]) for key in left
            )
        return left == right
```

## 注册表还要能被观察

最后一件容易漏的事：**注册表是观测点。**

因为它处在「模型想做什么」和「真的做了什么」之间，所以它天然是记录一切的合适位置。至少要记四样：

- **调用了哪个工具、参数是什么**（模型请求的原始形态）
- **执行了没有、花了多久**
- **结果是什么**（成功、可预期失败、还是异常）
- **被拦下的调用和原因**

最后一条尤其重要。如果只记「执行成功的」，你就无法区分「模型没想调那个危险工具」和「它想调但被拦住了」—— 而后者恰恰说明闸门在工作，也是你调阈值的依据。第 9 章讲审计轨迹时给的是同一条理由。

审计记录应能区分模型提出的调用、宿主授权决定、实际执行与最终结果，但不要默认把原始参数完整落日志：其中可能有凭据、个人信息或业务机密。优先记录脱敏后的字段、稳定 hash、结果类别和关联 ID；确需保留原始请求时，限定访问、加密、保留期限与审计用途。

## 常见坑

- **把函数签名当完整 schema 用。** 普通类型注解通常不能表达模型需要的全部范围、格式与描述；Python `Literal` 等机制可以表达部分枚举，运行时 schema 仍应单独定义并校验。
- **把最小示例校验器当成完整 JSON Schema 实现。** 本例只检查根层必填、部分类型、枚举与额外字段；生产环境应使用经过验证的 schema validator，并单独做业务校验与授权。
- **把所有异常都吞掉并交给模型重试。** 只有确定没有执行或确定失败时才回填错误；结果未知、权限异常和宿主缺陷应暂停续跑并对账。
- **提供「万能工具」。** 一个能执行任意 SQL 的工具，等于把整个数据库的动作空间交给模型。工具粒度就是权限粒度。
- **在注册表里藏业务分支。** 同一个工具名在不同任务下行为不同，会让模型无法从描述推断出正确用法。
