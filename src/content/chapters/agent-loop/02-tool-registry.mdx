第 4 章讲过工具的描述与 schema。这一节讲**装工具的那个东西** —— 注册表。

它看起来只是一个字典（名字到函数），但一个能用的注册表要承担四件事：

1. **对外给出规格**：把内部实现翻译成模型能读的 schema
2. **对内分发调用**：按名字找到函数并执行
3. **在校验层拦一道**：参数不合法时不执行
4. **统一失败形态**：把异常翻译成模型能理解的错误结果

四件事里，第 1 和第 2 是显而易见的，第 3 和第 4 才是真正决定健壮性的部分。

## 规格与实现要分开

一个常见写法是把两者混在一起：函数签名就是 schema。这在简单场景下能用，但很快会撞墙 —— 因为**模型需要的信息和函数需要的信息不是一回事**。

比如一个查询函数：

```python
def get_weather(city: str, day: str) -> dict:
    ...
```

函数签名告诉你的类型是 `str`，但模型需要知道的是：`day` 只接受「明天」和「后天」两个值。这个信息在类型里表达不出来，必须写进 schema。第 4 章实测过它的价值：enum 约束下模型 3/3 给出合法值，自由字符串则 0/3。

所以注册表里存的是**两份东西**：给模型看的 schema，和给代码用的函数。它们由同一个条目关联，但不是同一个东西。

## 校验要挡在模型和执行之间

第二件容易被跳过的事：**参数校验。**

为什么不能指望模型给对？第 5 章实测过：schema 里的范围、模式、格式约束**全都不强制**。模型可能给你一个超出范围的数字、一个不存在的 id、一个拼错的枚举值。

如果直接把它传进函数，你会得到一个 Python 异常 —— 而那个异常对模型毫无意义。正确的顺序是：

```python
def execute(name, args):
    entry = registry.get(name)
    if entry is None:
        return error("没有名为 %s 的工具" % name)      # 不抛异常，回一个可读的错误
    problems = validate(args, entry.schema)
    if problems:
        return error("参数不合法：%s" % problems)        # 告诉它哪里错了
    return run(entry.fn, args)
```

注意两个 `return error(...)`：**它们不抛异常，而是回一个结果。** 这是第 4 章那条结论的直接应用 —— 错误要作为工具结果回填给模型，并且要说清原因，否则它不知道该怎么改。

## 失败必须被翻译

第三件事：**把异常统一成模型能读的形态。**

工具的失败有两大类：

- **可以预期的失败**（查不到数据、参数越界、权限不足）→ 应该作为正常结果返回，并在内容里说清原因
- **意外的失败**（网络超时、代码 bug、依赖挂了）→ 应该被捕获，翻译成一条简短说明，**不要让异常穿透到循环外面**

第二类的处理原则是：**循环不应该因为一个工具出错而终止。** 模型收到「这个工具暂时不可用」之后，往往能换一条路 —— 而如果异常直接抛出，你连让它尝试的机会都没有。

但有一个例外必须说清楚：**如果失败意味着「状态未知」，不要急着回填成功或失败。** 第 4 章实测过这个场景：返回「状态未知」时，模型会主动不重试并说明理由。这是对的 —— 因为它意识到重复执行可能有副作用。

## 注册表还有一个隐含职责：它是安全边界

第 9 章讲过计算机使用的动作空间是**开放**的（同一个 click 什么都能点）。工具调用的**动作空间**指的是「模型这一轮所有可能做出的动作的集合」，而它是**封闭**的 —— 模型只能调用注册表里有的东西。

这个差别看起来是工具调用的优势，但它只在一种情况下成立：**注册表里没有危险的工具。**

一个真实的坏例子是「万能 SQL 工具」：

```python
Tool("run_sql", "执行任意 SQL", lambda q: db.execute(q))
```

它的动作空间实际上等于整个数据库。第 9 章那套闸门在这里同样适用：**工具定义的粒度就是你的权限粒度。** 与其给一个万能工具加一堆正则检查，不如把它拆成几个语义明确的工具（查询订单、退款），让越界在结构上不可能发生 —— 这正是第 4 章讲的 poka-yoke（可以理解为「防呆设计」：不靠事后检查拦住错误，而是改结构让错误压根无从发生）。

## 一个真实的错误案例：直接抛异常

我第一版实现里的 `execute` 是这样的：

```python
def execute(name, args):
    return REGISTRY[name][1](**args)     # 名字错 → KeyError；参数错 → TypeError
```

跑起来第一个任务就挂了，报的是：

```text
KeyError: 'get_weather_by_city'
```

模型把工具名记长了一点。如果这个异常穿透到循环外面，整轮任务终止；而在修正后的实现里，它收到的是：

```json
{"error": "没有名为 get_weather_by_city 的工具。可用工具：get_weather"}
```

**下一轮它就用对了。** 这个对比说明了注册表第三件事的价值：把「代码级失败」翻译成「对话级反馈」，模型才有机会自我修正 —— 而这正是第 5 章第 3 节那条结论（带错误信息重试 6/6，空洞重试 0/6）在循环里的应用。

## 注册表要不要管并发

第 1 章讲过，一次回复里可以有多个工具调用块，它们的执行是你可以选择的。注册表在这里有一个容易忽略的职责：**决定同一轮里的多个调用是串行还是并行，以及失败时怎么算。**

三种策略，各有代价：

**全串行。** 一个执行完再下一个。最简单，也最容易推理 —— 副作用顺序确定。代价是慢：三个互不相关的查询要等三倍时间。

**全并行。** 一起发出去。快，但有两个问题：一是如果你有多个副作用工具，顺序就不确定了；二是其中一个失败时，其他的可能已经生效了。

**按工具声明。** 每个工具在注册表里标一个「可并行 / 必须串行」，调度器据此分组。这是实际系统里最常见的做法，代价是你要为每个工具做判断。

选择的关键在这条：**只读工具可以并行，有副作用的工具默认串行。** 因为并行一个副作用操作，等于把「执行顺序」这个信息交给了调度器 —— 而它不知道业务上哪个顺序才对。

还有一个细节：并行执行时，**每个工具的结果仍要按各自的 tool_use_id 回填**（`tool_use_id` 指的是「这一轮里某一次具体调用」的唯一标识，就是响应里 `tool_use.id` 那个值），而且顺序最好保持与请求一致（虽然协议不强制）。保持一致的好处是，日志和轨迹读起来可预测。

### 「可并行」这个标记落在哪

它是注册表条目上的一个字段，和 `schema`、`fn` 并列。要给它显式默认值，因为忘记标注时必须退到安全的一边：

```python
entry = {
    "schema": schema,
    "fn": fn,
    "parallel_safe": schema.get("parallel_safe", False),   # 默认 False：不声明就串行
}
```

判据只有一条：**这个调用会不会改变外部状态？** 会改（写库、发消息、扣款）就是 `False`，纯读（查询、计算、检索）才给 `True`。默认 `False` 意味着「忘记标注」的代价是多等一会儿，而不是写坏数据 —— 这是这里唯一可接受的默认值。

有了这个字段，同一轮里的多个 `tool_use` 就能按它分组调度。下面这段是自包含的：

```python
"""按 parallel_safe 分组的调度：只读并发、副作用串行。

自包含，不需要凭据。
实跑状态：2026-10-12。
"""
import time
from concurrent.futures import ThreadPoolExecutor


class Registry:
    def __init__(self):
        self.entries = {}

    def tool(self, name, fn, parallel_safe=False):
        # parallel_safe 默认 False：不声明就串行 —— 忘记标注时退到安全的一边
        self.entries[name] = {"fn": fn, "parallel_safe": parallel_safe}

    def execute(self, name, args):
        return self.entries[name]["fn"](**args)


def dispatch(blocks, registry):
    """按 parallel_safe 分组：只读的并发发出去，副作用逐个来。"""
    safe, unsafe = [], []
    for b in blocks:
        (safe if registry.entries[b["name"]]["parallel_safe"] else unsafe).append(b)
    results = {}
    if safe:
        with ThreadPoolExecutor(max_workers=len(safe)) as pool:
            futures = {pool.submit(registry.execute, b["name"], b["input"]): b for b in safe}
            for fut, b in futures.items():
                results[b["id"]] = fut.result()
    for b in unsafe:
        results[b["id"]] = registry.execute(b["name"], b["input"])
    return results


def backfill(blocks, results):
    return [{"type": "tool_result", "tool_use_id": b["id"], "content": results[b["id"]]}
            for b in blocks]


def slow_read(city):
    time.sleep(0.4)
    return {"city": city, "temp_c": 31}


def write_record(id):
    time.sleep(0.4)
    return {"created": id}


if __name__ == "__main__":
    reg = Registry()
    reg.tool("read_a", slow_read, parallel_safe=True)
    reg.tool("read_b", slow_read, parallel_safe=True)
    reg.tool("write", write_record)          # 没标 → 默认串行

    blocks = [{"id": "t1", "name": "read_a", "input": {"city": "北京"}},
              {"id": "t2", "name": "read_b", "input": {"city": "上海"}},
              {"id": "t3", "name": "write",  "input": {"id": "ORD-1"}}]

    t0 = time.time()
    results = dispatch(blocks, reg)
    print("整轮用时：%.2f 秒" % (time.time() - t0))
    print("回填顺序：%s" % [b["id"] for b in blocks])
    print("结果：%s" % results)
```

实跑输出（2026-10-12）：

```text
整轮用时：0.81 秒
回填顺序：['t1', 't2', 't3']
结果：{'t1': {'city': '北京', 'temp_c': 31}, 't2': {'city': '上海', 'temp_c': 31}, 't3': {'created': 'ORD-1'}}
```

两个只读查询各睡 0.4 秒，却和一个副作用写入一起在 0.81 秒里跑完 —— 因为查询是并发的，写入单独串行。三个都串行的话，这个数会接近 1.2 秒。`dispatch` 返回的是 `{tool_use_id: result}` 而不是列表，回填时才能靠 id 对齐「哪个结果对应哪次调用」，而不是靠顺序。

## 完整可运行代码

下面这个注册表实现了上面四件事：给模型看 schema、按名字分发、执行前校验、把异常翻译成可读错误。

```python
"""工具注册表：schema、分发、校验、异常翻译。

纯本地逻辑，不需要凭据。它把第 2 节讲的四件事各实现一遍。

实跑状态：2026-10-09，已跑通。
"""


class Registry:
    def __init__(self):
        self.entries = {}

    def tool(self, schema):
        """装饰器：把 schema（给模型看）和函数（给代码用）绑在一起。"""
        def wrap(fn):
            self.entries[schema["name"]] = {"schema": schema, "fn": fn}
            return fn
        return wrap

    def specs(self):
        """对外：只暴露 schema，不暴露实现。"""
        return [e["schema"] for e in self.entries.values()]

    def execute(self, name, args):
        """对内：分发 + 校验 + 异常翻译。三件事都在这里。"""
        entry = self.entries.get(name)
        if entry is None:
            return {"error": "没有名为 %s 的工具。可用工具：%s"
                             % (name, ", ".join(self.entries))}

        problems = self.validate(args, entry["schema"]["input_schema"])
        if problems:
            return {"error": "参数不合法：%s" % "；".join(problems)}

        try:
            return entry["fn"](**args)
        except Exception as exc:                     # 不让异常穿透循环
            return {"error": "工具执行失败：%s" % exc}

    @staticmethod
    def validate(args, schema):
        """最小校验：必填、类型、枚举。真实实现可以用 jsonschema 库。"""
        problems = []
        for key in schema.get("required", []):
            if key not in args:
                problems.append("缺少必填字段 %s" % key)
        for key, spec in schema.get("properties", {}).items():
            if key not in args:
                continue
            want = spec.get("type")
            if want == "integer" and not isinstance(args[key], int):
                problems.append("%s 应该是整数，收到 %r" % (key, args[key]))
            if "enum" in spec and args[key] not in spec["enum"]:
                problems.append("%s 必须是 %s 之一，收到 %r"
                                % (key, spec["enum"], args[key]))
        return problems


reg = Registry()


@reg.tool({"name": "get_weather",
           "description": "查询某个城市某一天的最高气温。",
           "input_schema": {"type": "object",
                            "properties": {"city": {"type": "string"},
                                           "day": {"type": "string", "enum": ["明天", "后天"]}},
                            "required": ["city", "day"]}})
def get_weather(city, day):
    return {"city": city, "day": day, "temp_c": 31}


@reg.tool({"name": "boom",
           "description": "一个会抛异常的工具（用来演示异常翻译）。",
           "input_schema": {"type": "object", "properties": {}, "required": []}})
def boom():
    raise RuntimeError("下游服务超时")


if __name__ == "__main__":
    print("对外暴露的规格（只有 schema，没有实现）：")
    for s in reg.specs():
        print("  %s — %s" % (s["name"], s["description"]))
    print()

    print("=== 四种调用结果 ===")
    cases = [
        ("正常调用", "get_weather", {"city": "北京", "day": "明天"}),
        ("工具名不存在", "get_weather_by_city", {"city": "北京", "day": "明天"}),
        ("枚举值越界", "get_weather", {"city": "北京", "day": "下周三"}),
        ("缺少必填字段", "get_weather", {"city": "北京"}),
        ("工具内部抛异常", "boom", {}),
    ]
    for label, name, args in cases:
        out = reg.execute(name, args)
        mark = "✅" if "error" not in out else "⛔"
        print("  %s %-12s → %s" % (mark, label, out))
    print()
    print("五个结果里有四个是 error，但**没有一个异常穿透出来**。")
    print("模型收到的是可读的说明，而不是 Python 的堆栈。")
```

## 注册表还要能被观察

最后一件容易漏的事：**注册表是观测点。**

因为它处在「模型想做什么」和「真的做了什么」之间，所以它天然是记录一切的合适位置。至少要记四样：

- **调用了哪个工具、参数是什么**（模型请求的原始形态）
- **执行了没有、花了多久**
- **结果是什么**（成功、可预期失败、还是异常）
- **被拦下的调用和原因**

最后一条尤其重要。如果只记「执行成功的」，你就无法区分「模型没想调那个危险工具」和「它想调但被拦住了」—— 而后者恰恰说明闸门在工作，也是你调阈值的依据。第 9 章讲审计轨迹时给的是同一条理由。

四个字段里，参数要记**原始 JSON**，不要记解析后的对象。因为排查时你需要知道模型原本写了什么 —— 比如第 10 章那个把三元表达式塞进参数的案例，只有原始字符串才能看出问题。

## 常见坑

- **把函数签名当 schema 用。** 枚举、范围、格式这些模型需要的信息在类型里表达不出来，必须单独写。
- **参数不合法时直接抛异常。** 模型看不懂 Python 的堆栈，它需要的是「哪个字段、什么原因」。
- **让工具异常穿透循环。** 一个工具挂了不应该终止整轮任务，回一条错误结果让模型换路更划算。
- **提供「万能工具」。** 一个能执行任意 SQL 的工具，等于把整个数据库的动作空间交给模型。工具粒度就是权限粒度。
- **在注册表里藏业务分支。** 同一个工具名在不同任务下行为不同，会让模型无法从描述推断出正确用法。
