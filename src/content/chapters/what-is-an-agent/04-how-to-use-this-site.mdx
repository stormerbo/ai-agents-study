## 路径的结构

整条路径分成 6 个阶段，19 章。划分依据是**依赖关系**，不是难度递增 —— 后一阶段假设前一阶段已经成立。

**为什么是这个顺序**，用几个例子说明：

- **阶段 1 在阶段 2 之前**：不理解上下文是有损的，就无法理解为什么工具返回值要写得那么讲究
- **阶段 3 在阶段 4 之前**：不知道一次 agent 循环会产生多少种失败模式，就没法设计评估指标
- **阶段 4 独立成 4 章**：这是后端工程师的主场，也是大多数教程压缩成「部署」一节的地方

> 路径图里两个缩写先给一句解释，后面各章会展开：
> **RAG**（Retrieval-Augmented Generation，检索增强生成）：它指的是**先检索出外部知识的片段、再拼进上下文**让模型据此作答，而不是指望模型记住它 —— 可以类比成把「数据库查询结果」注入 prompt，而不是让程序凭内存猜。它解决的是「模型的参数里没有你的私有数据」这个问题（阶段 2 的第 6 章）。
> **MCP**（Model Context Protocol）= 一套**把工具与数据源接进模型的标准协议** —— 相当于给模型侧的 USB-C 接口：工具提供方实现一次 server，任何客户端都能用，不必为每家 agent 框架各写一遍适配（阶段 3 的第 14 章）。

## 一章里有什么

每一章由**节**组成。每一节包含固定的几块内容：

| 内容 | 说明 |
|---|---|
| 正文 | 讲解与代码 |
| 自检清单 | 需要你自己回答的问题，附参考答案 |
| 延伸阅读 | 外部资源，每条写明「为什么值得读」 |
| 动手实验 | 可以在站内跑的代码（见下方说明） |

### 关于自检清单：请先自己回答

自检清单的答案默认折叠。**强烈建议先自己想，再展开对照。**

这不是形式主义。LLM 领域有一个特点：**读的时候觉得都懂，动手时发现全是坑。** 自检清单是检测这个落差最廉价的手段 —— 如果你答不上来，说明那一节需要再看一遍，而不是说明问题太难。

### 关于答案的「依据标注」

每条自检答案下面都有一行标注，说明这条内容的依据类型：

| 标注 | 含义 |
|---|---|
| **有文档依据** | 官方文档或规范里明确写着，附可点的来源链接 |
| **经验判断** | 作者基于工程经验的推理，不是可查证的事实 |
| **未能核实** | 无法确认，但认为值得保留，会说明为什么核实不了 |

这个机制的存在有一个很实际的理由：**AI 领域的技术细节变化极快，而错误的断言与正确的断言在语气上没有任何区别。** 如果不标注，你无法分辨「这是官方文档写着的」和「这是作者的经验之谈」，而这两者被误认的代价完全不同。

所以在你看到「经验判断」时，请保持正常的怀疑；看到「有文档依据」时，可以直接去点那个链接核实。

**一条自检项在数据里长这样**（以第 1 章的一条为例，字段直接来自站内的数据文件）：

```json
{
  "id": "token-estimation",
  "question": "为什么不能按字符数估算 token？",
  "answer": "因为字符与 token 的换算关系随文本类型剧烈变化……",
  "basis": "documented",
  "sourceIds": ["claude-models-overview"],
  "note": "「中文 token 密度更高」是共识，但没有官方给出的确切倍数，因此只做定性描述。"
}
```

看懂这五个字段，也就看懂了本站的准确性机制：`answer` 是可以错的（它是作者的理解），
`basis` 说明这条依据有多强，`sourceIds` 指向可点开核实的来源，而 `note` 专门写**哪里没能核实**。
测试会强制这些字段合规 —— 标成「有文档依据」却没有来源，构建立刻失败。

## 关于动手实验

**站内实验已经可以用了。** 入口在顶部导航的「实验」，或者从任意章节的实验卡片点进去。

用法很简单：填入你自己的 API Key，直接运行。关于 Key 的处理方式，有三件事你要知道：

- Key 只存在**你的浏览器**里，不上传
- 运行时它经本站服务器**转发**给模型厂商 —— 服务端不存储、不记录日志
- 建议用一把**限额的、专用的** Key，用完随时吊销

第一次进去时把**厂商、端点地址、模型名、API Key** 填一遍。这四项是**成套保存**的，
下次打开自动恢复，不用重填。如果你用的是第三方中转平台，把端点地址改成它的地址即可。

### 实验会展示完整轨迹，而不只是最终答案

> **轨迹**在这里指实验记录下的完整事件序列：每一步给模型发了什么、它回了什么、用了多少 token、为什么停。它不是「运行日志」的同义词 —— 关键差别是它保留了**每一步模型看到的上下文**，那是复现问题的唯一依据（详见第 0 章第 2 节的定义与一份示例）。

这是它与「跑个 demo 看看效果」的区别。每个实验都会给出：

| 看到什么 | 为什么重要 |
|---|---|
| 模型的**思考过程**（可展开） | 看清它在回答之前做了什么判断 |
| 每一次**工具调用**及参数 | 理解「模型只生成意图，不执行任何东西」 |
| **token 用量**与停止原因 | 建立成本直觉，识别截断 |
| **原始事件**（协议层，折叠在最后） | 核对「厂商实际发的」与「语义层展示的」是否对得上 |

最后一项是特意保留的。多数教程只给你看结果，但要建立判断力，你需要能下钻到协议层 ——
尤其是当输出不符合预期时，那里是唯一可靠的依据。

## 内容的生产方式与局限

这一条很重要，请认真看。

**章节正文与大纲由 AI 辅助撰写，外部资源经过核实 —— 但「核实」是分级的。**

具体来说，本站做了这些：

| 做了什么 | 怎么做的 |
|---|---|
| 链接可用性 | 有巡检脚本定期检查所有外链（`scripts/check-links.mjs`） |
| 仓库状态 | 用 GitHub API 查过归档状态与最后更新时间 |
| 具体数字 | 要么标注来源与核实日期，要么不写 |
| 代码示例 | 凡是跑过的会标明「实测」；没跑过的会标明「未实跑」 |

**没有做什么：**

| 没做 | 后果 |
|---|---|
| 逐条核实所有技术论断 | 标「经验判断」的部分可能有误 |
| 全部代码在官方端点实跑 | 部分示例只做过语法检查 |
| 人工专家审阅 | 没有任何人逐字校对过 |

**你应该怎么对待这些内容**：把本站当作**一条有组织的路径和一份判断依据**，而不是权威参考。涉及具体 API 细节、版本行为、数字的地方，**第一手资料永远是官方文档**。

## 关于「实测数据」

你会在正文里看到标注为「实测」的数据块，比如：

```text
#1  三味咖啡
#2  三味咖啡
#3  三咖小馆        ← 第三次不同
（实测数据，deepseek-flash，2026-09-24）
```

这类数据有几个特点，值得你知道：

1. **它们来自真实调用**，不是从文档里抄的，也不是编的
2. **它们标注了模型与日期**，因为结论可能随模型变化
3. **它们可能与你自己的结果不同** —— 不同模型、不同端点、不同时间都可能不一样

第 3 点尤其重要。**当实测数据与你的结果冲突时，以你的为准** —— 因为那是你最关心的场景。我在正文里会尽量给出复现脚本，方便你自己跑一遍。

## 一些阅读约定

**技术术语保留英文原词。** 原因很实际：你要读的文档、论文和报错信息都是英文。把术语翻成中文反而会增加你搜索时的阻力。术语第一次出现时会给出中文解释。

**代码以 Python 为主。** 因为官方 SDK、论文复现代码、主流 agent 框架的示例大多是 Python。涉及浏览器、Node、MCP Server 时会补 TypeScript。

**每章都有一个「后端视角对照」小节**，明确列出哪些已有经验可以直接迁移、哪些直觉会失效。这是本站与其他教程最大的区别 —— 它假设你**已经是一个有经验的工程师**，而不是从零开始的学生。

## 你也可以复核这里的每个数字

本站所有「实测数据」都有一个共同前提：**你可以自己复现。**

采集脚本的模式见 `scripts/verify-api.mjs`：从 `.env.local` 读凭据、全程不打印 Key、把原始响应落到 `verify-output/`。内容体量（每节的中文与说明文字字数）也做成了脚本 —— `node scripts/content-stats.mjs` 会按节列出四个指标，验收标准写在 `AGENTS.md` 里。

之所以把它写进这一节，是因为**这套路径的可靠性依赖于「你能验证它」**。任何一个数字，如果读者只能选择信或不信，它就不该出现在教程里。

## 两分钟拿到第一把 Key

零 AI Agent 经验的第一个卡点就是这一步。按顺序做完，你就会有一个能用的 Key 和一份能直接填进实验页的配置。

**第 1 步：选一家。** 三家任选其一，第 1 章的实验都支持。差别只在门槛：

| 厂商 | 控制台 | 你要拿到的 Key | 免费额度 |
|---|---|---|---|
| Anthropic（Claude） | platform.claude.com | `sk-ant-...` | 通常需要绑卡/预充值，额度按量计费 |
| DeepSeek | platform.deepseek.com | `sk-...` | 按量计费，起步门槛低（本站实测用的就是它的兼容端点） |
| OpenAI | platform.openai.com | `sk-...` | 需要绑卡 |

> 上面三家的「免费额度」我**没有逐一实测**，它们随地区与活动变动 —— 以你打开控制台时看到的为准。真正不变的是下一件事。

**第 2 步：建一把专用的、限额的 Key。** 不要用生产环境的 Key，也不要复用它。在控制台里新建一把，命名成 `study-site` 之类；多数控制台支持设月度上限或用完即吊销。原因很直接：这把 Key 会被你用在本站的实验页里，也可能被你复制进脚本。

**第 3 步：复制一次，存到安全的地方。** Key 通常**只在创建时显示一次**，关掉页面就看不到了。存进你的密码管理器，或直接写进本地的 `.env.local`（**不要提交进 git**）。

**第 4 步：把四项配置填进实验页（或在脚本里设成环境变量）。** 这四个值必须成套匹配，混搭是新手最常见的失败：

```text
厂商      Anthropic / DeepSeek / OpenAI        ← 决定用哪家的请求格式
端点地址  https://api.anthropic.com           ← 官方端点
          https://api.deepseek.com/anthropic  ← 兼容端点（形状像 Anthropic，行为不一定像）
模型名    deepseek-flash / claude-sonnet-5 …   ← 必须是端点真的支持的名字
API Key   sk-ant-... / sk-...                 ← 第 3 步复制的那串
```

（示例：构造数据，未实跑 —— 具体模型名请以你控制台上列出的为准。`deepseek-flash` 是本站实测用过的名字。）

**判断四项是否配对成功**：发一次最简单的请求（哪怕只是「只回复两个字：收到」）。成功会返回一段 JSON，里面有 `usage.input_tokens` 与 `stop_reason`。失败则对照：

| 报错关键词 | 大概率是 | 怎么办 |
|---|---|---|
| `AuthenticationError` / 401 | Key 错了，或这一家不认这种认证头 | 重新复制 Key；兼容端点通常用 `x-api-key` 而不是 `Authorization: Bearer` |
| `invalid model`/「支持的模型名是 ……」 | 模型名与端点不匹配 | 直接用报错里列出的名字 |
| `insufficient balance`/ 402 | 账户没钱了 | 充值，或先换一家有免费额度的 |
| 连接超时 | 端点地址写错（少了路径，或缺 `https://`） | 对照第 4 步的表 |

## 现在可以开始了

如果你还没有 API Key，按上面四步去申请一个（Claude、DeepSeek、OpenAI 任一都可以，第 1 章的实验都支持）。**注意申请一个限额的、专用的 Key，不要用生产环境的。**

准备好之后，从第 1 章开始。第一章会带你完成第一次调用，并且告诉你**为什么那次调用会花钱、会失败、会在什么地方让你意外**。
