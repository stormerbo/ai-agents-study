有些任务只能通过图形界面完成，或者现有 API、CLI、浏览器可访问性接口不足以覆盖目标操作。视觉 GUI 自动化是其中一条路线，但“computer use”不是单一实现：本节先讨论一个**自建截图/坐标适配器**，再把它与当前厂商提供的 computer-use / browser-use 工具集区分开。

在本节自建适配器中，程序把合成界面截图发给模型，模型返回 JSON 动作提议；宿主若要真正操作界面，还必须自行解析、校验、授权并执行动作，再把结果反馈给模型。本文下面的 820×520 示例只请求动作提议，**不执行点击或输入，也不构成完整的 computer-use agent loop**。

因此，本节的“三点”是这个适配器设计与语义化业务 API 的对照，不是所有 computer-use 产品的通用定义。Anthropic 当前 computer-use toolset 由多个成员工具组成，宿主执行调用并回传结果，也支持按顺序执行的批量动作；browser-use 则可以同时使用页面结构、可访问性树、元素引用和截图坐标。选择接口应以任务与可用能力为准。参见 [Computer use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool)、[Browser use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/browser-use-tool) 与 [Tool combinations](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-combinations)。

## 区别一：观测是像素，不是结构化数据

业务 API 可以返回为应用设计的字段与状态；本节的自建适配器只把一张位图作为模型观测。历史样例使用 820×520 合成界面，PNG 为 8,187 字节，2026-10-09 的端点记录该请求输入为 382 token。**这些数字描述该次历史请求与该自建适配器，不代表所有视觉工具的输入形式或当前 token 用量。**

模型需要从像素中识别控件与布局，识别结果可能出错；这不是说所有 GUI 工具都只能看像素。以 Anthropic Browser use 为例，模型可先读页面可访问性树并通过元素引用定位，遇到页面结构不可用的区域再回退到截图与坐标。

## 区别二：动作是通用原语，不含领域语义

工具调用里，每个工具都是为任务定制的：`create_user(name, email)` 这个名字本身就携带了「创建用户」这层意思，而且它的参数是类型化的。

本节自建 JSON 协议只定义了三个动作：

```json
{"action": "click", "x": 280, "y": 171}
{"action": "type", "text": "Zhang San"}
{"action": "done"}
```

这些只是示例适配器的原语。它们不能表达所有界面操作；而且点击的业务含义由具体界面、坐标、当前状态与宿主权限共同决定。单看 `click` 字段，无法判断它将触发普通导航还是重要副作用。另一方面，业务 API 也不天然安全：宽权限的 `execute_sql` 或 `run_shell` 同样可能造成广泛影响。**风险边界取决于宿主实际暴露和授权的能力，而不是“API 封闭、GUI 开放”这样的二分法。**

Anthropic 当前 computer-use toolset 也不只是 click/type：文档列出截图、缩放、鼠标、键盘、等待等成员动作，并允许宿主按序执行一个批次；因此下方三个动作不能代表该工具集。

## 区别三：动作结果不等于业务后置条件

这是三点里最容易被忽略的一点：**适配器回报动作被接收或执行，不等于应用业务目标已经达成。**

失败信号的形态取决于协议与宿主实现。API 可能返回 HTTP 错误、工具错误结果或业务拒绝；computer-use/browser-use 宿主也可以将执行失败作为 `is_error` 等结果回传。反过来，调用成功也不能证明“用户已创建”或“付款已完成”。应区分传输/工具执行结果与独立的业务后置条件，并针对不确定的外部效果设计查询或对账。

对本节自建适配器而言，单个 `click` JSON 提议本身不含执行结果。要判断界面是否变化，宿主还要执行并获取新观测；有变化也未必证明目标成功，没有变化则可能有多种解释。具体反馈能力取决于适配器和应用。

## 那为什么还要用它

这些工程限制会提高设计与维护成本。什么时候仍值得考虑界面自动化？

因为有一类任务**真的没有 API**：

- 内部的老后台系统，只有网页界面，没有对外开放的接口
- 第三方 SaaS 的免费版不给 API 权限
- 桌面软件（财务、设计工具）根本没有 HTTP 接口
- 一次性任务：只是要把 20 条记录录进一个表单，为它单独写一个 API 集成不值当

这些场景的共同点是：**要么没有可用接口，要么写集成的成本高于点界面的成本**。在这种前提下，视觉 GUI 自动化可以作为一种自动化路线；若有稳定 API、CLI、浏览器 DOM/可访问性接口或现成集成，通常应先比较这些路线的可靠性、权限和维护成本。

有时 API 技术上可用，但一次性或低频任务未必值得投入集成；也可以比较人工操作、浏览器结构化自动化与 GUI 自动化。维护成本取决于目标站点、权限和变化频率，不能笼统断言视觉方案总比 API 更省维护。

所以这一章的定位不是默认推荐视觉自动化，而是帮助你在 API、CLI、页面结构化接口与 GUI 自动化之间，按任务可达性、授权边界、稳定性和维护成本做选择。

## 从动作提议到完整循环还缺什么

本节的 API 样例停在“模型提出动作”。一个真正运行的 agent loop 还需要宿主逐步完成：解析并验证动作结构、检查坐标/文本长度等约束、按授权策略决定是否允许执行、在隔离环境执行、收集成功或失败结果，并将适当的新观测送回模型。对可能产生重要副作用的动作，还要在执行前实施审批与范围限制。

当前厂商工具集的执行协议也不应被简化成“每个动作都重新发送整张截图”：Anthropic computer-use 文档支持一轮返回按序执行的动作批次，并说明通常在批次后观察；browser-use 可以返回页面结构或截图。是否需要新观测、使用哪种观测，取决于前一步会否影响后续决策和工具提供的反馈能力。

旧版第 9 章汇总曾记录合成表单任务为 5 步、5 次往返、每步 473/758/1053/1356/1661 token、总计 5,301，并标注三次运行均成功。但逐次 provider 响应和可复算的业务判分材料未留存；本节代码也不能复现那段执行。因此这里只保留为**未经独立复核的历史摘要**，不据此宣称 3/3 成功或推导一般成本曲线。每步 token 数与合计仅是存档记录，不作为可复现结果。

## 三点区别分别落在哪一节

- **本节自建适配器以截图为输入** → 第 2 节的观测-动作循环（何时需要新鲜观测）、第 3 节（为什么偶尔会点空）
- **坐标动作缺少业务语义** → 第 4 节的权限与活动范围（宿主权限与动作风险）
- **动作结果不等于业务后置条件** → 第 3 节与第 4 节（观测与确认点设计）

读后面几节时如果觉得某条结论有点突然，回到这张对照上通常能对上。

这三条是本节自建适配器的观察，不是 GUI 自动化的统一理论。实际系统的可靠性由观测接口、动作与权限设计、宿主执行/反馈、应用状态判据共同决定。

## 接入真实屏幕前的三项校准工作

上面的历史坐标提议来自 PIL 合成界面；本节截图与换算示例不能证明真实桌面环境的命中率。若要接入实际 GUI，需要验证捕获与注入能力、校准坐标映射，并在受限环境中检查应用后置条件：

**一，把屏幕截下来。** `mss` 是最轻的选择，几行就够：

```python
import mss
from PIL import Image

def grab(region=None):
    """抓主屏（region=None）或指定矩形，返回 PIL Image。"""
    with mss.mss() as sct:
        shot = sct.grab(region or sct.monitors[1])   # monitors[1] = 主屏
        return Image.frombytes("RGB", shot.size, shot.rgb)
```

**二，把动作注进去。** `pyautogui` 负责点击与敲键：

```python
import pyautogui

def click_screen(x, y):
    pyautogui.moveTo(x, y, duration=0.05)   # 坐标语义需按 OS、显示缩放与库文档确认
    pyautogui.click()

def type_text(text):
    pyautogui.typewrite(text, interval=0.02)   # 仅 ASCII；中文要配 pyperclip 粘贴
```

`pyautogui` 与 `mss` 的坐标范围和显示缩放语义需要结合目标 OS、窗口模式及库版本核实；在部分高 DPI 环境里，截图像素与注入坐标可能存在缩放差异。应以已知标记点校准映射，不要把 Retina 的 2× 比例当成跨平台规则。

**三，校准坐标映射。** 截图与自动化库使用的坐标系可能因操作系统、显示缩放、窗口捕获范围和库实现而不同；不要假设一个固定 DPR 换算适用于所有环境：

```python
def to_screen(x_shot, y_shot, shot_size, origin_xy, win_logical_size):
    """截图坐标 -> pyautogui 屏幕坐标。
    origin_xy: 抓取区域左上角在逻辑屏幕上的位置（窗口原点）
    win_logical_size: 该区域在逻辑屏幕上的宽高"""
    sx = win_logical_size[0] / shot_size[0]   # 用校准后的逻辑窗口尺寸与截图尺寸求比例
    sy = win_logical_size[1] / shot_size[1]
    return origin_xy[0] + x_shot * sx, origin_xy[1] + y_shot * sy
```

把一个**假设的比例映射**算出来看（纯算术示例，不是实际设备测量）：截图为 `2000×1400`，经校准后对应的目标窗口坐标尺寸为 `1000×700`，原点为 `(200,150)`。模型在截图上给点 `(1600,800)`：

```text
正确：按已校准比例缩放并加原点 -> (1000, 550)  偏差   0 px
漏掉比例缩放但加原点           -> (1800, 950)  偏差 894 px
做了缩放但漏掉原点             -> ( 800, 400)  偏差 250 px
缩放与原点都漏掉               -> (1600, 800)  偏差 650 px
```

历史记录报告的最近登记元素中心距离在 1.3 到 2.6 px；它不是目标点击误差。**而坐标系错一次可能造成数百像素偏移**。接入真实屏幕时，应先校准截图与屏幕坐标变换，再单独测目标命中和业务后置条件。

> 实跑状态：`mss` 与 `pyautogui` 的调用片段是伪代码，本环境没有这两个依赖或可授权的 GUI 会话。比例映射公式与数值表是独立的纯算术示例，不代表实机截图/输入验证。首次接入需按目标 OS、显示设置和库版本校准坐标，并在隔离环境通过无副作用标记点验证后置条件。
## 可运行的动作提议请求

这段代码渲染一张合成界面并请求模型给出动作提议；它不会执行点击、输入或任何 UI 副作用。运行需要 Pillow、macOS 示例字体路径（或替换为本机字体）和 `VERIFY_MODEL`、`ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN` 环境变量。API Key 不要写入源码或输出。`max_tokens=400` 只是单次响应上限，不保证模型一定返回合法或完整 JSON。

```python
"""最小请求：把合成截图发给模型并打印动作提议，不执行该动作。

实跑状态：请求形态曾于 2026-10-09 在 deepseek-flash 端点调用；原始逐次响应未留存，模型输出不可据此重现。
"""
import base64
import json
import os
import urllib.request
from io import BytesIO
from PIL import Image, ImageDraw, ImageFont

FONT = "/System/Library/Fonts/Supplemental/Arial.ttf"
W, H = 820, 520
BUTTON = (60, 380, 240, 432)          # Create 按钮的区域


class RejectRedirects(urllib.request.HTTPRedirectHandler):
    """Keep a credentialed API request from following an unverified URL."""
    def redirect_request(self, req, fp, code, msg, headers, newurl):
        return None


def open_api(req, timeout=120):
    opener = urllib.request.build_opener(RejectRedirects())
    return opener.open(req, timeout=timeout)


def render(focus=None, value=""):
    img = Image.new("RGB", (W, H), "white")
    d = ImageDraw.Draw(img)
    d.rectangle([0, 0, W, 64], fill=(240, 244, 250))
    d.text((60, 24), "NEW USER FORM", fill=(20, 30, 50), font=ImageFont.truetype(FONT, 20))
    d.text((60, 110), "Name", fill=(90, 100, 115), font=ImageFont.truetype(FONT, 14))
    d.text((60, 210), "Email", fill=(90, 100, 115), font=ImageFont.truetype(FONT, 14))
    d.rectangle([60, 150, 500, 196], outline=(60, 120, 220) if focus == "name" else (170, 180, 195),
                width=3 if focus == "name" else 1)
    d.rectangle([60, 250, 500, 296], outline=(60, 120, 220) if focus == "email" else (170, 180, 195),
                width=3 if focus == "email" else 1)
    d.text((72, 164), value, fill=(20, 20, 20), font=ImageFont.truetype(FONT, 18))
    d.rectangle(list(BUTTON), fill=(30, 110, 220))
    d.text((BUTTON[0] + 26, BUTTON[1] + 15), "Create", fill="white", font=ImageFont.truetype(FONT, 18))
    buf = BytesIO()
    img.save(buf, format="PNG")
    return buf.getvalue()


SYSTEM = "\n".join([
    "你是一个通过截屏操作界面的 agent。你必须只输出一个 JSON 对象，不要解释。",
    '{"action":"click","x":<整数>,"y":<整数>} 或 {"action":"type","text":"..."}' + ' 或 {"action":"done"}',
    "坐标以截图左上角为原点。",
])


def step(prompt, focus=None, value=""):
    png = render(focus, value)
    body = json.dumps({"model": os.environ["VERIFY_MODEL"], "max_tokens": 400, "system": SYSTEM,
                       "messages": [{"role": "user", "content": [
                           {"type": "text", "text": prompt + "\n这是当前屏幕："},
                           {"type": "image", "source": {"type": "base64", "media_type": "image/png",
                            "data": base64.b64encode(png).decode()}},
                       ]}]}).encode()
    req = urllib.request.Request(
        os.environ["ANTHROPIC_BASE_URL"].rstrip("/") + "/v1/messages", data=body,
        headers={"content-type": "application/json",
                 "x-api-key": os.environ["ANTHROPIC_AUTH_TOKEN"],
                 "anthropic-version": "2023-06-01"})
    with open_api(req, timeout=120) as resp:
        data = json.loads(resp.read())
    u = data.get("usage", {})
    tok = (u.get("input_tokens", 0) + u.get("cache_read_input_tokens", 0)
           + u.get("cache_creation_input_tokens", 0))
    text = "".join(b.get("text", "") for b in data.get("content", []) if b.get("type") == "text")
    return text.strip(), tok, png


if __name__ == "__main__":
    for probe in [
        ("点击 Name 输入框", "把光标放到 Name 输入框里。"),
        ("在已聚焦的框里输入", "在已聚焦的输入框里输入 Zhang San。"),
    ]:
        label, prompt = probe
        text, tok, png = step(prompt, focus="name" if "已聚焦" in prompt else None)
        print("[%s] 输入 %d token（图 %d 字节）" % (label, tok, len(png)))
        print("   模型输出：%s" % text[:120].replace("\n", " "))
    print()
    print("两点观察：")
    print("1) 这次请求将 %dx%d 截图作为图像输入；其他 GUI 工具也可能提供结构化页面状态。" % (W, H))
    print("2) 本地 JSON 协议给出动作提议；此代码不会执行动作，也不验证业务后置条件。")
```

存档输出节选（2026-10-09；逐次原始响应未保存）：

```text

模型提议：{"action":"click","x":280,"y":171}
[在已聚焦的框里输入] 输入 384 token（图 8189 字节）

```

## 常见坑

- **把动作提议当成已经执行。** 本节代码只打印 JSON，不会操作屏幕；即使宿主报告动作调用成功，也应独立检查业务后置条件。
- **以为动作空间小就代表风险小。** 风险取决于宿主给适配器的真实权限、目标应用和授权策略；简单原语仍可能触发重要副作用。
- **把像素观测当成所有 GUI 工具的唯一形式。** Browser use 等工具可以提供可访问性树与元素引用，也可结合截图。
- **把最近元素中心距离当成目标级点击精度。** 历史记录没有完整目标命中判据，不能据此判断模型定位“很准”；应在目标环境里记录预期目标、点击坐标、实际命中与业务结果。
- **假设界面结构会决定成功率。** 视觉布局可能影响识别，但本项目留存数据不足以量化界面规整程度与成功率的关系；需要在目标任务上评测。
