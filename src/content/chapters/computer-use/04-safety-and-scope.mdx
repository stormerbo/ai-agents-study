前两节展示了两类风险：坐标动作本身不包含业务语义，重复调用也可能留下未确认状态。本节把控制面拆成几部分，帮助你逐项设计策略与执行边界。

这两类风险共同说明：权限与执行约束应由可信宿主强制，不能只写在提示词里。

下面用四类控制做教学示例。它们不是一份完整的生产安全方案；授权、隔离、审计、隐私和恢复仍需按具体系统补齐。

## 第一道：活动范围

最直观的一道 —— **限定它能碰到哪里**。

对截图/坐标适配器，可以把允许点击的屏幕区域作为一层策略。坐标必须与执行器实际使用的窗口、缩放和滚动坐标系一致；屏幕矩形只约束点击位置，不能证明点击对象的语义正确，也不会限制键盘输入、其他工具或应用自身的授权。

历史 harness 的一条失败摘要记录了 **323 px 的最近登记元素中心距离**。它不是相对 Create 按钮的误差，也没有保留点击坐标，因此不能据此推断模型点到了哪里或判定为「乱试」。坐标范围限制仍可降低越界动作的影响，但区域应按具体界面和任务设计。

范围白名单能减少执行器可点击的位置，但白名单内仍可能有危险控件。它是纵深防护的一层，不能代替动作级授权或应用侧权限校验。OWASP 授权建议采用默认拒绝并在每次请求上验证授权；这里的坐标范围不提供这些语义，参见 [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。

实现上就是一组矩形：

```python
g = Guard(safe_zones=[(60, 150, 500, 296), (60, 380, 240, 432)])
print(g.allow({"action": "click", "x": 280, "y": 173}))  # (True, "ok")
print(g.allow({"action": "click", "x": 700, "y": 100}))  # (False, ...)
```

矩形包含判断对给定坐标是确定的；但坐标映射、目标移动和焦点状态仍可能不准确。策略应在执行器实际动作前检查，并按接口分别约束点击、键盘、文本输入与导航。

## 第二道：预算

第二道是预算。请求发出后才知道 provider 实际 usage，所以仅在响应后比较累计 token 是**事后记账**，不能阻止当前请求花费超限。发送前应检查步数与预算余量，按输入估算和最大输出预留额度；响应回来后用实际 usage 对账，若超出预留则不再执行动作或发起新请求。预估误差、并发请求和 provider 计费口径仍可能造成超额，需按目标端点校准。Python [内置类型文档](https://docs.python.org/3.14/library/stdtypes.html)说明 `bool` 是 `int` 的子类，因此只检查 `isinstance(value, int)` 会放过 `True`；预算边界要显式拒绝布尔值、浮点数和负数，并分别校验请求前的预留量与响应后的实际 usage。

**步数上限**。应在每次模型请求之前检查剩余步数；第 3 节的 noop 历史摘要只表明一条运行记录到 8 步上限，不证明模型是否意识到动作无效。宿主还应把预算耗尽、模型退出和任务完成分开记录。

**token 预算**。步数与 token 用量并不等价：截图复杂度、历史长度、模型输出和缓存口径都会影响 usage。每次调用前尽量用输入估算与请求级输出上限预留预算，调用后再用实际 usage 对账；预算边界能否严格执行取决于 provider 和并发模型。

预算应按目标工作负载测量，并覆盖重试、停滞与收尾路径。第 3 节留下的 tiny 失败输出为 19,209 与 26,568 token，noop 为 11,827；旧 scorer 和缺失的原始响应使它们无法用于估计失败概率、期望成本或通用预算倍率。

## 第三道：熔断

第三道用于发现可能的「原地打转」，例如连续多次观测未见预期进展。

相同的压缩哈希可作为可能停滞的信号，但碰撞或漏掉细微变化都可能发生，不能证明界面完全相同、任务卡死或业务失败。连续 3 次相邻比较相等需要至少 4 次观测（基线帧加 3 次比较）；阈值要按目标界面的误报与漏报校准，并保留未确认状态。

```text
观测 1（建立基线）→ 继续
观测 2（相邻比较 1：相同）→ 继续
观测 3（相邻比较 2：相同）→ 继续
观测 4（相邻比较 3：相同）→ 停止新动作，标记为可能停滞
```

实现上可将感知哈希用于候选信号，或屏蔽已知动态区域；每种方法都可能把真实变化漏掉或把正常变化当作进展，因此阈值策略应结合应用状态、超时和其他观测。

阈值需按界面动态校准。延迟更新、动画和确认流程都可能改变误报与漏报；部署前应在目标 UI 验证该信号如何触发等待、重新观测或人工处理。

## 第四道：高影响动作的授权与审批

这一类控制针对高影响或难以补偿的后果，审批强度应与影响、用户授权和恢复能力相匹配。

可逆性是风险评估因素之一，但不能单独决定是否允许自动执行。低风险且有明确授权的操作可能自动执行；高影响或授权不足的操作应要求额外确认、限制参数或转人工。

关键边界是：**模型不能为自己产生的动作自行批准。**

批准可以由用户交互或独立策略提供，不要求物理上位于循环之外；但批准来源必须独立于模型提议，并绑定到具体任务、目标和参数。对于异步或延迟执行，还需设置有效期、一次性消费与撤销规则，避免把旧批准复用于改过的动作。

教学代码用一个由宿主传入的一次性引用演示该边界。真实系统必须由可信授权流程验证批准者、动作摘要、任务和有效期；下面的字符串引用本身不提供身份认证或防篡改能力：

```python
action = {"action": "click", "x": 150, "y": 200}
# requires_approval 由可信宿主按真实目标和动作策略计算。
# 实际批准由可信宿主验证并提供；此字符串引用自身不是身份凭据。
g.approve_once("task-42", action, opaque_ref="approval-91")
g.allow(action, task_id="task-42", approval_ref="approval-91", requires_approval=True)
```

`approve_once()` 仅是教学接口，不应暴露给模型动作路由。模型可以提出动作，宿主则根据已验证的用户意图和策略决定是否执行；白名单、审批或哈希检查的存在本身不等于系统已获授权。

## 审计轨迹：出事之后靠什么复盘

前面的策略检查不能替代事后审计。记录应足以调查失败，同时按数据敏感度做最小化、脱敏、访问控制与保留期限管理；截图可能包含凭据、个人信息或业务机密，不应默认永久保存整屏内容。

建议根据风险保留足够的事件证据，并按需脱敏：

- **观测引用或经批准的脱敏截图**，并记录采集时间、哈希和保留策略
- **动作提议的受控记录**，避免将凭据或完整页面内容写入日志
- **实际 usage、预算预留与停止原因**
- **执行决策、结果状态、拒绝原因和批准记录引用**

只记「模型请求了什么」，无法区分动作未执行、已执行、被拦截或结果未知。日志可协助复核和重建事件顺序，但模型调用、外部状态与 UI 时序通常不能靠日志保证逐字节重放。参见 [OWASP Logging Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html) 关于事件数据、敏感数据最小化与日志保留的建议。

这些记录应由宿主或可信执行器生成，而非依赖模型自述；应把它们当作调查证据，不承诺精确重放。

## 为什么需要多层控制

这四类控制覆盖不同风险，相互补充，但不构成完整的生产安全验收：

| 闸门 | 防的是 | 缺了会怎样 |
|---|---|---|
| 活动范围 | 超出任务范围的输入 | 越界动作可能触发未授权或意外结果 |
| 预算 | 缺少成本与等待上限 | 循环可能持续消耗资源，直到外部停止 |
| 熔断 | 原地打转 | 预算被无效步骤吃掉，走不到有用的那一步 |
| 高影响审批 | 任务/目标/参数未获授权 | 范围和预算合法仍不代表该副作用获准 |

最后一行值得单独说：坐标范围与预算检查不代表动作已经获准。高影响操作还需独立判断任务、目标、参数与调用者授权。

组合起来，它们覆盖界面范围、预算、无进展处理和高影响动作授权；还需单独验证账户权限、执行器隔离、隐私与日志治理、业务后置条件和故障恢复。
## 完整可运行代码

下面的纯本地示例演示边界检查、请求前预算预留、响应后 usage 对账、相邻观测停滞信号，以及绑定具体任务和动作的一次性批准引用。它不实现真实身份认证、可信授权服务、并发预留、UI 语义定位或隔离执行。

```python
"""安全闸门的本地教学模型；不调用网络或真实 UI。

实跑状态：2026-10-20，离线脚本执行通过。
"""
from dataclasses import dataclass, field
import hashlib
import json
import math


@dataclass
class Guard:
    safe_zones: list[tuple[float, float, float, float]]
    step_budget: int = 12
    token_budget: int = 20000
    no_change_limit: int = 3
    max_text_chars: int = 500

    steps_started: int = 0
    tokens_used: int = 0
    same_screen: int = 0
    last_hash: str | None = None
    grants: set[tuple[str, str, str]] = field(default_factory=set)
    consumed_grants: set[tuple[str, str, str]] = field(default_factory=set)

    def __post_init__(self):
        for name, value in (
            ("step_budget", self.step_budget),
            ("token_budget", self.token_budget),
            ("no_change_limit", self.no_change_limit),
        ):
            if isinstance(value, bool) or not isinstance(value, int) or value < 1:
                raise ValueError(f"{name} must be a positive integer")
        if isinstance(self.max_text_chars, bool) or not isinstance(self.max_text_chars, int) or self.max_text_chars < 0:
            raise ValueError("max_text_chars must be a non-negative integer")
        for x0, y0, x1, y1 in self.safe_zones:
            if not all(math.isfinite(v) for v in (x0, y0, x1, y1)) or x0 > x1 or y0 > y1:
                raise ValueError("invalid safe-zone rectangle")

    @staticmethod
    def fingerprint(action: dict) -> str:
        encoded = json.dumps(action, sort_keys=True, separators=(",", ":"), ensure_ascii=False)
        return hashlib.sha256(encoded.encode("utf-8")).hexdigest()

    def begin_request(self, reserved_tokens: int) -> tuple[bool, str]:
        """Call before the provider request; reservation is an estimate, not a guarantee."""
        if isinstance(reserved_tokens, bool) or not isinstance(reserved_tokens, int) or reserved_tokens < 0:
            return False, "invalid token reservation"
        if self.steps_started >= self.step_budget:
            return False, "step budget exhausted"
        if self.tokens_used + reserved_tokens > self.token_budget:
            return False, "token budget reservation would exceed limit"
        self.steps_started += 1
        return True, "ok"

    def finish_request(self, actual_tokens: int, observation_hash: str) -> tuple[bool, str]:
        """Reconcile usage after response; hash must represent the observation sent."""
        if isinstance(actual_tokens, bool) or not isinstance(actual_tokens, int) or actual_tokens < 0:
            return False, "invalid provider usage"
        self.tokens_used += actual_tokens
        if self.tokens_used > self.token_budget:
            return False, "actual usage exceeded budget; do not execute returned action"
        if not isinstance(observation_hash, str) or not observation_hash:
            return False, "missing observation hash"
        if observation_hash == self.last_hash:
            self.same_screen += 1
        else:
            self.same_screen = 0
        self.last_hash = observation_hash
        if self.same_screen >= self.no_change_limit:
            return False, "possible stagnation; stop before another action"
        return True, "ok"

    def approve_once(self, task_id: str, action: dict, opaque_ref: str) -> None:
        """Demo seam only; production approval must be verified by a trusted host."""
        self.grants.add((task_id, self.fingerprint(action), opaque_ref))

    def allow(self, action: dict, *, task_id: str, focused_target: str | None = None,
              approval_ref: str | None = None, requires_approval: bool = False) -> tuple[bool, str]:
        if not isinstance(action, dict) or not isinstance(action.get("action"), str):
            return False, "invalid action shape"
        kind = action["action"]
        if kind == "click":
            if set(action) != {"action", "x", "y"}:
                return False, "unexpected click fields"
            x, y = action["x"], action["y"]
            if (isinstance(x, bool) or isinstance(y, bool)
                    or not isinstance(x, (int, float)) or not isinstance(y, (int, float))
                    or not math.isfinite(x) or not math.isfinite(y)):
                return False, "click coordinates must be finite numbers"
            if not any(x0 <= x <= x1 and y0 <= y <= y1
                       for x0, y0, x1, y1 in self.safe_zones):
                return False, "click outside configured region"
        elif kind == "type":
            if set(action) != {"action", "text"} or not isinstance(action["text"], str):
                return False, "invalid type action"
            if len(action["text"]) > self.max_text_chars:
                return False, "text input exceeds limit"
            if focused_target not in {"search-box", "approved-form-field"}:
                return False, "focused target is not allowlisted"
        elif kind == "done":
            if set(action) != {"action"}:
                return False, "unexpected done fields"
        else:
            return False, "unknown action: default deny"

        fingerprint = self.fingerprint(action)
        if requires_approval:  # 由可信宿主的资源/动作策略决定
            grant = (task_id, fingerprint, approval_ref or "")
            if grant not in self.grants or grant in self.consumed_grants:
                return False, "missing, mismatched, or already consumed approval"
            self.consumed_grants.add(grant)
        return True, "ok"


if __name__ == "__main__":
    g = Guard(safe_zones=[(60, 150, 500, 296)],
              step_budget=2, token_budget=2500,
)
    print("范围与默认拒绝")
    for action in (
        {"action": "click", "x": 280, "y": 173},
        {"action": "click", "x": 900, "y": 100},
        {"action": "launch-shell"},
    ):
        print(action, "->", g.allow(action, task_id="task-1")[0])

    print("请求前预算预留")
    print("第 1 次:", g.begin_request(1000))
    print("响应对账:", g.finish_request(900, "frame-a"))
    print("第 2 次:", g.begin_request(1700))  # 预留将超过 token 上限
    step_guard = Guard(safe_zones=[], step_budget=1)
    step_guard.begin_request(100)
    print("步数耗尽:", step_guard.begin_request(100))

    print("动作绑定的一次性批准")
    high_impact_click = {"action": "click", "x": 150, "y": 200}
    g.approve_once("task-1", high_impact_click, "opaque-demo-ref")
    print("原动作:", g.allow(high_impact_click, task_id="task-1",
                                approval_ref="opaque-demo-ref", requires_approval=True))
    print("重复消费:", g.allow(high_impact_click, task_id="task-1",
                                approval_ref="opaque-demo-ref", requires_approval=True))
```

实跑输出（2026-10-20，当前教学代码）：

```text

{'action': 'click', 'x': 280, 'y': 173} -> True
{'action': 'click', 'x': 900, 'y': 100} -> False
{'action': 'launch-shell'} -> False
请求前预算预留
第 1 次: (True, 'ok')
响应对账: (True, 'ok')
第 2 次: (False, 'token budget reservation would exceed limit')
步数耗尽: (False, 'step budget exhausted')
动作绑定的一次性批准
原动作: (True, 'ok')
重复消费: (False, 'missing, mismatched, or already consumed approval')
```

本地批准接口仅用于演示绑定关系和一次性消费；真实系统必须由宿主从可信审批记录验证批准者、任务、参数摘要和有效期。

## 把 Guard 接进循环：预算与动作的边界

Guard 本身是纯逻辑；调用顺序决定预算和动作是否真的被约束。下面是宿主集成的伪代码，call_model、current_screen 与执行器接口需由具体 provider / UI adapter 实现：

```python
while True:
    observation = current_screen()                  # 捕获一次
    observation_hash = hash_observation(observation)
    reservation = estimate_input(observation, history) + max_output_tokens

    ok, why = guard.begin_request(reservation)       # 请求前预留
    if not ok:
        stop(why)
        break

    response = call_model(history, observation,
                          max_output_tokens=max_output_tokens)
    ok, why = guard.finish_request(
        response.actual_usage, observation_hash      # 对账同一份输入观测
    )
    if not ok:
        stop(why)                                    # 不执行本次返回的动作
        break

    action = parse_and_validate(response)
    ok, why = guard.allow(
        action, task_id=task_id,
        focused_target=trusted_ui.focused_target(),
        approval_ref=trusted_host.approval_for(action, task_id),
    )
    if not ok:
        report_blocked_to_model_or_user(action, why)
        continue

    result = trusted_ui.execute(action)
    verify_business_postcondition(result)
```

begin_request 必须在 provider 调用前执行，响应回来后用实际 usage 对账。估算与并发可能导致实际用量越过预算；严格共享预算需要由可信宿主原子预留，并限制请求最大输出。哈希必须对应发给模型的那一帧，不能在响应后重新截屏再拿来比较。allow 必须在执行器产生副作用之前运行，而且还需结合目标 UI 的语义定位、账户授权和结果核验。

被拒绝的动作如何反馈取决于协议。纯文本 JSON 循环应把拒绝原因作为下一条 user 消息或终止状态；不要把自定义 JSON 对象伪装成 Anthropic tool_result。在 Anthropic client-side tool-use 流程中，结果必须关联原始 tool_use block 的 id（即 tool_use_id）；若采用 Anthropic computer-use 工具集，还需遵循对应工具集字段要求。is_error 是可选的错误信号，不保证模型一定采取某种恢复策略。参见 [Anthropic Handle tool calls](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls)。

## 本节小结

1. **活动范围、预算、停滞信号与高影响动作审批** 是不同的教学控制面；缺失某一层会留下对应风险，但这四项不是完整安全方案。
2. **预算按目标负载测量**：第 3 节的历史摘要不能支持失败成本倍数或预算分布。
3. **哈希用于提示可能停滞，不证明业务无进展**；3 次相邻相同比较需要 4 次观测，阈值应实测校准。
4. **批准来源必须独立于模型提议**，并绑定具体任务、目标和参数；批准可以由用户交互或独立策略产生。
5. **策略执行、受控审计和业务结果核对各有作用**；还需验证授权身份、隔离、隐私、恢复和运行环境，不能仅凭本节示例判定可上线。
6. **策略应由可信宿主在动作执行前强制**；模型遵循提示只能作为辅助信号，不能替代应用侧授权。
## 常见坑

- **把权限边界写在提示词里。** 「不要点击删除按钮」是一句请求，不是一条约束。约束要写在执行动作之前的那层代码里。
- **让模型自己批准高影响动作。** 批准来源必须独立于模型提议，并绑定任务、目标和参数；批准由 UI、审批服务或独立策略产生都可以。
- **只设步数上限，不设 token 上限。** 两者不等价 —— 界面越复杂，单张截图越贵，同样的步数可以差出好几倍成本。
- **只按成功路径测预算。** 应覆盖目标环境中的重试、停滞与收尾路径，并记录实际 usage 和停止原因；第 3 节历史摘要不能提供通用倍率。
- **用像素或文件字节判断「界面有没有变化」。** 光标闪烁和动画会让它永远不相等，闸门就废了。
- **把某个停滞阈值当成通用常数。** 哈希与阈值只是启发式；用目标界面测误报、漏报和等待时间。
- **只在动作前设闸门，不做执行后的核对。** 闸门防的是「不该做的动作」，防不住「做对了动作但结果不对」。结果核对（第 3 节）是另一半。
