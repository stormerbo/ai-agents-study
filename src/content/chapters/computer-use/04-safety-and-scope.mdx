前两节把两个事实摆出来了：**动作空间是开放的**（同一个 `click` 什么都能点），**而模型不能作为停止条件**（它卡住时会一直重试）。

这两条合起来就是一个很具体的工程要求：**权限边界必须由你的代码来画，而不是写在提示词里。**

这一节把边界拆成四道闸门，并给出一份可运行的实现。

## 第一道：活动范围

最直观的一道 —— **限定它能碰到哪里**。

界面自动化的动作空间是「整个屏幕」，但一个具体任务通常只需要屏幕的一小块：填这张表单、点这一个按钮。所以第一件事就是把「允许点击的区域」声明成白名单。

实测里那一次失控很有说服力：小目标注入下，模型最后点出了 **323 px 的落空距离** —— 那已经不在按钮附近了，而是在**乱试**。如果屏幕上那个位置恰好有个危险按钮，这一下就点中了。

范围白名单的价值不在于「它会点错」，而在于**点错时的爆炸半径被封住了**。

实现上就是一组矩形：

```python
g = Guard(safe_zones=[(60, 150, 500, 296), (60, 380, 240, 432)])
g.allow({"action": "click", "x": 280, "y": 173})   # 放行（在输入框里）
g.allow({"action": "click", "x": 700, "y": 100})   # 拦截（在范围外）
```

注意这道闸门是**确定性的**：给定坐标与矩形，结果只有放行或拦截，没有「大概可以」。这和前面几章反复出现的判断一样 —— 能写成确定性规则的东西，就不要交给模型。

## 第二道：预算

第二道是钱和时间。它有两种，都要设：

**步数上限**。第 2 节讲过它是兜底；第 3 节的实测说明了它为什么会真的用上 —— 点击无效时模型连续重试了 4 次都没有停，最后是撞上上限才结束的。

**token 上限**。这一条容易被漏掉，因为步数上限看起来已经间接限制了成本。但两者并不等价：界面复杂时单张截图就可能接近 996 token（第 8 章实测的上限），12 步的 token 总量会是几步的好几倍。按 token 设上限，才是真正的成本闸门。

预算怎么定？**按失败路径定，不要按成功路径定。** 第 3 节实测：成功的运行约 5,000 token，而失败的运行是 12,000 到 27,000。如果按成功路径设 6,000，那么每一次失败都会超支 —— 而失败是常态的一部分。

## 第三道：熔断

第三道防的是「原地打转」，它的判据是**界面连续 N 步没有变化**。

这道闸门比步数上限更早触发，也更省：如果连续三步截图一模一样，这个循环已经不可能靠继续走变好了，而每多走一步都要付一次截图的钱。

```text
第 1 步（同一张界面）→ 继续
第 2 步（同一张界面）→ 继续
第 3 步（同一张界面）→ 继续
第 4 步（同一张界面）→ 熔断：界面连续 3 步无变化，判定为卡住
```

实现上有两个坑。**一是不要用文件字节相等去比** —— 光标闪烁、加载动画、时间戳都会让两张视觉上相同的图产生不同字节。要么比较缩小后的感知哈希，要么明确排除掉允许变化的区域。

**二是阈值别设成 2。** 有些操作本来就需要两步才见效（点了提交 → 出现确认弹窗）。实测里模型在点击无效时重试了 4 次，说明「连续 2 到 3 步不变」是正常范围，3 到 4 步才是异常。

## 第四道：不可逆动作的确认点

这一道最关键，因为它防的是**无法撤销的后果**。

判据可以写得很干脆：**如果一个动作失败之后无法用另一个动作撤销，它就不该由循环自动执行。**

而这里有一个必须讲清楚的设计要求：**确认点不能放在模型这一层。**

理由直白：模型既可以发起那个动作，也可以「批准」它 —— 那不是确认，那是自问自答。确认必须来自**循环之外**：人（在界面上点一下）、或者一条独立的策略（比如「金额超过 X 就必须人工」）。

实现上就是把批准权从模型手里拿走：

```python
g.allow({"action": "delete-all"})          # 拦截：不可逆，未获确认
g.declare("delete-all", approved_by="人")  # 这一步只能由循环之外调用
g.allow({"action": "delete-all"})          # 放行
```

注意 `declare()` 这个接口**不在模型的输出格式里**。模型能决定的只有「我想做什么」，而「允许做什么」由代码决定。这两件事分开，是整个设计里最重要的那条线。

## 审计轨迹：出事之后靠什么复盘

四道闸门都是**事前**的。但界面自动化一定会出事 —— 不是「如果」，是「什么时候」。所以还需要一件**事后**的事：留痕。

要留的东西很少，但缺一不可：

- **每一步的截图**（本来就要发给模型，顺手落盘）
- **每一步的动作**（模型输出的**原始 JSON**，不是解析后的版本）
- **每一步的 token**（事后算成本，也用于发现异常）
- **动作是否被执行、以及被拦截的原因**

最后一条最容易被漏掉。只记「模型请求了什么」，你就无法区分「它没想做」和「它想做但被拦住了」—— 而后者恰恰是闸门在工作的证据，也是调阈值的依据。

这些东西**必须在循环里记，不能在模型那边记**。模型不会主动汇报自己 5 步前点了哪里；日志才是唯一能事后重放的东西。

## 为什么是四道，而不是一道

这四道闸门分别防四种不同的失控，任何一道都替代不了另一道：

| 闸门 | 防的是 | 缺了会怎样 |
|---|---|---|
| 活动范围 | 点到不该点的地方 | 一次乱点就可能造成不可逆后果 |
| 预算 | 无限烧钱和无限等待 | 卡住的循环永远不结束 |
| 熔断 | 原地打转 | 预算被无效步骤吃掉，走不到有用的那一步 |
| 不可逆确认 | 无法撤销的后果 | 其他三道都拦不住「动作确实做对了，但那个动作本身不该做」 |

最后一行值得单独说：**前三道都是「动作层面的安全检查」，它们默认「模型想做的动作是对的」。** 第四道是唯一会质疑「这个动作该不该做」的 —— 它不看坐标在不在范围内，它看的是语义。

四道合起来，才是「活动范围」这个词的完整含义：**不只是「它能碰哪里」，还包括「它能花多少」「它能试多久」和「它能决定什么」。**
## 完整可运行代码

下面把这四道闸门落成可运行、可测试的代码。它是纯本地逻辑，不需要任何凭据。

```python
"""权限与活动范围：三道闸门的最小实现。

纯本地逻辑，不需要网络。它把第 4 节讲的边界落成可测试的代码：
  一、活动范围（只能碰白名单区域）
  二、预算（步数 + token）
  三、熔断（连续 N 步界面无变化就中止）
  四、不可逆动作必须显式确认

实跑状态：2026-10-09，已跑通。
"""

from dataclasses import dataclass, field


@dataclass
class Guard:
    """包在动作外面的一层。模型说什么不算数，它先过这里。"""

    safe_zones: list          # 允许点击的矩形列表 [(x0,y0,x1,y1), ...]
    step_budget: int = 12
    token_budget: int = 20000
    no_change_limit: int = 3  # 连续多少步界面无变化就熔断
    irreversible: set = field(default_factory=set)   # 需要显式确认的动作名

    steps: int = 0
    tokens: int = 0
    same_screen: int = 0
    last_hash: str | None = None
    confirmations: set = field(default_factory=set)
    log: list = field(default_factory=list)

    def declare(self, action_name: str, approved_by: str) -> None:
        """不可逆动作必须由**人或策略层**批准，不能由模型自己批准。"""
        self.confirmations.add(action_name)
        self.log.append("已确认 %s（由 %s 批准）" % (action_name, approved_by))

    def record_step(self, tokens: int, screen_hash: str) -> tuple[bool, str]:
        self.steps += 1
        self.tokens += tokens
        if self.steps > self.step_budget:
            return False, "步数超预算（%d/%d）" % (self.steps, self.step_budget)
        if self.tokens > self.token_budget:
            return False, "token 超预算（%d/%d）" % (self.tokens, self.token_budget)
        if screen_hash == self.last_hash:
            self.same_screen += 1
            if self.same_screen >= self.no_change_limit:
                return False, "界面连续 %d 步无变化，判定为卡住" % self.same_screen
        else:
            self.same_screen = 0
        self.last_hash = screen_hash
        return True, "ok"

    def allow(self, action: dict, irreversible_names: set | None = None) -> tuple[bool, str]:
        names = irreversible_names or self.irreversible
        kind = action.get("action")
        if kind == "click":
            x, y = action.get("x"), action.get("y")
            inside = any(x0 <= x <= x1 and y0 <= y <= y1 for x0, y0, x1, y1 in self.safe_zones)
            if not inside:
                return False, "点击 (%d,%d) 落在活动范围之外" % (x, y)
        if kind in names and kind not in self.confirmations:
            return False, "动作 %s 不可逆，未获确认" % kind
        return True, "ok"


if __name__ == "__main__":
    # 只允许在表单区域里点：输入框 + Create 按钮
    g = Guard(safe_zones=[(60, 150, 500, 296), (60, 380, 240, 432)], step_budget=6)

    print("闸门一：活动范围")
    for px, py_ in [(280, 173), (700, 100), (150, 400)]:
        ok, why = g.allow({"action": "click", "x": px, "y": py_})
        print("  点 (%3d,%3d) → %s  %s" % (px, py_, "放行" if ok else "拦截", "" if ok else why))
    print()

    print("闸门二：步数与 token 预算")
    for i in range(1, 8):
        ok, why = g.record_step(tokens=1000, screen_hash="h%d" % i)
        print("  第 %d 步（token 累计 %5d）→ %s" % (i, g.tokens, "继续" if ok else "停止：" + why))
        if not ok:
            break
    print()

    print("闸门三：熔断（界面连续无变化）")
    g2 = Guard(safe_zones=[], no_change_limit=3, step_budget=99)
    for i in range(1, 6):
        ok, why = g2.record_step(tokens=100, screen_hash="一模一样")
        print("  第 %d 步（同一张界面）→ %s" % (i, "继续" if ok else "熔断：" + why))
        if not ok:
            break
    print()

    print("闸门四：不可逆动作的确认点")
    g3 = Guard(safe_zones=[], irreversible={"delete-all"})
    ok, why = g3.allow({"action": "delete-all"})
    print("  模型请求 delete-all → %s  %s" % ("放行" if ok else "拦截", "" if ok else why))
    g3.declare("delete-all", approved_by="人（在 UI 上点了确认）")
    ok, why = g3.allow({"action": "delete-all"})
    print("  人确认之后 → %s" % ("放行" if ok else "拦截"))
    print()
    print("关键点：确认是在 Guard 之外取得的，模型自己无法调用 declare()。")
    print("模型能决定「想做什么」，但只有代码能决定「允许做什么」。")
```

实跑输出（2026-10-09）：

  点 (700,100) → 拦截  点击 (700,100) 落在活动范围之外
  点 (150,400) → 放行

  第 1 步（token 累计  1000）→ 继续

## 本节小结

1. **活动范围、预算、熔断、不可逆确认** —— 四道闸门防四种失控，缺一道都会漏。
2. **预算按失败路径定**：实测失败路径是成功路径的 2.4 到 5.3 倍。
3. **熔断用感知哈希，不要用字节相等**；阈值 3 到 4 步，不是 2。
4. **确认点必须在循环之外** —— 模型既发起又批准，那不是确认。
5. **事前四道闸门 + 事后审计轨迹 + 第 3 节的结果核对**，三样齐全才算一个能上线的界面自动化。
6. **这四道闸门都不需要模型配合** —— 它们全部在模型之外。这一点是刻意的：安全边界不能建立在被约束者的自觉上。
## 常见坑

- **把权限边界写在提示词里。** 「不要点击删除按钮」是一句请求，不是一条约束。约束要写在执行动作之前的那层代码里。
- **让模型自己批准不可逆动作。** 它能发起、也能批准，那不是确认。批准入口必须在循环之外。
- **只设步数上限，不设 token 上限。** 两者不等价 —— 界面越复杂，单张截图越贵，同样的步数可以差出好几倍成本。
- **按成功路径设预算。** 实测失败路径是成功路径的 2.4 到 5.3 倍。预算是给失败留的，不是给顺利留的。
- **用像素或文件字节判断「界面有没有变化」。** 光标闪烁和动画会让它永远不相等，闸门就废了。
- **把熔断阈值设成 2。** 有些操作本来就需要两步才见效，阈值太低会误杀正常流程。
- **只在动作前设闸门，不做执行后的核对。** 闸门防的是「不该做的动作」，防不住「做对了动作但结果不对」。结果核对（第 3 节）是另一半。
