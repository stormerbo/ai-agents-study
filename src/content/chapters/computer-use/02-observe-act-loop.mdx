一种最小的截图/坐标适配器可以写成四步：**获取当前观测 → 让模型给一个动作 → 执行 → 校验结果**。本节代码是自己拼装的合成环境与 Anthropic-compatible Messages API 请求，不是 [Anthropic 原生 computer-use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool)；真实工具集可能一次返回多个动作，也可能提供不同的状态反馈与执行语义。读者应先辨认当前使用的是哪种接口，再决定循环边界。

看起来简单，但循环里有两个设计决定会直接影响成败：**何时需要重新观测**，以及**循环什么时候停**。本节用一个固定的本地合成任务说明设计方法；其中历史模型输出只作为有限观察，不代表当前模型的性能基线。

## 为什么动作后要重新观测

一个自然的疑问是：截图能不能少发几次？比如「先给它一张全局图，然后它自己按坐标操作就行」。

不能把旧图当作动作后的当前状态：**上一步的动作可能改变界面。** 本来该出现下一条输入框的位置，现在可能是刚弹出来的提示；本来禁用的按钮，现在可用了。用旧观测决定依赖新状态的动作，等于闭着眼睛按记忆走路。

在本节使用的截图/坐标适配器中，动作结果不包含足以确认业务状态的语义信息；若适配器提供设备级状态，它也不能替代业务结果校验。因此需要通过后续截图或应用状态查询确认效果。具体反馈通道取决于适配器能力；「每步重新截图」是本实验循环采用的校验方式，不是所有 computer-use 系统的唯一方案。

## 实测一：循环的形状

我搭了一个可控的合成界面环境（820×520，两个输入框 + 一个按钮），任务是「填入 Name 与 Email，然后点 Create」。环境是本地绘制的，所以每一步都可复现、可精确打分。

连续跑三次，三次的动作序列完全一致：

```text
click:name → type → click:email → type → click:submit
```

**5 步完成，3/3 成功。** 序列里没有一次多余的点击，也没有一次「点了空白」。

## 实测二：历史重发如何改变输入量

本地历史记录保留了三次五步成功运行的总用量：5,288、5,347、5,345 token（`deepseek-flash`，2026-10-09）。但逐步 usage、完整请求体、模型路由版本与原始响应没有保存，因此无法把这些总数还原成可审计的逐轮输入表；旧文中的 473/758/1,053/1,356/1,661 与 5,301 合计也不能确认属于这三次运行。这里保留三个总数作为历史观察，不据此推导成功率、每步边际成本或普遍成本倍数。

仍然可以把“每次请求都重发全部图像历史”的结构算清楚。假设每轮新增一张图、五次模型请求分别包含 1、2、3、4、5 张历史图，那么五轮一共处理 **1+2+3+4+5=15 张图像实例**。若暂用第 8 章同一旧端点与旧测量口径的 283 token/图作演示，图像部分约为 **15×283=4,245 token**，还没有计入任务文本、动作文本、输出 token、缓存计量差异或端点的图像预处理。此数是公式演示，不是对上述历史总用量的复算。

在上下文完整保留、每步都加一张近似固定 token 数图像的条件下，累计图像输入按 `n(n+1)/2 × 每图 token` 增长；这说明此类请求的图像输入部分可呈二次增长。真实总费用还受压缩/裁剪、图像分辨率、缓存计费、输出量、模型与端点行为影响，不能把“减少一步”概括成固定倍数，也不能称为“平方根级杠杆”。先查看实际发送的消息历史与每轮 usage，再决定是否压缩旧图、保留最近图像或改用可验证的结构化状态。

图像 token 数尤其依赖厂商、模型与日期。第 8 章的 283 token 是 2026-10-09 的历史实验值；[DeepSeek 当前视觉文档](https://api-docs.deepseek.com/guides/vision/)给出的处理和上限已不同，且会随接口更新，因此这个值只用于上述历史口径的演算，不能当作今天调用该端点的预算常数。

## 实测三：它点得有多准

每次点击我都会算「点击点」到「最近元素中心」的距离。它描述点击点离任一已登记元素中心有多远，不是“点击点到预期目标中心的误差”，也不能单独表示任务准确率：

| 运行 | 点击次数 | 落空次数 | 平均距离 |
|---|---:|---:|---:|
| 1 | 3 | 0 | 2.1 px |
| 2 | 3 | 0 | 2.6 px |
| 3 | 3 | 0 | 1.3 px |

（实跑数据，2026-10-09。界面 820×520。）

历史三次运行报告的**最近元素中心距离为 1.3 到 2.6 像素**。由于没有为每次点击保留预期目标中心与命中判据，这个距离不能解释为目标点击精度，也不能支撑“缩图后仍能认得按钮”的结论。

第 3 节会展示更小目标的历史观察；其适用范围同样限于对应的合成环境和模型运行。更一般的结论是：平均距离指标即使很小，也不代表点击目标正确，更不能代替业务结果校验。

## 循环的三个终止条件

把“循环退出”与“任务成功”分开。模型输出 `done` 可以让控制器停止继续调用模型，但不能证明任务完成；业务成功必须由独立判据确认，例如应用状态/API 回读、目标对象存在或明确的页面结果。下面的三个条件是本节自建控制器可采用的退出规则，不是所有 computer-use API 的协议要求。

**一，模型请求结束。** 这只是一个停止信号；记录退出原因并运行独立的任务成功判据，否则结果应标为未确认。

**二，步数/预算上限。** 硬性兜底。历史实验记录过模型重复尝试，但没有逐轮原始响应，所以这里只保留“为控制器设置有界预算”的设计要求，不把历史运行当作可重放证据。

**三，观测疑似没有进展。** 这可以作为退出或转人工的信号，但不能由“画面相似”推出“继续也不可能变好”。阈值应结合可预期的动画/异步等待与任务风险设置；高风险状态要用业务读回确认。

实现上，可以用**感知哈希**（perceptual hash）作低成本启发式：它尝试让视觉上相似的图得到相近的指纹，与逐字节敏感的文件哈希目标不同。dHash 把缩小后的灰度图相邻像素作比较；相同输出只表示这个压缩指纹相同，不证明两张原图完全相同，也不能证明业务状态没变化。小目标、细字变化和不同画面碰撞都可能漏掉，因此它适合触发“可能没进展”的检查或熔断候选，不能作为任务成功判据。一个最小实现如下：

```python
from PIL import Image

def dhash(img, size=8):
    """感知哈希：先缩到 (size+1)×size 灰度图，再逐行比较相邻像素的亮度，
    得到 size*size 位（这里是 64 位）的十六进制串。"""
    g = img.convert("L").resize((size + 1, size), Image.LANCZOS)
    px = list(g.getdata())
    bits = 0
    for r in range(size):
        for c in range(size):
            bits = (bits << 1) | (1 if px[r * (size + 1) + c] > px[r * (size + 1) + c + 1] else 0)
    return "%016x" % bits
```

它到底顶不顶用，用一个「会闪烁」的界面测最直接：同一张表单，加一个闪烁的光标和一行每秒变化的计时数字，连续渲染 6 帧：

```text
帧  光标  时钟   PNG sha256(前10)   dHash
 1   亮   t=00  6e72aaa7f0       9040909000909004
 2   灭   t=01  466065af86       9040909000909004
 3   亮   t=02  25a1e9b019       9040909000909004
 4   灭   t=03  edcaa1e2a5       9040909000909004
 5   亮   t=04  c17b4cf662       9040909000909004
 6   灭   t=05  fb78f78528       9040909000909004

字节哈希：6 帧 6 个不同值 -> 永不相等（熔断永不触发）
dHash   ：6 帧 1 个不同值 -> 这组帧的 64 位指纹相同
```

（本地合成帧观察，2026-10-12。同一个 dHash 实现，对这 6 帧分别算字节哈希与 dHash；只说明该样本的光标/计时变化未改变指纹。）

这组输出只说明：逐字节比较会发现每帧文件不同，而 dHash 在这组光标/计时变化下得到相同指纹。若 `MAX_SAME=3`，需要先有一帧作为基线，再发生三次连续相等比较，也就是至少四帧；它只说明“连续观测到相同指纹”，不说明任务一定卡住。接进循环时，可在提交模型请求前检查这个信号，并将其作为熔断候选：

```python
last_hash, same_count, MAX_SAME = None, 0, 3
while steps < max_steps and not state["done"]:
    img = screenshot_as_pil()
    h = dhash(img)
    if h == last_hash:
        same_count += 1
        if same_count >= MAX_SAME:      # 连续 3 次相邻截图比较得到相同指纹
            break                       # 熔断候选；上层应报告“未确认完成”
    else:
        same_count = 0
    last_hash = h
    # ... 下面照旧：发图 -> 取动作 -> 执行
```

反过来也要知道它的边界：dHash 是**全图**指纹，如果界面里有一块大区域在合法地动（进度条、滚动列表），dHash 每步都会变，也可能漏报停滞。可以在明确允许变化区域后比较 ROI，但裁剪本身也会漏掉被排除区域内的重要变化。若界面变化影响提交、付款或删除等结果，应再用业务状态查询/人工确认，不能靠哈希熔断。

## 完整可运行代码

下面是一个有外部前置条件的模型调用示例：环境由本地绘制的合成界面驱动，不操作真实桌面；需要 Pillow、可用的字体文件、网络与兼容的 API 凭据，并设置 `VERIFY_MODEL`、`ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN`。请求会拒绝 HTTP 重定向，以免把 API key 转发给跳转目标。Python [urllib.request 文档](https://docs.python.org/3.14/library/urllib.request.html)说明 `HTTPRedirectHandler.redirect_request` 可以通过返回 `None` 拒绝自动重定向；本地 loopback 回归测试确认当前默认 opener 的 POST 重定向会把 `x-api-key` 带到目标。此 handler 只阻止自动跟随，不替代对 base URL、TLS、代理和凭据来源的信任配置。环境和判分逻辑可复现，模型动作、token 用量和路由结果不保证复现。代码只验证本地表单状态，不是可用于真实桌面的安全执行器。

```python
"""计算机使用：一个可控的合成界面环境 + 真实的观测-动作循环。

环境是本地绘制的（不依赖真实操作系统），所以每一步都可复现、可精确打分。

实跑状态：2026-10-09，deepseek-flash。
"""
import os

import base64, json, os, re, urllib.request
from io import BytesIO
from PIL import Image, ImageDraw, ImageFont

FONT = "/System/Library/Fonts/Supplemental/Arial.ttf"
W, H = 820, 520

# 每个可交互元素的区域与中心 —— 用于判定落点所在区域，不代表目标级精度
ELEMENTS = {
    "name":   (60, 150, 500, 196),
    "email":  (60, 250, 500, 296),
    "submit": (60, 380, 240, 432),
}
BASE_ELEMENTS = {
    "name":   (60, 150, 500, 196),
    "email":  (60, 250, 500, 296),
}
# 变体：tiny 把按钮缩小到 44x26；decoy 加一个同样显眼的 Cancel
VARIANTS = {
    "baseline": {"submit": (60, 380, 240, 432)},
    "tiny":     {"submit": (60, 380, 104, 406)},
    "decoy":    {"submit": (60, 380, 240, 432), "cancel": (270, 380, 430, 432)},
}
VARIANT = "baseline"


def font(sz):
    return ImageFont.truetype(FONT, sz)


def render(state):
    img = Image.new("RGB", (W, H), "white")
    d = ImageDraw.Draw(img)
    d.rectangle([0, 0, W, 64], fill=(240, 244, 250))
    d.text((60, 24), "NEW USER FORM", fill=(20, 30, 50), font=font(20))
    d.text((60, 110), "Name", fill=(90, 100, 115), font=font(14))
    d.text((60, 210), "Email", fill=(90, 100, 115), font=font(14))
    for key in ("name", "email"):
        x0, y0, x1, y1 = ELEMENTS[key]
        focused = state["focus"] == key
        d.rectangle([x0, y0, x1, y1], outline=(60, 120, 220) if focused else (170, 180, 195),
                    width=3 if focused else 1)
        d.text((x0 + 12, y0 + 14), state["values"][key] or "", fill=(20, 20, 20), font=font(18))
    x0, y0, x1, y1 = ELEMENTS["submit"]
    d.rectangle([x0, y0, x1, y1], fill=(30, 110, 220))
    d.text((x0 + 12, y0 + 6), "Create", fill="white", font=font(15 if VARIANT == "tiny" else 18))
    if "cancel" in ELEMENTS:
        cx0, cy0, cx1, cy1 = ELEMENTS["cancel"]
        d.rectangle([cx0, cy0, cx1, cy1], fill=(235, 238, 243))
        d.text((cx0 + 26, cy0 + 15), "Cancel", fill=(60, 70, 90), font=font(18))
    if state.get("error"):
        d.rectangle([60, 452, W - 60, 486], fill=(255, 238, 238))
        d.text((72, 460), state["error"], fill=(190, 40, 40), font=font(14))
    if state.get("done"):
        d.rectangle([0, 0, W, H], fill=(240, 252, 245))
        d.text((60, 200), "SUCCESS", fill=(20, 140, 70), font=font(34))
        d.text((60, 260), "user created: " + state["values"]["name"], fill=(30, 40, 50), font=font(18))
    buf = BytesIO()
    img.save(buf, format="PNG")
    return buf.getvalue()


def apply_action(state, act, log):
    """执行一个动作。返回是否有推进。"""
    kind = act.get("action")
    if kind == "click":
        x, y = float(act.get("x", -1)), float(act.get("y", -1))
        hit = None
        best = 1e9
        for key, (x0, y0, x1, y1) in ELEMENTS.items():
            cx, cy = (x0 + x1) / 2, (y0 + y1) / 2
            dist = ((x - cx) ** 2 + (y - cy) ** 2) ** 0.5
            if dist < best:
                best, nearest = dist, key
            if x0 <= x <= x1 and y0 <= y <= y1:
                hit = key
        log.append({"act": "click", "target": hit, "nearest": nearest, "dist": round(best, 1)})
        if hit in ("name", "email"):
            state["focus"] = hit
            state["error"] = None
        elif hit == "cancel":
            state["values"] = {"name": "", "email": ""}
            state["focus"] = None
            state["error"] = None
        elif hit == "submit":
            if VARIANT == "noop":
                pass          # 点了完全没反应：界面不变、也没有报错
            elif state["values"]["name"] and state["values"]["email"]:
                state["done"] = True
            else:
                state["error"] = "Name and Email are both required."
        else:
            state["focus"] = None
            state["error"] = "Clicked empty space."
        return True
    if kind == "type":
        text = str(act.get("text", ""))
        log.append({"act": "type", "text": text, "into": state["focus"]})
        if state["focus"] in ("name", "email"):
            state["values"][state["focus"]] += text
            return True
        state["error"] = "Nothing is focused."
        return True
    if kind == "done":
        log.append({"act": "done"})
        return False
    state["error"] = "Unparseable action."
    log.append({"act": "invalid", "raw": str(act)[:80]})
    return True


class RejectRedirects(urllib.request.HTTPRedirectHandler):
    """Do not forward the API key to a redirect target."""
    def redirect_request(self, req, fp, code, msg, headers, newurl):
        return None


def call_model(history, max_tokens=1500):
    body = json.dumps({"model": os.environ["VERIFY_MODEL"], "max_tokens": max_tokens,
                       "system": SYSTEM, "messages": history}).encode()
    req = urllib.request.Request(
        os.environ["ANTHROPIC_BASE_URL"].rstrip("/") + "/v1/messages", data=body,
        headers={"content-type": "application/json",
                 "x-api-key": os.environ["ANTHROPIC_AUTH_TOKEN"],
                 "anthropic-version": "2023-06-01"})
    # Reject redirects: the request carries a credential header.
    opener = urllib.request.build_opener(RejectRedirects())
    with opener.open(req, timeout=180) as resp:
        data = json.loads(resp.read())
    u = data.get("usage", {})
    tok = (u.get("input_tokens", 0) + u.get("cache_read_input_tokens", 0)
           + u.get("cache_creation_input_tokens", 0))
    text = "".join(b.get("text", "") for b in data.get("content", []) if b.get("type") == "text")
    return text, tok, u.get("output_tokens", 0)


SYSTEM = "\n".join([
    "你是一个通过截屏操作界面的 agent。每一步你只会看到一张当前屏幕的截图。",
    "你必须只输出一个 JSON 对象，不要任何解释、不要 markdown 代码块。三种形式之一：",
    '{"action":"click","x":<整数>,"y":<整数>}',
    '{"action":"type","text":"<要输入的文本>"}',
    '{"action":"done"}',
    "坐标以截图左上角为原点。要输入文字必须先点击对应的输入框。",
    "任务完成后输出 {\"action\":\"done\"}。",
])

TASK = "在表单里填入 Name = Zhang San、Email = zhang@example.com，然后点击 Create 按钮创建用户。"


def parse_action(text):
    """用 raw_decode —— 贪婪正则会吃掉尾部文字（见 AGENTS §4.16）。"""
    i = text.find("{")
    if i < 0:
        return None
    try:
        obj, _ = json.JSONDecoder().raw_decode(text[i:])
        return obj
    except Exception:
        return None


def run_trial(max_steps=12):
    global ELEMENTS
    ELEMENTS = dict(BASE_ELEMENTS)
    ELEMENTS.update(VARIANTS[VARIANT])
    if VARIANT != "decoy":
        ELEMENTS.pop("cancel", None)
    state = {"focus": None, "values": {"name": "", "email": ""}, "error": None, "done": False}
    history = [{"role": "user", "content": [
        {"type": "text", "text": TASK + "\n这是当前屏幕："},
        {"type": "image", "source": {"type": "base64", "media_type": "image/png",
         "data": base64.b64encode(render(state)).decode()}},
    ]}]
    log, tokens, steps, step_tokens = [], 0, 0, []
    while steps < max_steps and not state["done"]:
        steps += 1
        text, tin, tout = call_model(history)
        tokens += tin + tout
        step_tokens.append((steps, tin, tout))
        act = parse_action(text)
        if act is None:
            log.append({"act": "PARSE_FAIL", "raw": text[:100]})
            break
        cont = apply_action(state, act, log)
        history.append({"role": "assistant", "content": text})
        if not cont or state["done"]:
            break
        history.append({"role": "user", "content": [
            {"type": "text", "text": "执行完毕。这是新的屏幕："},
```

## 这个循环能优化到什么程度

在不改变任务成功判据的前提下，可以考虑减少图像输入。下表的历史样例估算无法复核，因为逐轮 usage、图像压缩前后请求和模型结果均未留存；所以不把旧估算包装成节省承诺：

| 方案 | 要记录的量 | 当前证据状态 |
|---|---|---|
| 全量历史 | 每次请求中的图像数与 usage | 有三次历史总 token；缺逐轮原始请求，不能复算 |
| 缩放截图 | 缩放前后质量、实际 usage、关键目标成功率 | 本节未测；不同模型/端点的预处理不同 |
| 只留最近图像并附摘要 | 任务状态遗漏率、token、成功/误操作 | 本节未测；必须用任务集验证摘要是否丢失关键状态 |

DeepSeek 当前视觉文档说明图像在推理前会按规则缩放，且声明了当前单图 token 上限；这与本书旧实验的模型别名、日期和用量口径不同。不要根据“缩到 512px”直接假定每张图固定为 186 token。应在目标端点实际请求并读取 usage，同时验证小字、密集控件与边缘目标是否仍可辨认。

缩小图片可能降低输入量，也可能损失小字和小目标的信息。本节报告的“到最近元素中心距离”不是相对期望目标的点击误差，因此不能据此证明缩图后仍能准确操作。要评估缩放，需先定义目标级成功判据，再在相同任务与模型配置下对照。

只保留最近两张截图会让模型失去更早的视觉证据。文字摘要可能降低成本，也可能遗漏状态；只有在任务级评测显示它没有破坏必要信息时，才可采用。

具体到代码（示例：构造数据，未实跑）：

```python
# recent_shots: [(步骤号, 说明, png_b64), ...]，最多留 2 张
# summaries:    只记录经应用状态/观测确认的结果（示例：构造数据，未实跑）
def build_history(recent_shots, summaries, task):
    content = [{"type": "text", "text": task + "\n更早的步骤（文字记录）：\n" + "\n".join(summaries)}]
    for _step, label, b64 in recent_shots:
        content.append({"type": "text", "text": label})
        content.append({"type": "image", "source": {"type": "base64",
                        "media_type": "image/png", "data": b64}})
    return [{"role": "user", "content": content}]

# 每一步结束时：旧的移出窗口、压成一行文字；新的进窗口。
recent_shots.append((step, "第 %d 步后：" % step, new_b64))
while len(recent_shots) > 2:
    old_step, old_label, _ = recent_shots.pop(0)
    # summary_for_step 必须读取已确认的状态记录，不能把模型提议当作执行结果。
    summaries.append(summary_for_step(old_step, verified_state_log))
```

两个细节：**摘要里必须带步骤号和已经验证的状态变化**（例如读回确认「Name 已填入」），否则模型无法把它和当前画面接上；**摘要要跟着观测走、不能把模型提议当作结果**。上面是接口草图，`summary_for_step` 和 `verified_state_log` 需要由具体适配器实现，本段未实跑。

如果应用提供可访问性树、DOM、状态查询或稳定 API，优先评估这些结构化观测；它们仍可能需要截图检查渲染结果，但不必把“每步一张整屏图”当成视觉自动化的理论下限。具体接口取舍按状态覆盖、权限、可靠性与维护成本评估。
## 常见坑

- **复用旧截图来决定依赖新状态的动作。** 动作后先确认哪些状态可能变化，再用足够新鲜的观测决策。
- **只靠「模型说完成」终止。** 实测里模型会在卡住时一直重试，而它不会主动说「我卡住了」——必须有步数上限。
- **把历史总用量当成可复算的逐步曲线。** 历史原始请求缺失时，只能保留其有限观察范围；成本推算要从实际请求历史与 usage 重新测量。
- **把感知哈希相等当作业务状态未变化。** 哈希只作候选信号；关键状态仍要用区域级/语义校验或任务结果判据确认。
- **把最近元素中心距离说成点击精度。** 该指标未与预期目标中心关联，不能证明命中目标或准确率。
- **步数上限设得太大。** 上限是兜底，不是预算；到那时成本和延迟都已经付出去了。真正该做的是尽早发现「在打转」。

在真实执行器前，还要严格验证模型动作的 schema、允许的 action 名称、坐标是否有限且在屏幕范围内、输入长度与目标范围，并在代码层实现授权、确认和隔离。本例的 `parse_action` 只尝试从文本中解出 JSON，`apply_action` 是有限的合成表单状态机；它们不能作为真实浏览器或桌面执行的输入校验与安全边界。
