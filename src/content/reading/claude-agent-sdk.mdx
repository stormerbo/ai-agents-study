**一句话结论**：这是官方对 agent 的抽象层 —— 但**建议在第 11 章手写完 agent 循环之后再读**。

## 为什么强调「之后」

本站第 11 章让你从零手写一个 agent 循环（五个零件：终止条件、工具调度、预算、循环检测、状态持久化）。做完那件事再看官方 SDK，**你才有判断力**：

- 哪些抽象是**必要的**（它替你解决了一个真实存在的复杂度）
- 哪些是**多余的**（它只是换了一种写法）
- 哪些是**有代价的**（它拿走了控制权）

**先看 SDK 的问题在于：你会把它的抽象当成问题的本质。** 而本站第 13 章讲框架选型时的核心主张就是这条 —— **框架不是能力**。

## 这份 SDK 相对手写多给什么

按本站第 13 章那张分工表，框架通常在**状态与恢复**这一层给得多：对话与工具调用的循环调度、会话持久化与恢复、权限与执行策略的接入点（对应第 16 章）、流式输出与事件。

而 **agent 逻辑本身、幂等、预算闸门**仍要你写 —— 这一点本站第 21 章第 4 节用真 LangGraph 实测过：**检查点覆盖不到「副作用已发生、状态未落盘」那个窗口。**

## 和本站的关系

- **第 11 章「agent 循环」** —— 手写一遍，作为判断 SDK 的基准
- **第 13 章「框架选型」** —— 选型判据与「能让路」的检查项
- **第 21 章「工具与上手」** —— 用真框架搭一个最小 agent 的实操

## 建议怎么读

**第 11 章写完循环之后再来。** 第一次只看 Quickstart 跑通一次，然后重点读「权限/执行策略」与「会话持久化」两处 —— 那是框架真正替你省事的地方。
