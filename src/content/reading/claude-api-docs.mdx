## 三个值得先知道的组织特点

**一、「服务端工具」是一个容易漏掉的分支。** 网页搜索、代码执行这些**由平台侧执行**的工具，和你要自己实现的工具是两套机制。做选型时先想清楚「这个工具该我实现还是平台已经提供」。

**二、文档分「参考」与「指南」两种语气。** API reference 是查的（参数名、字段、错误码），Guides 是读的（做法与取舍）。**混着读会很慢。**

**三、同一件事常常有两处写法（SDK 与裸 HTTP）。** 本站第 1 章实测过一个具体后果：`count_tokens` 在不同 SDK 版本里挂在不同对象上，照文档抄的代码可能直接 `AttributeError`。**文档给的是「当前版本」的写法，而你环境里的版本未必是当前版本。**

## 怎么用这一站

1. **第一次** —— 只走 Quickstart 拿到一次成功调用，然后回到本站第 1 章看机制
2. **之后** —— 把它当参考手册：要写什么就查哪一页
3. **每次升级 SDK 前** —— 扫一眼 Release notes，再看相关页面的写法有没有变
