**一句话结论**：做多厂商适配时必须对照的另一份权威参考 —— **它和 Anthropic 的差异不是细节，是结构。**

## 三处结构性差异

| 维度 | Anthropic | OpenAI |
|---|---|---|
| **system** | 顶层字段 | `messages` 里的第一条消息 |
| **工具定义** | `input_schema` | `function.parameters` |
| **流式工具参数** | `input_json_delta` 按 `index` 累积 | `delta.tool_calls` 按 `index` 累积 |

**第一行不只是位置不同。** Anthropic 把 system 放在顶层，反映的是「系统指令是配置、不是历史」这个语义（本站第 3 章讲上下文分块时用了这个区分）。而在 messages 里，system 就是对话历史的第一条。

**这个差别会影响你的适配层设计**：如果你的内部表示是「配置 + 历史」两段，那么映射到 OpenAI 时要合并；反过来则要拆。

## 一个有价值的观察

**第二、三行其实是同一个东西的两种命名。** 两家都要求用 JSON Schema 描述参数、流式时参数分片下发并用 `index` 关联到同一次调用。

**这说明工具调用的形状是趋同的**（本站第 14 章在 MCP 上也观察到了同一件事）。差异集中在**字段名与嵌套位置** —— 而适配层要处理的正好是这些。
