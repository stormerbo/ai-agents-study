**一句话结论**：让模型**交替地「想一步、做一步」**，比只让它想（CoT）或只让它做，都更强。

## 它解决了什么

在 ReAct 之前有两条路，各有各的病：

| 做法 | 问题 |
|---|---|
| **只推理**（chain-of-thought） | 模型可以「想得很对」但无法获取新信息，于是会编 —— 也就是幻觉 |
| **只行动**（让模型直接输出动作） | 没有推理过程，模型不知道为什么要做这个动作，也无法从错误中调整 |

ReAct 的做法是把两者**交错**：`Thought → Action → Observation → Thought → …`。

关键的机制在 **Observation 这一步**：模型发出的动作会真的被执行，结果（成功或失败）作为观察值回到上下文里。**于是模型有了纠错的输入** —— 它能看到「我刚才的假设是错的」，然后改。

这就是本站第 11 章那个 agent 循环的原始出处。

## 论文里两个值得记住的结果

**一、ReAct 减少幻觉的机制不是「更聪明」，而是「有据可查」。** 论文在知识密集任务上的观察是：模型一旦能查证，它就不再需要用编造来填空。这条对工程的意义很直接 —— **如果你在自己的 agent 里看到幻觉，先问「它有没有查证的手段」，而不是先换更大的模型。**

**二、推理与行动的比例需要调。** 论文发现「想太多、做太少」会退化成绩效变差的原版 CoT；「只做不想」也不如交错。**交错的次数是个超参数。**

## 它和后面那些东西的关系

ReAct 是 2022 年的论文，而今天「agent」这个词基本等于它描述的那个循环。所以读它的价值**不在于学一个新方法，而在于看清哪些部分是本质的**：

- **本质**：交替、观察回灌、基于观察纠错
- **不是本质**：具体用哪个提示词格式（`Thought:` / `Action:` 这种标签是为了当时的模型）

**提示词的写法过时了，机制没有。** 这也是本站第 11 章讲「五个零件」而不是讲「ReAct 提示词模板」的原因。
