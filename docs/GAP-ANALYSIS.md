# 与《深入理解 AI Agent》的内容对比（2026-10-10）

> 对比对象：李博杰《深入理解 AI Agent：设计原理与工程实践》，309 页，pandoc 生成。
> 目的：判断本站的**内容丰富度是否需要继续提升**，以及提升什么。

## 一、体量：接近，但组织方式不同

|          | 本站                              | 这本书                         |
| -------- | --------------------------------- | ------------------------------ |
| 中文正文 | **247,012 字**                    | **276,690 字**                 |
| 结构     | 24 章 / **117 节**                | 10 章 / ~84 二级节 / ~190 子节 |
| 平均单元 | 2,111 字/节                       | 3,294 字/二级节                |
| 形态     | 网页，每节配实测数据与 Mermaid 图 | 纸质书，公式与图示为主         |

**结论：正文体量只差 12%，但书把同样的字数压进了更少、更深的单元。**
本站 117 节铺得宽，书 10 章挖得深。

**② 上下文工程 —— 缺的是机制层**

本站 5 节讲的是**策略**：上下文不是越多越好、system prompt 的高度、即时检索、压缩与结构化笔记、子智能体。

书 9 节 / 31 子节多出的是**机制**：

- Chat Template：消息怎么变成 token
- **KV Cache 的原理与约束** —— 为什么前缀一改就全废
- KV Cache 与 Prompt Cache 是**两个层级**的缓存
- 缓存作为架构约束
- **Agent Skills**：领域能力的可组合单元，以及它在上下文里的位置
- **Agent 状态栏**：用元信息增强轨迹管理
- 生产级分层压缩

本站讲「什么时候该压缩」，书讲「为什么缓存的约束长成这样」——后者决定架构。

**③ Coding Agent —— 本站没有专章**

书用 4 节 / 15 子节讲：整体流程、Harness 实践、故障与错误恢复、搜索工具、文件编辑工具、安全，以及「代码作为元能力」的六种形态。

本站相关内容散在第 21 章（工具与上手）与第 22 章（源码研读）里，**没有独立成章**。
对后端工程师来说这可能是最该补的一章 —— coding agent 是最可能天天用到的形态。

**④ 多 Agent 失败模式 —— 书列了 6 种，本站只列了 3 种**

书的清单：共享文件系统的并发冲突、错误的级联放大、同质趋同、互相扯皮、循环失控、**理解债与认知投降**。

本站第 12 章列了 3 种，且长处在**成本实测**（内容 × 装载次数的成本模型、三种拓扑对照）—— 这一点书没有。

## 三、判断

**需要提升，但提升的不是页数 —— 是三个能力缺口。**

本站 247k 字 vs 书 277k 字，差距只有 12%；但**深度分布不均**：
生产工程那一半（9 章 48 节）比书深得多，而设计原理那一半明显浅于书。

### 优先级

|        | 补什么                           | 从 → 到   | 理由                                                         |
| ------ | -------------------------------- | --------- | ------------------------------------------------------------ |
| **P0** | 评估章加深                       | 5 → 12 节 | 「你凭什么说变好了」是本站现有实测方法论的延伸，不是新领域   |
| **P0** | Coding Agent 专章                | 0 → 6 节  | 目标读者最可能天天用的形态，现在只散在两章里                 |
| **P1** | 上下文工程机制层                 | 5 → 9 节  | KV Cache / Chat Template / Prompt Cache 决定架构，不只是优化 |
| **P1** | 多 Agent 失败模式                | 3 → 6 种  | 书那 6 种是可复用的检查清单                                  |
| **P2** | 持续进化                         | 0 → 4 节  | 从轨迹获得学习信号、四种进化方法；与本站「反思/记忆」章衔接  |
| —      | 模型后训练 / 机器人 / Agent 社会 | —         | **不做**                                                     |

### 一个前提

**新增内容必须守住本站的标准**：四块齐全（实测数据 + Mermaid 图 + 可运行代码 + 真实错误案例）、
中文 ≥1500 / 说明文字 ≥3000。

如果只是把书里那 31 个子节的标题变成 31 节「介绍性文字」，那是注水，还不如不补。
**评估章尤其要小心** —— 书讲的方法论本站可以用自己的 20 题评测集复现出数据来；复现不了的，
按 §3.1 标 `basis: unverified` 并说明原因。
