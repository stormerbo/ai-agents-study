# 课程章节与内容导航改版设计

- 日期：2026-10-26
- 状态：设计方向已获用户批准，规格已按评审意见补齐交互状态、正文状态语义与可测的无障碍/响应式验收
- 范围：课程章节总览、章节详情与单节内容页的浏览体验

## 背景

这是一个面向有后端经验读者的中文 AI Agent 学习路径站。课程内容按学习阶段与依赖关系组织。当前章节总览按阶段展示章节卡片；单章页包含目标、后端视角对照、小节列表、资源、实验、自检与作业；单节页主要靠面包屑及文末“上一节 / 下一节”移动，没有能直接定位全站任意章节或小节的目录。课程规模已达数十章 / 百余节，单靠线性翻页与返回章节页造成不必要的导航中断。

本改版让读者同时回答两个问题：这章的学习顺序是什么？读到一半时，怎样直接跳到全课程另一节？不改变课程内容、依赖策略、静态交付或本地学习进度机制。

## 已确认的设计选择

- 内容页采用全站树形课程侧栏，覆盖所有学习阶段、章节和各章小节。
- 目录初次显示时默认展开当前阶段与当前章节，其它部分折叠；用户可按需展开/收起。
- 章节详情页采用学习路线，用连续、有序的小节列表突出学习顺序，而非优先改为宽卡片网格或章节关系地图。
- 章节总览仍按学习阶段组织，完善层级与章入口，不重做信息架构。
- 延续现有语义色、主题变量、进度及课程顺序；浅色、深色与窄屏均须一致可用。

## 页面与交互

### 1. 章节总览（/chapters）

- 保留章节总数进度与浏览器本地保存说明；阶段顺序、阶段标题、tagline、摘要与阶段色保持课程数据驱动。
- 调整视觉层级，让阶段信息成为章节分组的锚点、章卡成为可识别的路线入口；不增添纯装饰指标。
- 章入口至少表现章序、名称、摘要、小节数、预计时长、难度和正文可用性。正文可用性只由 lessons[].hasBody 汇总：全部有正文显示“正文齐全”，部分有正文显示“部分有正文”，全部无正文显示“仅有大纲”；不得用 Chapter.status 代替。ContentStatus 是编写流程状态，不在此处展示；正文存在不表示已经发布、审校或核实。若已有自检数量指标仍有帮助，可继续保留。
- 适配章节标题、摘要较长及多小节章节，不裁剪必要信息；为可键盘操作的整卡链接保留清晰焦点态。

### 2. 章节详情页（/chapters/[chapterId]）

将页面主叙事从“若干独立区块的目录页”调整为“认识目标、按路线学习、随时验证”的连续学习顺序：

1. 面包屑显示章节索引及所属阶段。
2. 章节开场显示序号、标题、摘要，以及难度、估时、小节数量与按 lessons[].hasBody 聚合的正文可用性：“正文齐全 / 部分有正文 / 仅有大纲”（分别对应全部 true / 混合 / 全部 false）；不得用 Chapter.status 覆盖此状态，也不在此处展示 ContentStatus 工作流状态。清楚但不过分占据首屏。
3. 展示本章总体学习进度和“学完能做到什么”。
4. 将小节列表设计为单列纵向路线。每节包含清楚的序号、标题、已有摘要、估时、基于 Lesson.hasBody 的“有正文 / 仅大纲”标记与完成状态；Lesson.status（planned / outlined / drafting / published）是另一独立编写流程状态，不用于推导正文可用性，也不在该入口重复显示。整项是直达内容页的可访问链接。段落顺序沿课程原有 lesson 顺序，不使用额外排序字段。
5. 保留本项目主线“后端视角对照”（可迁移经验、会失效的直觉），让它仍在主要学习路径中容易找到。
6. 保留先修建议、实验、逐节自检、阶段作业、延伸资源和上一章/下一章；可将低频辅助信息安排在路线之后，但不得删除已有内容、功能或信息依据。

### 3. 单节内容页（/chapters/[chapterId]/[lessonSlug]）

- 将全站课程目录作为内容页固定的跳转入口：包含全部阶段、阶段内全部章节，以及各章全部小节。选中当前小节可一眼分辨，并让当前章/阶段有明确上下文。
- 使用既有课程查询数据与顺序（stages、chapters、lessons），不添加重复排序/导航数据。
- 初次打开一个 lesson 路由时展开当前阶段和当前章；其余阶段/章默认折叠。阶段 summary 是纯展开控制，不导航（没有阶段详情路由）。每章名称是独立链接，指向 /chapters/{chapterId}；章内另有独立 summary 展开/收起该章小节；小节名称链接到 /chapters/{chapterId}/{lessonSlug}。summary 与链接必须是相邻而独立的交互控件，不能把 Link/button 嵌进 summary。
- 将导航树放入具名 landmark：<nav aria-label="课程目录">，阶段/章/节用嵌套 ul/li 分组；当前节链接用 aria-current="page"。目录链接文本须自解释。
- disclosure 优先用原生 <details>/<summary>；每层键盘可操作且展开状态可被辅助技术感知。因当前路径默认值来自 URL，使用 lesson.id 作为导航树根节点的 React key，使 Next 客户端导航到另一个 lesson 或浏览器后退/前进时目录按新 URL 重置：仅新当前阶段与章节自动打开，非当前分组回到折叠，之前手动展开/收起的其它分组不跨 lesson 保留。当前节所在路径永远打开。无需将目录变为 Client Component；若实施发现 key remount 在目标 Next 版本不满足，需要以浏览器测试验证等价行为，不得悄悄丢掉此契约。
- 目录点击是到章节页或内容页的真实站内 URL 导航；跨章内容连续性仍由既有“上一节 / 下一节”逻辑负责。
- 桌面宽屏（视口宽度 ≥1024 CSS px 且高度 ≥720 CSS px）将课程导航放在正文右侧，与当前节延伸资源共处同一个层级清楚的辅助栏，避免竞争性的第二整栏；辅助栏 sticky top-20，整体 max-block-size: calc(100dvh - 6rem)，并以单一内部纵向滚动容器承载课程目录与资源。焦点移动到滚动容器内的目录项时，该项须滚动可见。短视口禁用 sticky 与视口限高，使辅助栏按文档自然滚动；任何情况下不得遮住站点顶栏、文章内容或焦点。
- 有课程导航时，正文使用约 48–52rem 阅读宽度并受外层总宽度约束；资源与课程目录共用辅助列，不形成两侧导航夹击正文。
- 移动/窄屏（宽度 <1024 CSS px）将课程目录折叠区放在正文标题及学习元信息之后、正文之前，课程目录默认收起。不得使用固定/覆盖正文的抽屉或悬浮目录；展开内容走正常文档流，延伸阅读继续可访问。
- 保留站点全局导航、章节面包屑、内容标题、正文或未写正文状态、自检、完成按钮、资源、上一节/下一节及其本地进度说明；站点主导航、课程目录、面包屑、翻页导航使用互不重复的 accessible name。

## 结构与数据流

- 优先新增一个小型可复用课程目录视图（命名由实现计划决定），作为 src/content/curriculum 导出的 stages、chapters 和 lesson 的纯展示消费端；课程页路径仍从现有 id/slug 产生。
- 目录接收当前 lesson/chapter 的 id 用于当前项、默认展开和链接语义；所有构建期可得信息从 server components 传入，不为静态内容目录引入数据获取、数据库或新的状态服务。
- 若原生 disclosure 满足交互，维持 Server Component，不将 144 个入口不必要地推入客户端 JavaScript。使用 <nav aria-label="课程目录"> 内的嵌套 ul/li；阶段 summary 只展开分组，章标题链接与展开章内小节的 summary 为相邻独立控件；章节和小节链接文本自解释，当前小节以 aria-current="page" 表示。summary 可由 Enter/Space 激活并正确播报展开状态。站点主导航、面包屑、节间翻页有不同且具体的 accessible name。
- 当前阶段、章节的展开默认值由当前路由派生，不在课程数据重复保存。导航树使用当前 lesson.id 作为 React key：在不同 lesson 路由间进行 Next Link 导航、浏览器后退和前进都以新 URL 重置树开合态，仅展开新的当前路径；同一路由内用户手动开合保持不变。

## 不在本次范围内

- 改写课程内容、章序、依赖、阶段划分和“软建议而非硬门槛”策略。
- 将完成状态从 localStorage 迁移、添加登录、服务器进度、多设备同步或课程服务端数据。
- 为侧栏增加全文搜索、筛选器、可拖拽、推荐算法、收藏、课程地图或“解锁”机制。
- 改造网站顶栏、知识地图、实验、资源、搜索/索引或全文排版系统（除维持布局所需的局部适配外）。
- 清理或回滚工作区里其他已经存在的内容/证据改动；它们不是此设计的范围。

## 验收标准

1. 章节总览仍完整列出每个阶段、章节，并可进入各章节；状态、进度与数据顺序正确。
2. 章节详情以单列的顺序路线展示本章全部小节，入口不会遗漏，也不会改变现有完成状态的语义。
3. 任意内容页的侧栏能遍历全站每个阶段、章和节；所有目标指向正确 ID / slug，当前节正确标记。
4. 首次访问 lesson 路由仅当前阶段、当前章展开；同页内 disclosure 可手动开合。经 Next Link 导航至本章另一节、跨章/跨阶段导航及浏览器后退/前进时，以新 URL 重置所有非当前分组为折叠，只展开新当前路径；aria-current 指向目标节。首节、末节、无正文与跨章边界通过检查。
5. 章节与 lesson 正文可用状态只取自 hasBody：lesson true/false 分别显示“有正文 / 仅大纲”；chapter 全 true / 混合 / 全 false 分别显示“正文齐全 / 部分有正文 / 仅有大纲”。ContentStatus 是独立编写工作流元数据，不与 hasBody 相互覆盖或推断。增加契约测试覆盖 planned/outlined/drafting/published 与 hasBody true/false 的组合及章节三种聚合，至少包括 hasBody=true 且 status=drafting 的不一致数据。
6. 在 1440×900 桌面检查辅助栏 sticky 且 max-block-size 为 calc(100dvh - 6rem)，课程目录与资源在单一辅助栏内滚动；在 1280×640 短桌面检查无 sticky 与视口限高且目录随文档自然滚动。外栏不得遮挡 3.5rem 高站点栏、正文或键盘焦点。含资源/无资源页面在 1440px 宽度下正文以约 48–52rem 为目标（受总体宽度约束），不得被两侧辅助栏夹窄。
7. 在 320×640 与 375×812 CSS px 手机视口，目录位于正文标题/元信息之后、正文之前且初始折叠；在 1280×800 浏览器 200% zoom（有效 CSS viewport 约 640×400）重复验证窄屏行为。每个视口 `document.documentElement.scrollWidth === document.documentElement.clientWidth`；不得水平溢出、遮挡正文或只能 hover 才可用。触控点击与键盘 Tab、Shift+Tab、Enter、Space 均可访问 summaries 和 links；交互目标至少 44×44 CSS px、焦点清楚可见，内部滚动不裁剪焦点项。用 VoiceOver + Safari 或 NVDA + Chrome 验证课程目录 landmark 名称、嵌套列表层级、折叠状态播报、当前节“当前页”语义与焦点/阅读顺序。
8. 浅/深主题普通文本对比度至少 4.5:1，大字号文本与焦点指示器/交互边界至少 3:1，以自动对比检查结合浏览器采样或人工核验。未写正文、完成进度、自检和上一节/下一节仍保留。
9. 增加有针对性的课程目录数据/渲染合同测试：验证阶段、章、节树覆盖与 URL、当前项、嵌套层级/ARIA 语义和默认展开派生；再运行相关测试、`pnpm typecheck`、`pnpm lint` 和构建。每条命令单独记录结果。
10. 视觉检查至少覆盖章节总览、含资源、无资源、长目录和首尾/跨章正文，在上述宽/短桌面、窄屏与 200% zoom 下分别检查浅/深主题；遵循 AGENTS.md 的主题切换流程。

## 风险与注意点

- 144 个节链接的目录若全部展开会喧宾夺主；因此只自动展开当前路径，且保持各层闭合控件明确。
- 当前内容页的延伸资源与新课程目录若抢占相同的窄右栏，文章会变窄；将它们放到同一辅助栏的不同分区，并在窄屏移动至正文附近。
- 不要把 details 的 defaultOpen 误当成永久受控状态：在同一 lesson 页面内手动开合后保持该选择；经站内链接、浏览器后退/前进到不同 lesson.id 时由根节点 key remount 重置非当前组为折叠并打开新当前路径。须在真实浏览器测试这些路由转移。
- Tailwind v4 的动态色类必须已有 @theme 令牌或使用行内 style（目前 stage.colorToken 已用于动态阶段变量），避免静默无样式。
- 工作树现存其他变更广泛且不属于本功能；实现、格式化和提交均须限定改动范围，不回滚用户内容。
