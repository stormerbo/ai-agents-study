# 课程章节与内容导航改版设计

- 日期：2026-10-26
- 状态：设计已获用户批准，待规格评审与用户检查文档
- 范围：课程章节总览、章节详情与单节内容页的浏览体验

## 背景

这是一个面向有后端经验读者的中文 AI Agent 学习路径站。课程内容按学习阶段与依赖关系组织。当前章节总览按阶段展示章节卡片；单章页包含目标、后端视角对照、小节列表、资源、实验、自检与作业；单节页主要靠面包屑及文末“上一节 / 下一节”移动，没有能直接定位全站任意章节或小节的目录。课程规模已达数十章 / 百余节，单靠线性翻页与返回章节页造成不必要的导航中断。

本改版让读者同时回答两个问题：这章的学习顺序是什么？读到一半时，怎样直接跳到全课程另一节？不改变课程内容、依赖策略、静态交付或本地学习进度机制。

## 已确认的设计选择

- 内容页采用全站树形课程侧栏，覆盖所有学习阶段、章节和各章小节。
- 目录初次显示时默认展开当前阶段与当前章节，其它部分折叠；用户可按需展开/收起。
- 章节详情页采用学习路线，用连续、有序的小节列表突出学习顺序，而非优先改为宽卡片网格或章节关系地图。
- 章节总览仍按学习阶段组织，完善层级与章入口，不重做信息架构。
- 延续现有语义色、主题变量、进度及课程顺序；浅色、深色与窄屏均须一致可用。

## 页面与交互

### 1. 章节总览（/chapters）

- 保留章节总数进度与浏览器本地保存说明；阶段顺序、阶段标题、tagline、摘要与阶段色保持课程数据驱动。
- 调整视觉层级，让阶段信息成为章节分组的锚点、章卡成为可识别的路线入口；不增添纯装饰指标。
- 章入口至少表现章序、名称、摘要、小节数、预计时长、难度和正文准备状态；若已有自检数量指标仍有帮助，可继续保留。
- 适配章节标题、摘要较长及多小节章节，不裁剪必要信息；为可键盘操作的整卡链接保留清晰焦点态。

### 2. 章节详情页（/chapters/[chapterId]）

将页面主叙事从“若干独立区块的目录页”调整为“认识目标、按路线学习、随时验证”的连续学习顺序：

1. 面包屑显示章节索引及所属阶段。
2. 章节开场显示序号、标题、摘要，以及难度、估时、小节数量与正文状态；清楚但不过分占据首屏。
3. 展示本章总体学习进度和“学完能做到什么”。
4. 将小节列表设计为单列纵向路线。每节包含清楚的序号、标题、已有摘要、估时、正文/大纲状态与完成状态；整项是直达内容页的可访问链接。段落顺序沿课程原有 lesson 顺序，不使用额外排序字段。
5. 保留本项目主线“后端视角对照”（可迁移经验、会失效的直觉），让它仍在主要学习路径中容易找到。
6. 保留先修建议、实验、逐节自检、阶段作业、延伸资源和上一章/下一章；可将低频辅助信息安排在路线之后，但不得删除已有内容、功能或信息依据。

### 3. 单节内容页（/chapters/[chapterId]/[lessonSlug]）

- 将全站课程目录作为内容页固定的跳转入口：包含全部阶段、阶段内全部章节，以及各章全部小节。选中当前小节可一眼分辨，并让当前章/阶段有明确上下文。
- 使用既有课程查询数据与顺序（stages、chapters、lessons），不添加重复排序/导航数据。
- 初始状态展开当前阶段和当前章；其它阶段/章默认折叠。每层使用语义正确、键盘可操作且能暴露展开状态的折叠交互（优先原生 details/summary，若客户端实现确有必要须说明理由并支持无脚本内容可发现）。所有层均可手动展开。
- 目录点击是到章节页或内容页的真实站内 URL 导航；跨章内容连续性仍由既有“上一节 / 下一节”逻辑负责。
- 桌面宽屏将课程导航放在正文右侧，与当前节延伸资源共处一个层级清楚的辅助栏，避免竞争性的第二整栏；辅助导航尽量 sticky，但不能遮住站点顶栏、文章内容或焦点。
- 有课程导航时，正文保持舒适的阅读宽度（目标约 48–52rem，沿用既有文章排版）。没有资源也不缩到难读的窄列；内容很长时文章不被双侧栏挤压。
- 移动端将课程导航变成正文附近可触达的“课程目录”折叠区；侧栏不得固定挡住正文，支持窄屏长标题与触控操作。延伸阅读继续可访问。
- 保留站点全局导航、章节面包屑、内容标题、正文或未写正文状态、自检、完成按钮、资源、上一节/下一节及其本地进度说明。

## 结构与数据流

- 优先新增一个小型可复用课程目录视图（命名由实现计划决定），作为 src/content/curriculum 导出的 stages、chapters 和 lesson 的纯展示消费端；课程页路径仍从现有 id/slug 产生。
- 目录接收当前 lesson/chapter 的 id 用于当前项、默认展开和链接语义；所有构建期可得信息从 server components 传入，不为静态内容目录引入数据获取、数据库或新的状态服务。
- 若原生 disclosure 满足交互，维持 Server Component，不将 144 个入口不必要地推入客户端 JavaScript。HTML 遵循分组/导航 landmark，summary 可被键盘激活，链接文本对屏幕阅读器自解释，当前页以 aria-current="page" 或等效语义表示。
- 当前阶段、章节的展开默认值由当前路由派生，不在课程数据重复保存。

## 不在本次范围内

- 改写课程内容、章序、依赖、阶段划分和“软建议而非硬门槛”策略。
- 将完成状态从 localStorage 迁移、添加登录、服务器进度、多设备同步或课程服务端数据。
- 为侧栏增加全文搜索、筛选器、可拖拽、推荐算法、收藏、课程地图或“解锁”机制。
- 改造网站顶栏、知识地图、实验、资源、搜索/索引或全文排版系统（除维持布局所需的局部适配外）。
- 清理或回滚工作区里其他已经存在的内容/证据改动；它们不是此设计的范围。

## 验收标准

1. 章节总览仍完整列出每个阶段、章节，并可进入各章节；状态、进度与数据顺序正确。
2. 章节详情以单列的顺序路线展示本章全部小节，入口不会遗漏，也不会改变现有完成状态的语义。
3. 任意内容页的侧栏能遍历全站每个阶段、章和节；所有目标指向正确 ID / slug，当前节正确标记。
4. 初始展开策略严格为当前阶段、当前章；其它阶段/章折叠，手动开合可用。首节、末节、无正文和跨章边界路径不出错。
5. 有/无资源时正文宽度、资源位置和目录布局均合理，不发生冲突；桌面侧栏不盖住全局顶栏和正文。
6. 窄屏不出现横向溢出、被固定目录遮挡或只能 hover 才可达的内容；目录可通过键盘与触控访问，展开状态可感知，焦点可见。
7. 浅/深主题的文本、边框、阶段状态和焦点对比可读；未写正文、完成进度、自检和既有上一/下一导航仍保留。
8. 增加有针对性的课程目录数据 / 渲染合同测试：验证阶段、章、节树覆盖与 URL、当前项和默认展开派生；再运行相关测试、pnpm typecheck、pnpm lint 和构建。运行每个命令时记录其自身结果，不用一个命令的通过推断其它命令通过。
9. 视觉检查至少覆盖章节总览、包含资源的正文、无资源正文与首尾/长目录一种代表状态，在宽桌面和窄屏以及浅/深主题验证；遵循 AGENTS.md 的主题切换与页面验证流程。

## 风险与注意点

- 144 个节链接的目录若全部展开会喧宾夺主；因此只自动展开当前路径，且保持各层闭合控件明确。
- 当前内容页的延伸资源与新课程目录若抢占相同的窄右栏，文章会变窄；将它们放到同一辅助栏的不同分区，并在窄屏移动至正文附近。
- 不要把 details 的默认开合误当成永久受控状态；用户在当前页面的展开选择要保持自然。每次导航至新节时默认路径由新路由提供。
- Tailwind v4 的动态色类必须已有 @theme 令牌或使用行内 style（目前 stage.colorToken 已用于动态阶段变量），避免静默无样式。
- 工作树现存其他变更广泛且不属于本功能；实现、格式化和提交均须限定改动范围，不回滚用户内容。
